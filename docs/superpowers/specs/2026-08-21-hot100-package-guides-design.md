# Hot 100 按 Package 分类逐题详解设计

## 目标

在 `src/main/java/frequence` 现有 package 结构内，为官方 LeetCode Hot 100 主线题及当前项目中的同专题扩展题建立系统化题解文档。文档面向面试复习，要求能够脱离 Java 源码直接完成算法回忆，同时通过文件链接回到用户现有实现、标准实现、错误版本和对数器。

## 范围

- 官方 Hot 100 题目标记为 `【Hot 100】`。
- `frequence` 下其他唯一 LeetCode 题目标记为 `【扩展】`。
- 当前基线约为 119 个唯一题号；实施时重新扫描，生成最终覆盖表。
- 同一题号的多个实现只讲一次，例如 Q46、Q146、Q460；其他文件放入“版本对比”或“错误分析”。
- `Comparator`、`DifferentialTest`、模板辅助类、节点定义和非题目练习不作为独立题目。
- 错误版本不单独计数，但其问题应进入对应题目的“易错点”部分。

## 单题统一结构

每道题按照以下顺序编写：

1. `题号 + 题名 + 【Hot 100/扩展】`
2. 核心思想：使用一句可以直接背诵的结论概括模型。
3. 算法流程：按可执行步骤描述。
4. 正确性依据或循环不变量：解释为什么可以排除、转移或贪心。
5. 标准 Java 代码：给出适合面试手写的完整核心实现。
6. 关键代码解释：只解释真正需要推导的部分。
7. 易错点：优先吸收项目 Java 文件中现有的“错误原因与正确改法”注释。
8. 可选解法及取舍：说明暴力、标准解、最优解之间的选择；没有有价值替代方案时省略。
9. 时间复杂度和空间复杂度。
10. 面试记忆模板：压缩成数行决策规则。
11. 项目链接：主实现、参考实现、错误版、对数器和已有专题 Markdown。

## 代码选择原则

- 首选用户已经 AC 的 `myXxx` 实现；保留其核心思路，但统一变量命名和排版。
- 用户实现正确但不是推荐面试版本时，同时给出“用户版本评价”和“推荐版本”。
- 标准代码使用 Java 8 兼容语法，与项目 `pom.xml` 保持一致。
- 不为追求最短代码牺牲状态定义、边界安全和可解释性。
- 比较器避免减法溢出，使用 `Integer.compare`。
- 涉及前缀和或可能溢出的累加时使用 `long`。
- 代码只展示题目的核心类型；LeetCode预定义的 `ListNode`、`TreeNode` 可通过简短注释说明。

## 分类与交叉引用

- 每道题只在其 Java 文件所在 package 的文档中完整讲解。
- 一个题目同时属于多个模型时，其他专题只建立链接，不复制整段题解。
- 总索引提供“按 LeetCode 分类”和“按算法模型”两种入口。
- 主线题排在扩展题之前；专题内部按“基础模型 -> 典型变形 -> 高难扩展”排序，不机械按题号排序。

## 质量控制

实施完成后执行以下检查：

1. 扫描全部 `Q*.java`，按题号去重并生成预期覆盖集合。
2. 扫描全部专题 Markdown 中的题号，检查缺失和重复完整讲解。
3. 检查每题是否包含标签、核心思想、标准代码、复杂度、易错点、记忆模板和项目链接。
4. 校验所有相对 Markdown 链接指向存在的文件。
5. 将文档中的 Java 代码块抽取到临时目录，对可独立编译的代码执行 Java 8 语法检查；依赖 LeetCode节点类型的代码单独做结构检查。
6. 运行项目现有的 `mvn test` 和相关对数器，确保文档工作未破坏代码。

## 非目标

- 不修改用户现有算法实现。
- 不移动或重命名现有 package 和 Java 文件。
- 不重复粘贴题目完整原文和大段示例。
- 不追求收录所有 LeetCode 相似题，只覆盖当前项目已有扩展题。
- 不把运行时间百分位作为算法优劣依据。

## 验收标准

- 官方 Hot 100 主线题全部出现且标记正确。
- 当前 `frequence` 下每个唯一 LeetCode题号都被主线或扩展题解覆盖。
- 重复实现不会被误计为多道题。
- 每道题的讲解深度不低于“三数之和”示例。
- 所有文档位于对应 package，根索引能够导航到题目和 Java 文件。
- 链接检查、覆盖检查和 Maven验证全部通过。
