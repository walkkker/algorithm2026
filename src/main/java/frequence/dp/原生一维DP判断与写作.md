# 原生一维 DP 判断与写作

> **优先级：第一层，面试必会。**
>
> 本文先解决两个问题：一道题能否直接定义原生一维状态，以及确定可以后如何稳定写出代码。
> 背包二维推导、空间压缩和各题完整复盘参见[《一维DP核心总结》](./一维DP核心总结.md)。

## 一、必须先记住的结论

```text
代码使用一个dp[]，不代表逻辑状态原本只有一维。

原生一维DP：一个变化参数足以唯一描述子问题。
压缩一维DP：逻辑状态原本需要多个参数，只是复用了存储空间。
```

例如：

```text
Q279：dp[target]，知道target就能枚举最后一个平方数，属于原生一维。
Q300：dp[i]，强制以nums[i]结尾，属于重新设计后的一维状态。
Q416：逻辑状态是物品范围+容量，boolean[]只是二维0-1背包压缩。
Q518：逻辑状态是物品范围+目标值，int[]只是二维完全背包压缩。
```

判断的核心不是最终写了几维数组，而是：

> 删除某个参数后，相同状态是否仍然拥有完全相同的可选集合、约束和后续答案？

## 二、最高优先级：判断能否原生一维

### 1. 从递归参数判断

先尝试给子问题写一句完整定义：

```text
process(i)
process(target)
process(end)
```

如果一个参数足以唯一确定子问题，通常可以设计原生一维DP：

```text
process(i)      -> dp[i]
process(target) -> dp[target]
```

如果必须同时知道两个独立变化参数：

```text
process(index, rest)
process(left, right)
process(i, previousIndex)
```

逻辑状态通常是二维。除非能够像Q300一样重新定义状态，否则不要直接删除其中一个参数。

### 2. 四问判断法

面对新题，依次回答：

```text
1. 一个下标或目标值能否唯一描述当前子问题？
2. 知道该状态后，合法前驱和可选集合是否已经确定？
3. 枚举最后一步、前一个位置或分割点，能否覆盖全部答案？
4. 是否还必须知道物品范围、交易状态、区间另一端或历史选择？
```

前三问为“是”、第四问为“否”，优先尝试原生一维DP。

### 3. 不能只看循环层数

两层循环不等于二维DP：

```java
for (int i = 0; i < n; i++) {
    for (int j = 0; j < i; j++) {
        dp[i] = Math.max(dp[i], dp[j] + 1);
    }
}
```

Q300中只有 `dp[i]` 是子问题；`j`只是枚举转移来源，不是状态坐标。

反过来，一个 `dp[]` 也不一定是原生一维：

```java
for (int num : nums) {
    for (int rest = target; rest >= num; rest--) {
        dp[rest] |= dp[rest - num];
    }
}
```

Q416的物品维度仍由外层循环阶段隐式承载。

## 三、最高优先级：状态定义的标准写法

不要写：

```text
dp[i]表示最大值。
```

必须同时写出四项：

```text
1. 范围：前缀、后缀、必须结尾，还是目标值；
2. 约束：当前位置是否必须参与；
3. 目标：最大值、最小值、方案数还是可行性；
4. 下标：是真实位置，还是前缀长度/目标数值。
```

标准句式：

```text
dp[i]表示在______范围内，满足______约束时，______问题的答案。
```

示例：

```text
Q198：dp[i]表示房屋[0,i]范围内能够获得的最大金额，房屋i不要求必须偷。
Q300：dp[i]表示必须以nums[i]结尾的最长严格递增子序列长度。
Q139：dp[end]表示前缀s[0,end)能否被字典单词完整拆分。
Q279：dp[target]表示组成target所需的最少完全平方数数量。
```

状态定义必须在写循环之前完成。初始化、转移、遍历方向和答案位置都应从这句话直接推出。

## 四、第一层常见原生一维模型

### 1. 固定前驱型

当前位置只依赖固定数量的相邻状态：

```text
Q70：dp[i] = dp[i-1] + dp[i-2]
Q198：dp[i] = max(dp[i-1], dp[i-2] + nums[i])
```

写作重点：区分 `i` 是前缀长度还是真实下标，并为前两个状态建立业务化base case。

### 2. 必须以位置 `i` 结尾

状态强制当前位置参与：

```text
dp[i] = 必须以位置i结尾的局部答案
```

前驱可能是：

```text
只连接i-1：Q152最大乘积子数组；
枚举所有j<i：Q300最长递增子序列；
根据已有长度跳跃：Q32最长有效括号。
```

因为最优方案可能在任何位置结束，最终答案通常是：

```java
ans = Math.max(ans, dp[i]);
```

而不是机械返回 `dp[n-1]`。

### 3. 前缀分割型

状态坐标通常是前缀长度：

```text
dp[end] = 前缀[0,end)的答案
```

固定结尾 `end`，枚举最后一段起点：

```java
for (int end = 1; end <= n; end++) {
    for (int start = 0; start < end; start++) {
        // 由dp[start]和区间[start,end)转移
    }
}
```

Q139中 `dp[0]=true` 表示空前缀已经合法拆分，是第一个单词能够开始的基础。

### 4. 目标值/最后一步型

状态下标是要凑出的数值：

```text
dp[target] = 凑出target时的最优值、可行性或排列数量
```

枚举最后选择的元素：

```java
for (int target = 1; target <= bag; target++) {
    for (int weight : weights) {
        if (weight <= target) {
            dp[target] = combine(dp[target], dp[target - weight]);
        }
    }
}
```

典型题：

```text
Q279、Q322：combine是min，求最少数量；
Q377：combine是sum，统计有序排列；
可达性问题：combine是逻辑或。
```

### 5. 位置推进 + 固定状态

有些问题除了位置，还需要少量固定业务状态：

```text
cash[i]、hold[i]
maxEnd[i]、minEnd[i]
```

严格说它包含有限状态维度，但状态数量不随输入增长，通常拆成多个一维数组或常数变量。不要为了形式上
只有一个数组，把语义不同的状态强行合并。

## 五、目标值一维DP的关键边界

### 1. Q279和Q322为什么可以直接一维

二者都可以定义：

```text
dp[target] = 凑出target所需的最少元素数量
```

知道 `target` 后，可选平方数或硬币集合已经确定；枚举最后一个元素可以覆盖全部答案；不同选择顺序
即使重复到达同一结果，也不会改变 `min` 的结果。因此不必为了套背包模板先扩展成二维。

### 2. Q377为什么目标外层

Q377统计有序排列。目标外层枚举最后元素，可以分别生成 `1+2` 和 `2+1`：

```java
dp[0] = 1;
for (int target = 1; target <= bag; target++) {
    for (int num : nums) {
        if (num <= target) {
            dp[target] += dp[target - num];
        }
    }
}
```

### 3. Q518为什么不是原生目标值计数

Q518统计无序组合，`1+2` 和 `2+1`只能算一次。只定义 `dp[target]`并枚举最后元素会重复计数，
必须在逻辑上增加物品范围：

```text
dp[i][target] = 只使用前i种硬币组成target的组合数量
```

压缩后虽然只剩 `dp[target]`，物品维仍由外层循环承载：

```java
dp[0] = 1;
for (int coin : coins) {
    for (int target = coin; target <= amount; target++) {
        dp[target] += dp[target - coin];
    }
}
```

这是一维存储，不是原生一维逻辑状态。

## 六、标准书写流程

面试中按照以下顺序写，不要先写循环：

### Step 1：写状态定义

```text
dp[i/target]准确表示什么？范围、约束、目标和下标语义是什么？
```

### Step 2：写base case

```text
空前缀、目标0、第一位置分别表示什么？
```

常见初始化：

| 目标语义 | `dp[0]` | 其他状态 |
|---|---:|---:|
| 最少数量 | `0` | `INF` |
| 可行性 | `true` | `false` |
| 方案数 | `1` | `0` |
| 最大价值且允许不装满 | `0` | `0` |

### Step 3：枚举最后一步或前驱

```text
当前答案的最后一步是什么？
去掉最后一步后进入哪个严格更小的状态？
所有分类是否完整且互斥？
```

### Step 4：确定遍历方向

依赖更小下标则正序，依赖更大下标则倒序。若是背包压缩，额外判断本轮是否允许重复读取当前物品：

```text
0-1背包容量倒序；
完全背包容量正序。
```

### Step 5：确定答案位置

```text
范围整体最优：通常在边界状态；
必须以i结尾：通常遍历所有dp[i]取最优；
目标值DP：通常返回dp[target]。
```

### Step 6：写复杂度

循环层数不等于状态维度，但决定时间复杂度。分别统计状态数量和每个状态枚举的前驱数量：

```text
时间 = 状态数量 × 单状态转移代价
空间 = 实际保存的状态数量
```

## 七、面试可直接使用的模板

### 1. 最少数量目标值DP

```java
int[] dp = new int[bag + 1];
Arrays.fill(dp, bag + 1);
dp[0] = 0;

for (int target = 1; target <= bag; target++) {
    for (int weight : weights) {
        if (weight <= target) {
            dp[target] = Math.min(
                    dp[target],
                    dp[target - weight] + 1
            );
        }
    }
}
```

记忆依据不是代码外形，而是：

```text
枚举最后选择的weight，前驱目标是target-weight。
```

### 2. 必须以位置结尾

```java
for (int i = 0; i < n; i++) {
    dp[i] = baseValue;
    for (int j = 0; j < i; j++) {
        if (canConnect(j, i)) {
            dp[i] = combine(dp[i], dp[j]);
        }
    }
    ans = combine(ans, dp[i]);
}
```

### 3. 前缀分割

```java
dp[0] = baseValue;
for (int end = 1; end <= n; end++) {
    for (int start = 0; start < end; start++) {
        if (dp[start]可用 && 区间[start,end)合法) {
            更新dp[end];
        }
    }
}
```

## 八、不能原生一维的危险信号

出现以下情况时，不要急着删除状态参数：

```text
1. 每个物品只能使用一次或有数量限制；
2. 必须统计无序组合，不能重复计算不同选择顺序；
3. 未来可选集合取决于已经处理到第几种物品；
4. 需要同时知道区间左右边界；
5. 需要交易次数、冷冻期、持有状态等业务状态；
6. 删除参数后，同一个dp下标对应了不同后续选择。
```

这时优先保留完整二维或多状态定义。空间压缩属于后续实现优化，不应该反过来决定逻辑状态。

## 九、最终检查表

写完代码后逐项检查：

```text
1. dp下标是位置、长度还是目标值？
2. 状态描述的是范围整体，还是必须以当前位置结尾？
3. 一个下标真的能唯一确定子问题吗？
4. base case是否有明确业务含义？
5. 最后一步分类是否完整？
6. 循环方向是否满足依赖先计算？
7. min/max前驱不可达时是否会溢出或产生假答案？
8. 最终答案在dp边界，还是需要遍历全部结尾状态？
9. 当前一维数组是原生状态，还是二维状态的存储压缩？
10. 如果是计数，当前统计的是排列还是组合？
```

最重要的能力不是记住一维代码，而是每次都能完整说出：

```text
dp状态表示什么；
为什么一个参数足够；
每个状态从哪里转移；
为什么不会漏解或重复计数。
```
