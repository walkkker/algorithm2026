# 多维 DP 核心总结

## 先看结论

这五道题虽然都可以使用二维数组，但二维下标的业务含义并不相同：

| 模型 | 题目 | 状态定义 | 最终答案 |
| --- | --- | --- | --- |
| 棋盘位置模型 | Q62 不同路径 | `dp[row][column]`：到达真实坐标的答案 | `dp[m - 1][n - 1]` |
| 棋盘位置模型 | Q64 最小路径和 | `dp[row][column]`：到达真实坐标的最小代价 | `dp[m - 1][n - 1]` |
| 双序列前缀模型 | Q1143 最长公共子序列 | `dp[i][j]`：两个长度分别为 i、j 的前缀答案 | `dp[m][n]` |
| 双序列前缀模型 | Q72 编辑距离 | `dp[i][j]`：两个长度分别为 i、j 的前缀答案 | `dp[m][n]` |
| 双序列前缀+纯计数 | Q115 不同的子序列 | `dp[i][j]`：s前i个字符组成t前j个字符的方案数 | `dp[m][n]` |
| 单序列区间模型 | Q5 最长回文子串 | `dp[left][right]`：闭区间是否为回文串 | 扫描所有区间维护最长答案 |

真正需要记忆的不是“创建二维数组”，而是以下四件事：

1. 每一个维度具体表示什么。
2. `dp` 格子表示坐标、长度，还是闭区间。
3. 当前格子依赖哪些规模更小的格子。
4. 哪种遍历顺序能够保证依赖已经计算完成。

## 一、棋盘位置模型：Q62、Q64

`row`和`column`就是实际下标，合法范围分别为`[0, m - 1]`和`[0, n - 1]`：

```java
int[][] dp = new int[m][n];
return dp[m - 1][n - 1];
```

不能机械地认为“DP都要多开一行一列”。额外的第0行、第0列通常用于表示空前缀或无物品状态；
真实棋盘本身已经包含坐标0，不需要再人为平移。

Q62求路径数量：

```text
dp[row][column] = dp[row - 1][column] + dp[row][column - 1]
```

Q64求最小代价：

```text
dp[row][column]
    = min(dp[row - 1][column], dp[row][column - 1])
    + grid[row][column]
```

二者的结构相同，区别只在于聚合算子：一个对来源求和，一个对来源取最小值。

## 二、双序列前缀模型：Q1143、Q72

为了自然表示空字符串，`i`和`j`定义为前缀长度：

```text
dp[i][j]处理的是：
text1[0, i)
text2[0, j)
```

因此：

```java
int[][] dp = new int[m + 1][n + 1];
char current1 = chars1[i - 1];
char current2 = chars2[j - 1];
return dp[m][n];
```

这里`m + 1`并不是固定模板，而是状态定义要求第0行、第0列表示空前缀。

### Q1143：最长公共子序列

```text
当前字符相等：dp[i][j] = 1 + dp[i - 1][j - 1]
当前字符不同：dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
```

### Q72：编辑距离

状态定义：

```text
dp[i][j] = word1前i个字符转换成word2前j个字符的最少操作数
```

末尾字符不同时，必须同时枚举三种“最后一步”：

```text
替换：dp[i - 1][j - 1] + 1
删除：dp[i - 1][j] + 1
插入：dp[i][j - 1] + 1
```

不能根据两个完整字符串的长度关系决定只执行哪一种操作。全局长度相等时，局部最优解仍可能包含删除和插入。

#### 为什么末尾相同时可以直接取左上角

当：

```text
word1[i-1] == word2[j-1]
```

两个结尾字符已经免费匹配，可以保留它们，把问题直接缩小为：

```text
dp[i][j] = dp[i-1][j-1]
```

这里不需要再和插入、删除、替换分支比较。设：

```text
A = word1前i-1个字符
B = word2前j-1个字符
c = word2的第j个字符
```

`dp[i-1][j]`表示把 `A` 转换成 `B+c` 的最少操作数。先完成这次转换，再删除末尾的 `c`，
就得到一条把 `A` 转换成 `B` 的合法方案：

```text
A -> B+c -> B
成本 = dp[i-1][j] + 1
```

而 `dp[i-1][j-1]`就是 `A -> B` 在全部合法方案中的最小值，因此：

```text
dp[i-1][j-1] <= dp[i-1][j] + 1
```

同理：

```text
dp[i-1][j-1] <= dp[i][j-1] + 1
```

替换候选则是：

```text
dp[i-1][j-1] + 1
```

明确比免费匹配多一次操作。因此：

```java
if (chars1[i - 1] == chars2[j - 1]) {
    dp[i][j] = dp[i - 1][j - 1];
} else {
    dp[i][j] = 1 + Math.min(
            dp[i - 1][j - 1],
            Math.min(dp[i - 1][j], dp[i][j - 1])
    );
}
```

也可以先计算三个带代价的候选，然后写：

```java
if (chars1[i - 1] == chars2[j - 1]) {
    ans = Math.min(ans, dp[i - 1][j - 1]);
}
```

但这个 `Math.min` 是冗余比较，因为左上角已经被证明不大于另外三个候选。直接赋值更能体现
“相同结尾免费匹配、同时消掉两个结尾”的状态缩减。

### Q115：不同的子序列

Q115与Q1143使用相同的双前缀坐标，但DP格子的语义不同：Q1143保存最优长度，Q115直接保存方案数。

```text
不使用s[i-1]：dp[i-1][j]
s[i-1] == t[j-1]时使用当前字符：dp[i-1][j-1]
```

因此字符相等时：

```text
dp[i][j] = dp[i-1][j] + dp[i-1][j-1]
```

任意s前缀组成空t都只有一种方案，即全部不选，所以`dp[i][0] = 1`。

## 三、单序列区间模型：Q5

定义：

```text
dp[left][right] = s[left..right]是否为回文串
```

转移：

```text
s[left] == s[right]
并且内部区间s[left + 1..right - 1]是回文串
```

对应代码：

```java
dp[left][right] = chars[left] == chars[right]
        && (right - left <= 2 || dp[left + 1][right - 1]);
```

因为当前区间依赖`left + 1`，所以`left`必须从大到小遍历；`right`从`left`向右遍历。

Q5还可以使用中心扩展，时间O(N^2)、空间O(1)；Manacher可进一步做到时间O(N)。因此区间DP不是
本题性能最优方法，但它是理解单序列区间模型的标准入口。

## 四、二维表压缩成一维表

存储压缩不会改变逻辑状态维度。例如Q64逻辑上仍然是`dp[row][column]`，只是计算当前行时：

```text
更新前dp[column]     = 上方格子
更新后dp[column - 1] = 当前行左方格子
```

是否能够压缩，取决于当前格子是否只依赖有限的上一行/上一列信息。第一次学习这些题时优先保留二维表，
先确认状态定义、初始化和遍历方向，再考虑空间优化。
