## 2. 状态机基础

### 2.1 状态机是什么

状态机（State Machine）是一种建模方式：

> 系统在任意时刻处于某个明确状态；发生某个事件后，从当前状态转移到另一个状态。

一个完整状态机通常包含：

```text
1. 状态集合
2. 初始状态
3. 输入或事件
4. 合法状态转移
5. 终止状态或最终答案
```

例如订单系统：

```text
待支付 --支付--> 已支付
已支付 --发货--> 已发货
已发货 --签收--> 已完成
```

`待支付、已支付、已发货、已完成`是状态；`支付、发货、签收`是事件；箭头表示合法转移。

### 2.2 股票问题中的状态与事件

以不限制交易次数为例，每天结束时只有两种互斥状态：

```text
cash：当天结束时不持有股票
hold：当天结束时持有股票
```

之所以统一定义成“当天结束时”，是为了让所有状态处于相同时间边界。一天结束时不可能既持股又不持股，
因此这两个状态互斥且覆盖了基础问题的全部情况。

合法转移：

```text
cash -> cash：今天不操作，收益变化0
cash -> hold：今天买入，收益变化-price
hold -> hold：今天不操作，收益变化0
hold -> cash：今天卖出，收益变化+price
```

可以把它记成：

```text
cash --买入(-price)--> hold
hold --卖出(+price)--> cash
cash --不操作(0)----> cash
hold --不操作(0)----> hold
```

### 2.3 普通状态机如何变成状态机 DP

普通状态机只关心当前处于哪个状态；股票题还需要知道：到达每个状态时能够获得的最大收益是多少。

因此定义：

```text
cash[i] = 第i天结束时不持股的最大收益
hold[i] = 第i天结束时持股的最大收益
```

状态转移就是对所有能够到达当前状态的入边取最大值：

```text
cash[i] = max(
    cash[i-1],                 // 昨天不持股，今天不操作
    hold[i-1] + prices[i]      // 昨天持股，今天卖出
)

hold[i] = max(
    hold[i-1],                 // 昨天持股，今天不操作
    cash[i-1] - prices[i]      // 昨天不持股，今天买入
)
```

这相当于在状态机所有可能的交易路径中，只保留到达每个状态时收益最大的路径。

### 2.4 状态机 DP 与普通 DP 的关系

状态机 DP 仍然是普通 DP，只是状态具有明显的业务语义。

普通一维 DP：

```text
dp[i] = 处理到位置i时的答案
```

状态机 DP：

```text
dp[i][state] =
处理到位置i，并且结束时处于state状态的答案
```

例如 Q152 最大乘积子数组：

```text
dp[i][MAX] = 必须以i结尾的最大乘积
dp[i][MIN] = 必须以i结尾的最小乘积
```

股票：

```text
dp[i][CASH] = 第i天结束时不持股的最大收益
dp[i][HOLD] = 第i天结束时持股的最大收益
```

它们都属于：

```text
位置维度 + 状态维度
```

区别是 Q152 的 MAX/MIN 是同一个结尾位置上的数值极值属性，股票的 CASH/HOLD 是互斥业务状态。
详细比较参见[《乘积最大子数组与股票状态机DP对比.md》](../乘积最大子数组与股票状态机DP对比.md)。

### 2.5 状态必须充分概括历史

一个有效状态必须满足：

> 一旦知道当前状态和对应最优值，未来决策就不再需要知道完整历史。

基础股票问题中，知道今天结束时是否持股以及该状态的最大收益后，未来不需要再知道：

```text
之前具体在哪一天买入；
之前具体在哪一天卖出；
经过了哪些价格；
哪条交易路径到达当前状态。
```

这些历史已经被压缩进 `cash[i]` 和 `hold[i]`。如果两个看似相同的情况对未来具有不同权限，就不能
合并成一个状态。

冷冻期就是典型例子。仅有“不持股”无法区分：

```text
今天不持股，明天允许买入；
今天刚刚卖出，明天禁止买入。
```

两种情况对未来操作权限不同，因此必须拆成 `sold/rest`。交易次数限制同理：未来还能交易几次会影响
决策，所以必须增加交易次数维度。

### 2.6 什么时候增加状态，什么时候只修改转移边

判断标准是：新规则是否改变未来合法操作。

冷冻期改变未来权限：

```text
昨天刚卖出 -> 今天不能买入
```

因此需要增加 `sold/rest` 状态。

手续费不改变未来权限，只改变卖出操作的收益：

```text
hold --卖出(+price-fee)--> cash
```

所以手续费不需要增加状态，只需修改转移边权。交易次数会影响未来还能否继续交易，因此需要增加
`transactionCount` 状态维度。

可以把股票题拆成两部分：

```text
状态节点：cash、hold、sold、rest、cash[t]、hold[t]
转移边：买入、卖出、不操作、冷冻结束
```

题目新增限制后，先判断它改变的是“节点所需信息”，还是“某条边的条件或代价”。

### 2.7 如何自己设计状态机 DP

按以下顺序建模：

```text
1. 选择统一时间边界，例如“第i天结束时”。
2. 列出这个边界下所有互斥且完整的状态。
3. 检查知道当前状态后，未来是否还需要其他历史信息。
4. 为每个状态画出所有合法入边。
5. 给买入、卖出、不操作等边添加收益变化。
6. 对所有入边转移值取max/min或其他目标运算。
7. 设置初始状态、不可达状态和最终合法状态。
8. 先写未压缩数组，确认每条边都读取上一天，再压缩空间。
```

每个新状态都必须回答两个问题：

```text
今天什么都不做，继承哪个昨日状态？
今天执行买入、卖出等操作，从哪个昨日状态转移？
```

初始化时，不持股状态通常为0，第一天持股相当于买入：

```text
cash[0] = 0
hold[0] = -prices[0]
```

最终通常返回合法的不持股状态，因为持股状态仍承担买入成本，利润尚未通过卖出兑现。

### 2.8 与 Java State Pattern 的区别

这里的状态机是算法和数学建模概念，不等同于 Java 设计模式中的 State Pattern。

Java State Pattern 通常通过：

```java
interface State {}
class CreatedState implements State {}
class PaidState implements State {}
```

封装不同业务状态的行为。状态机 DP 通常使用：

```java
int[][] dp;
int cash;
int hold;
```

保存到达状态时的最优数值。

```text
State Pattern：组织面向对象业务行为。
状态机 DP：计算状态转移路径上的最优答案。
```

### 2.9 状态机记忆结论

```text
状态机 = 有限个互斥状态 + 合法状态转移 + 每条转移的条件或代价。

状态机DP = 在每个时间位置，记录到达每个状态时的最优答案。
```

股票问题中：

```text
状态：持股、不持股，以及题目限制要求的扩展状态；
事件：买入、卖出、不操作；
边权：-price、+price、-fee、0；
DP值：到达该状态时的最大收益。
```

## 3. 股票状态机统一视角

股票题首先按“每天结束时处于什么状态”定义 DP，而不是直接从利润公式入手：

```text
cash[i] = 第i天结束时不持有股票的最大收益
hold[i] = 第i天结束时持有股票的最大收益
```

不限制交易次数时：

```text
cash[i] = max(cash[i-1], hold[i-1] + price[i])
hold[i] = max(hold[i-1], cash[i-1] - price[i])
```

每个新状态都必须回答两个问题：

```text
今天什么都不做，继承哪个昨日状态？
今天执行买入、卖出等操作，从哪个昨日状态转移？
```

## 4. Q121：最多一次交易

最多一次交易意味着卖出后不能再次买入。`cash` 的卖出转移不变，但 `hold` 的买入只能从“从未交易”的
初始现金0出发：

```text
newCash = max(oldCash, oldHold + price)
newHold = max(oldHold, -price)
```

这里不能写成普通无限交易的 `oldCash-price`，否则允许使用历史卖出利润再次买入。Q121 也可等价地维护
历史最低价格并计算 `price-minPrice`，但双状态写法更便于与整个股票系列建立联系。

## 5. Q122：不限交易次数

卖出后未来仍可买入：

```text
newCash = max(oldCash, oldHold + price)
newHold = max(oldHold, oldCash - price)
```

`oldCash-price` 表示使用之前已经完成若干次交易的收益再次买入。

## 6. Q123：最多两次交易

将交易次数直接展开成四个状态：

```text
buy1  = 完成第一次买入后的最大收益
sell1 = 完成第一次卖出后的最大收益
buy2  = 完成第二次买入后的最大收益
sell2 = 完成第二次卖出后的最大收益
```

转移：

```text
newBuy1  = max(oldBuy1, -price)
newSell1 = max(oldSell1, oldBuy1 + price)
newBuy2  = max(oldBuy2, oldSell1 - price)
newSell2 = max(oldSell2, oldBuy2 + price)
```

Q123 是 Q188 在 `K=2` 时的常数状态展开。

## 7. Q188：最多K次交易

定义：

```text
cash[t] = 最多完成t次卖出，当前不持股的最大收益
hold[t] = 为完成第t次交易而持股时的最大收益
```

转移：

```text
cash[t] = max(cash[t], hold[t] + price)
hold[t] = max(hold[t], cash[t-1] - price)
```

压缩天数维后，交易次数从大到小更新，保证 `hold[t]` 读取的 `cash[t-1]` 仍是上一天状态。

当：

```text
K >= prices.length / 2
```

交易次数限制已经不会生效，可以退化成 Q122，避免 `O(NK)` 的无意义开销。

## 8. Q309：含冷冻期

卖出后的第二天不能买入，因此仅有 `cash/hold` 无法区分“不持股但今天能否买入”，需要三个状态：

```text
hold = 今天结束时持股
sold = 今天执行卖出
rest = 今天结束时不持股，并且今天没有卖出
```

转移：

```text
newHold = max(oldHold, oldRest - price)
newSold = oldHold + price
newRest = max(oldRest, oldSold)
```

买入只能从 `oldRest` 转移，不能从昨天刚卖出的 `oldSold` 转移，这一条边就是冷冻期约束。

## 9. Q714：含手续费

状态数量不需要增加，只需在一次完整交易中扣除一次手续费。当前模板统一在卖出时扣费：

```text
newCash = max(oldCash, oldHold + price - fee)
newHold = max(oldHold, oldCash - price)
```

也可以统一在买入时扣费，但不能买入、卖出两边都扣。

## 10. 初始化

基础双状态：

```text
cash = 0
hold = -prices[0]
```

冷冻期：

```text
hold = -prices[0]
sold = 负无穷（第0天不可能完成卖出）
rest = 0
```

最终答案通常取合法的不持股状态。冷冻期返回 `max(sold,rest)`；其他模板返回 `cash/sell`，不返回
仍承担买入成本且尚未兑现的 `hold/buy` 状态。

## 11. 空间压缩纪律

先写未压缩公式，再压缩天数维。压缩后保存上一轮快照：

```java
int oldCash = cash;
int oldHold = hold;
cash = Math.max(oldCash, oldHold + price);
hold = Math.max(oldHold, oldCash - price);
```

不要因为某个基础题中使用本轮新值“碰巧不影响结果”，就破坏状态定义。加入手续费、冷冻期或次数维后，
这种写法很容易直接出错。

## 12. 识别题目后如何选模板

```text
最多1次                    -> Q121
不限制次数                 -> Q122
最多2次                    -> Q123
最多K次                    -> Q188
卖出后下一天不能买         -> Q309
每次交易扣固定费用         -> Q714
```

如果限制组合出现，例如“K次交易 + 手续费”，不要背新公式；保留交易次数状态，在对应买入或卖出边增加
手续费即可。

## 13. 高频错误

1. 没有写清“状态表示当天结束时持股还是不持股”。
2. Q121 错用 `oldCash-price`，不小心允许多次交易。
3. Q188 的交易次数语义不一致，买入和卖出分别在哪次交易计数没有统一。
4. Q309 从昨日 `sold` 直接买入，违反冷冻期。
5. Q714 在买入和卖出时重复扣手续费。
6. 压缩状态时使用了本轮刚更新的新值。
7. 最终返回 `hold`，把尚未卖出的持仓当成已实现利润。
