# 隐式图 DFS：数组也是图

## 先记住这个结论

> 用户理解：这道题算是图 DFS，只不过形态是在数组上。
>
> **正确。Q1306 是典型的图 DFS，图使用数组隐式表示，没有显式构建邻接表。**

专业术语是 **隐式图（Implicit Graph）**：节点之间的边不必预先存下来，可以在搜索时根据规则计算。

**数据的存储形式，不等于算法模型。存储在数组里，不代表只能用数组遍历、贪心或 DP；要看状态之间的连接关系。**

## Q1306 如何对应图

| 图的概念 | 本题对应 |
| --- | --- |
| 顶点 | 数组下标 `i` |
| 有向边 | `i → i - arr[i]`、`i → i + arr[i]`，只考虑合法落点 |
| 起点 | `start` |
| 目标顶点 | 满足 `arr[i] == 0` 的下标 |
| 访问标记 | `visited[i]` |

**顶点是下标，不是元素值。** 两个位置的值即使相同，它们的位置、邻居也可能不同，不能视为同一个状态。

这是有向图：允许向左右跳，不等于边一定双向。能从 `i` 到 `j`，不保证 `arr[j]` 能让它跳回 `i`。

例如 `arr = [1, 1, 0]`，从下标1出发：

```text
下标0 → 下标1
下标1 → 下标0、下标2
下标2的值为0：已经命中目标，无需继续展开
```

下标0和1之间存在环，所以需要访问标记。

## 与邻接表 DFS 的对比

普通图先把边存入邻接表，然后枚举：

```java
for (int next : adj.get(i)) {
    dfs(next);
}
```

本题不需要构造邻接表，直接计算两个邻居：

```java
boolean p1 = dfs(arr, i - arr[i], visited);
boolean p2 = dfs(arr, i + arr[i], visited);
return p1 || p2;
```

**区别只是“邻居从哪里来”，不是搜索模型变了。** 越界落点在递归入口被排除即可。

节点数 `V = N`，每个节点至多两条合法出边，`E <= 2N`。因此 DFS 的时间复杂度 `O(V + E)` 在本题中是 **O(N)**。

访问数组和最坏递归栈共需 **O(N)** 额外空间。很深的路径可能耗尽 Java 调用栈；显式栈 DFS 或队列 BFS 可以避免系统栈溢出。

## 访问标记的准确含义

```java
if (i < 0 || i >= arr.length || visited[i]) {
    return false;
}
```

`visited[i]` 表示**已经开始探索**，不是“已经计算出该节点不可达”。第一次调用可能仍在递归栈中，还没有返回。

这里返回 `false` 的含义是：**跳过这条重复分支，不从这里重复报告成功。** 该节点的第一次调用已经负责探索它的出边，找到目标后会沿调用链传播成功结果。

必须精确区分：

- 全局访问标记不会影响“从最初 start 能否到达0”的最终判断。
- 中间某个调用的 `false` 不一定代表从该节点单独出发也无法到达0。
- 不要把中间调用的结果随意解释为每个节点独立的可达性缓存。
- 访问标记无需回溯撤销：同一下标的出边固定，不会因到达路径不同而出现新的跳法。

例如从 `[1,1,0]` 的下标1开始，先搜0，0再次遇到已标记的1会跳过，导致0这一调用返回false；随后1继续探索2并成功。但若单独从0出发，也能通过1到达2。

用户写法先计算 `p1` 和 `p2`，即使 `p1` 成功也会计算 `p2`，仍然正确。可选优化是直接使用短路或：

```java
return dfs(arr, i - arr[i], visited)
    || dfs(arr, i + arr[i], visited);
```

## 为什么不同于跳跃游戏 I 和 II

| 题目 | 跳跃规则 | 关键模型 |
| --- | --- | --- |
| Q55 | 可选择向右跳 `1..nums[i]` 步 | 连续可达前缀，用最远边界压缩 |
| Q45 | 同上，要求最少跳数 | 当前层边界与下一层边界，区间压缩的 BFS |
| Q1306 | 只能跳到两个指定落点 | 落点离散且可能成环，图 DFS/BFS |

Q1306 中能到达下标5，不意味着中间的1、2、3、4都可达，因此不能仅保存一个最远下标。

类似地，Q200 岛屿数量是二维网格上的图搜索；Q1306 是一维数组上的图搜索。两者都可以由题目规则直接计算邻居，而不构建邻接表。
