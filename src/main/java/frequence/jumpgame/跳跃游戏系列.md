## Q1871：先定义状态，再优化转移

`dp[i]`表示从0出发能否实际到达下标i。它不是前缀长度，也不是单纯判断s[i]是否为0。

前驱j需要满足 `minJump <= i-j <= maxJump`，所以前驱窗口是 `[i-maxJump,i-minJump]`，与合法下标范围取交集。任意前驱可达且当前字符为0，当前状态才可达。

```text
dp[i] = s[i]=='0' && 前驱窗口中至少存在一个dp[j]==true
```

暴力扫描窗口最坏O(N²)。窗口计数或前缀和都能把每次查询降为O(1)，总体O(N)，额外空间O(N)。

## 滑动窗口：left管出，right管进

`valid`是前驱窗口内实际可达位置的数量。

```text
旧窗口：[i-1-maxJump, i-1-minJump]
新窗口：[i-maxJump,   i-minJump]
离开：left-1 = i-maxJump-1
进入：right  = i-minJump
```

先移除后加入完全正确；只有两步完成后的valid才用于dp转移。代码只统计合法下标，越界部分不贡献计数。进入和离开都必须检查dp，不是仅检查字符0。

当minJump=maxJump时，窗口只有一个候选位置：移除旧候选，再加入新候选。窗口整体位于负下标时没有合法前驱，计数为0。

当前字符即使为1，也要移动窗口。当前为0与前驱可达是两个独立条件，不能只写valid>0。`? true : false`可以省略，但用户代码保留。

## 前缀和：统计的是dp，不是字符0

`prefix[t]`统计 `dp[0..t-1]` 中true的数量，闭区间 `[L,R]` 的可达数量为 `prefix[R+1]-prefix[L]`。

允许落脚不代表能到达。例如s="0100"、minJump=maxJump=2，位置3虽为0，却没有可达前驱。

前缀和与滑动窗口统计完全相同的信息：前者用相减查询，后者用一出一进维护。不能把其中一个误解为只检查字符0。

## 复盘要点

- Q55只有一个可达边界，用户avail与farthest可合并。
- Q45两个边界语义不同，扫描完一层才增加跳数；原题保证可达。
- Q1306的visited返回false是跳过重复分支，不是缓存该节点不可达。
- Q1871所有前驱都在左侧，没有环；DP值已计算好，窗口只负责快速汇总它们。
