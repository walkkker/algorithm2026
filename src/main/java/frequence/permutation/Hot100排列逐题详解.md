## Q31 NextPermutation 【Hot 100】

### 核心思想与题目要求

31. 下一个排列
DONE: 【已独立完成】当前实现已通过排列家族对数器。状态见
`frequence/待独立完成题目清单.md`。
给定一个整数数组，将它原地修改成字典序中紧接着的下一个排列。
如果当前已经是最大排列，则将它重排为最小排列。只允许使用常数额外空间。
**字典序排列家族定位：**Q31是排列空间的“直接后继操作”。
从最小排列开始反复调用本方法，就能按字典序枚举全部排列；Q60则不经过
中间排列，直接定位第k个排列。详见同目录《字典序排列家族.md》。
**核心结构：**从右向左找第一个`nums[pivot] < nums[pivot + 1]`。
`pivot`右侧必然是非递增序列，表示这个后缀已经处于自己的最大排列。
想让整体变大，必须修改`pivot`；想让增量最小，必须使用右侧中大于
`nums[pivot]`的最小元素替换它，然后把新后缀变成最小升序排列。
**三步模板：**
    - 从右向左找最右上升点`pivot`。
    - 从右向左找第一个大于`nums[pivot]`的元素并交换。
    - 反转`[pivot + 1, n - 1]`，使后缀从最大降序变成最小升序。
例如`[1,3,5,4,2]`：最右上升点是3，右侧最小的更大元素是4，
交换得到`[1,4,5,3,2]`，再反转后缀得到`[1,4,2,3,5]`。
如果找不到`pivot`，整个数组是非递增的最大排列，反转全部即回到最小排列。
该算法同样适用于含重复值的数组。
时间复杂度`O(N)`，额外空间复杂度`O(1)`。

3. 每次更新后维持上述定义；只有在不变量仍成立时才移动指针、覆盖数据或进入下一状态。

        public void nextPermutation(int[] nums) {

## Q60 PermutationSequence 【扩展】

### 核心思想与题目要求

60. 排列序列
DONE: 【已独立完成】当前实现已通过排列家族对数器。状态见
`frequence/待独立完成题目清单.md`。
集合`[1,2,...,n]`共有`n!`个排列。将全部排列按字典序排列，
返回第`k`个排列。题目保证`1 <= n <= 9`且`1 <= k <= n!`。
**字典序排列家族定位：**Q31是“当前排列 -> 直接后继”；Q60是
“排名 -> 排列”，也叫排列的反排名（unranking）。如果从第1个排列连续执行
`k - 1`次Q31，也能得到第k个排列，但时间复杂度会与k成正比。
Q60利用阶乘分块直接跳过整块排列。
**阶乘分块：**当剩余`remaining`个数字时，固定当前第一个数字后，
后面共有`(remaining - 1)!`种排列。因此，字典序排列可以按首元素分成
若干个大小完全相同的块。
例如`n=4, k=9`，先把k转为0-based排名8：
首位每块3! = 6个：8 / 6 = 1，选剩余[1,2,3,4]的下标1 -> 2，块内排名2。
第二位每块2! = 2个：2 / 2 = 1，选剩余[1,3,4]的下标1 -> 3，块内排名0。
后续依次选1、4，答案为2314。
**为什么要执行`k--`：**题目的k从1开始，但“商表示第几块，
余数表示块内排名”的计算需要使用0-based排名。如果不先减1，每个阶乘块的
最后一项都会被错误分到下一块。
当前实现使用`ArrayList#remove(int)`删除已选数字，单次删除为
`O(N)`，总时间复杂度`O(N^2)`，额外空间`O(N)`。
在本题`n <= 9`的范围内这是面试最合适的实现；没有必要为了将删除优化到
`O(log N)`而引入Fenwick树。
这个阶乘编码直接适用于互异元素。如果元素可重复，每个首元素对应的块大小不再是
简单的阶乘，而需要用多重集排列数公式重新计算。

对于n个数字，核心思想：分块， 每块数量是 (n-1)!
那么对于k （1-based），找出它对应哪个块的第哪个？
- 要转化成 0-based。 k--
- 转化成0-based之后，算法类似于 二维矩阵映射一维数字。
- 块也是0-based， k也是0-based
- k/(n-1)! 就是第几个块，  k%(n-1)! 就是 第几个块的第几个位置 （全是0-based，算法跟 二维矩阵映射一维数字 的计算逻辑是一样的）
- 特别注意，确定头元素后，剩余的(n-1)进行重复流程，但是要保证n-1的元素还是从小到大排列。因为我们要的是(n-1)元素里面的第k%(n-1)!个 0-based。 => 所以这里要使用 list.remove(index) O(N)的方法。
- 续：list.remove() 因为要保证剩余元素的有序性
