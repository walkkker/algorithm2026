# DFS扩散与多源BFS：区别与注意事项

相关题目：

- [Q200 岛屿数量](./Q200_NumberOfIslands.java)
- [Q994 腐烂的橘子](./Q994_RottingOranges.java)

## 核心区别

| 问题 | 岛屿数量 | 腐烂的橘子 |
| --- | --- | --- |
| 目标 | 统计连通分量数量 | 计算全部橘子腐烂的最短时间 |
| 关心的信息 | 两个位置是否连通 | 每个位置最早在第几分钟被到达 |
| 起点 | 每发现一个未访问陆地，启动一次遍历 | 所有初始腐烂橘子同时作为起点 |
| 推荐算法 | DFS递归扩散或BFS | 多源BFS |
| 遍历顺序是否重要 | 不重要 | 重要，必须按距离分层 |

最重要的判断标准：

```text
只关心能否到达、是否属于同一个连通块：DFS或BFS都可以。
关心最少步数、最短距离、第几层到达：优先使用BFS。
存在多个起点同时传播：把所有起点一起入队，使用多源BFS。
```

## Q200为什么可以使用DFS递归扩散

岛屿数量只需要判断连通性。

发现一个尚未访问的陆地后，从该位置出发，将上下左右所有连通陆地标记为已访问：

```java
private void infect(char[][] grid, int row, int col) {
    if (row < 0 || row >= grid.length
            || col < 0 || col >= grid[0].length
            || grid[row][col] != '1') {
        return;
    }

    grid[row][col] = '0';

    infect(grid, row - 1, col);
    infect(grid, row + 1, col);
    infect(grid, row, col - 1);
    infect(grid, row, col + 1);
}
```

这里不关心某块陆地是第几步被访问，只要求当前岛屿中的所有陆地最终都被标记。

因此：

- DFS先访问哪个方向不影响答案；
- BFS同样可以解决；
- 外层循环每发现一个未访问的`'1'`，岛屿数量加1，再消除整个连通分量。

## Q994为什么应该使用多源BFS

腐烂橘子要求每个新鲜橘子的最早腐烂时间。

对于每个新鲜橘子，需要计算：

```text
它到所有初始腐烂橘子中的最短距离
```

最终答案是：

```text
所有新鲜橘子的最早腐烂时间中的最大值
```

可以表示为：

```text
answer = max(每个新鲜橘子到任意腐烂源的最短距离)
```

如果某个新鲜橘子无法从任何腐烂源到达，返回`-1`。

因为网格中每移动一步的代价都是1，所以按层执行BFS时，第一次到达某个位置就是最短距离。

## 为什么递归深度不能直接作为分钟

例如：

```text
2 1 1 1 2
```

两个初始腐烂橘子会同时扩散：

```text
第0分钟：2 1 1 1 2
第1分钟：2 2 1 2 2
第2分钟：2 2 2 2 2
```

正确答案是`2`。

如果先从左侧腐烂橘子执行普通DFS，可能按照下面的递归深度依次访问：

```text
0 -> 1 -> 2 -> 3
```

它会先把右侧位置标记为已腐烂。随后从右侧初始腐烂橘子开始时，这些位置已经被访问，无法再更新为更短时间。

DFS保证能够找到一条路径，但不能保证第一次到达某个节点时使用的是最短路径。

BFS按距离分层扩展，在无权图中第一次到达节点时，一定得到了最短距离。

## 多源BFS的标准结构

### 1. 初始化全部起点

```java
Queue<int[]> queue = new ArrayDeque<>();
int fresh = 0;

for (int row = 0; row < rows; row++) {
    for (int col = 0; col < cols; col++) {
        if (grid[row][col] == 2) {
            queue.offer(new int[]{row, col});
        } else if (grid[row][col] == 1) {
            fresh++;
        }
    }
}
```

所有初始腐烂橘子共同构成第0层，必须同时加入队列。

### 2. 按层处理

```java
int minutes = 0;

while (!queue.isEmpty() && fresh > 0) {
    int size = queue.size();

    while (size-- > 0) {
        int[] cur = queue.poll();
        // 当前层节点向上下左右扩散
    }

    minutes++;
}
```

进入当前循环时，队列中的`size`个节点属于同一分钟。当前层产生的新节点只能在下一轮继续扩散。

### 3. 入队时立即标记

```java
grid[nextRow][nextCol] = 2;
fresh--;
queue.offer(new int[]{nextRow, nextCol});
```

不能等到节点出队时再修改状态。

如果同一个新鲜橘子同时与两个腐烂橘子相邻，第一个腐烂橘子会立即将它改成`2`；第二个腐烂橘子再检查时会发现它已经不是`1`，因此不会重复入队，也不会重复执行`fresh--`。

通用原则：

```text
BFS节点应在加入队列时立即标记为已访问。
```

## DFS能否计算最短传播时间

理论上可以，但不能使用普通的“访问后不再进入”模型。必须维护每个位置的最早到达时间：

```java
if (time >= bestTime[row][col]) {
    return;
}

bestTime[row][col] = time;
```

后续发现更短路径时，还要重新更新该位置并继续传播。节点可能被多次访问，这已经变成递归形式的距离松弛，实现和复杂度都不如多源BFS稳定。

对于边权全部为1的最短传播问题，直接使用多源BFS。

## 易错点

1. 只把一个初始腐烂橘子加入队列，遗漏其他传播源。
2. 没有固定当前层的`queue.size()`，导致新腐烂橘子在同一分钟继续扩散。
3. 节点出队时才标记，导致同一位置重复入队。
4. 每个腐烂橘子分别执行一次BFS，产生大量重复遍历。
5. 初始没有新鲜橘子时错误返回`1`，正确答案应为`0`。
6. BFS结束后没有检查`fresh`，遗漏无法到达的新鲜橘子。
7. 把DFS递归深度直接当作最短传播时间。

## 复杂度

对于`M x N`网格：

- DFS统计岛屿：时间复杂度`O(MN)`，递归栈最坏为`O(MN)`。
- 多源BFS腐烂橘子：时间复杂度`O(MN)`，队列空间最坏为`O(MN)`。

每个位置最多被有效访问一次。

## 面试记忆

```text
连通块：找到一个起点，DFS/BFS消除整个连通分量。

最短传播：全部源点同时入队，按层BFS。

入队即标记，防止重复入队。

DFS深度是一条搜索路径的深度，不天然等于最短距离。
```
