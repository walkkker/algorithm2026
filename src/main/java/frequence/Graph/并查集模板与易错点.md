## Q200中的建模

每块陆地最初都是一个独立集合，`sets`初始化为陆地总数。每合并两个原本不同的陆地集合，
执行一次`sets--`，最终集合数量就是岛屿数量。

只检查右方和下方即可覆盖所有无向邻接边，同时避免重复检查。但“只检查两个方向”不等于可以
缩小遍历区域：最右列仍可能与下方相连，最下行仍可能与右方相连，因此必须遍历完整矩阵，并在
读取邻居之前分别检查边界。

## 二维坐标转一维编号

```java
int index(int row, int col) {
    return row * cols + col;
}
```

`parent`、`size`和路径压缩栈均使用一维编号。当前实现只初始化陆地位置，因此调用union之前
必须确认两个端点都是陆地，不能让水域进入find。

## find与union的接口分层

```text
numIslands：使用二维网格坐标
union     ：接收两个二维坐标，并完成2D -> 1D适配
find      ：并查集内部方法，只接收一维编号
```

`find(int index)`采用一维参数的原因是内部数据结构本来就是一维数组，不是因为方法声明为
private。可见性控制与参数模型是两个独立问题。

union必须先判断两个代表节点是否不同：

```java
if (root1 != root2) {
    // 按size合并
    sets--;
}
```

遗漏该条件会让已经属于同一集合的节点被重复合并，并错误减少`sets`。

## 本次错误汇总

| 错误或遗漏 | 后果 | 修正 |
| --- | --- | --- |
| 右下扫描时把循环写成`row < m-1 && col < n-1` | 漏掉最右列向下、最下行向右的连接 | 遍历完整矩阵，每个方向独立检查边界 |
| 读取邻居后才判断是否越界 | 数组越界 | 利用`&&`短路，先判断邻居存在 |
| 把find参数设计归因于private | 混淆可见性与数据模型 | find使用1D内部编号，union负责2D适配 |
| union遗漏`root1 != root2` | 重复执行`sets--` | 仅在两个代表节点不同的情况下合并 |
| 对水域调用find/union | 水域parent未初始化，集合结构被污染 | union前保证两个位置均为`'1'` |
