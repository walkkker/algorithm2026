# 回溯核心：递归树、枚举与恢复现场

## 第一部分：精炼结论

> 回溯就是对一棵决策树进行DFS。每个递归节点代表一个子问题，每一层枚举当前状态下的所有合法选择；做出选择后递归进入下一层，返回时根据共享状态是否会影响兄弟分支，决定是否恢复现场。

写回溯之前，必须先回答五个问题：

1. **递归函数的定义是什么？**
2. **参数分别描述什么状态？**
3. **当前递归层枚举什么选择？**
4. **什么情况下到达叶子节点并收集答案？**
5. **当前分支修改了什么共享状态，返回前是否必须恢复？**

统一模板：

~~~java
private void process(State state, Path path, List<Answer> ans) {
    if (到达叶子节点) {
        ans.add(当前答案的快照);
        return;
    }

    for (Choice choice : 当前层的所有合法选择) {
        做选择;
        process(下一层状态, path, ans);
        恢复现场;
    }
}
~~~

这里最重要的不是背模板，而是先说清楚：

~~~text
process(当前状态)究竟负责解决什么子问题？
process返回后，传入的共享状态应该处于什么状态？
~~~

以Q46全排列为例，一句话定义为：

> process(arr, i, ans)固定arr[0,i)，全排列arr[i,n)，将完整排列加入ans；方法返回时必须把arr恢复成进入方法时的状态。

这个定义一旦确定，base case、枚举范围、递归参数和恢复现场都能直接推导出来。

---

## 第二部分：为什么回溯一定具有枚举行为

回溯要寻找的是一个、多个或者全部可行解。当前状态通常存在多个可能的下一步，因此必须枚举这些选择，并沿每个合法选择继续向下搜索。

枚举不一定总是for循环，也可能表现为几个显式分支：

~~~java
// 选择当前元素
path.add(value);
process(nextState, path, ans);
path.remove(path.size() - 1);

// 不选择当前元素
process(nextState, path, ans);
~~~

这仍然是在枚举当前节点的两条边：

~~~text
选择
不选择
~~~

因此更准确的结论是：

> 回溯一定存在“枚举当前状态的合法选择”的行为，但枚举可以通过循环、多个if分支或者固定数量的递归调用表达。

## 第三部分：递归函数定义就是契约

递归函数不能只定义“它要做什么”，还要定义进入时和返回时的状态。

| 契约部分 | 要回答的问题 |
| --- | --- |
| 前置状态 | 调用process时，哪些选择已经确定？哪些还没有确定？ |
| 当前职责 | 当前调用负责枚举哪一部分答案？ |
| 后置状态 | process返回后，共享可变对象是否恢复成调用前的状态？ |

### Q46的严格定义

进入process(arr, i, ans)时：

~~~text
arr[0, i) 已经确定
arr[i, n) 尚未确定
~~~

当前职责：

~~~text
枚举arr[i,n)的所有排列，
把当前前缀能够形成的完整排列加入ans。
~~~

返回方法时：

~~~text
arr必须恢复成进入process时的排列状态。
~~~

不能写成“已经确定到i”，因为位置i正是当前层准备确定的位置。推荐始终使用左闭右开区间：

~~~text
[0,i) 已确定
[i,n) 待处理
~~~

## 第四部分：五道典型题的枚举对象

| 题目 | 递归层的含义 | 当前层枚举什么 | 下一层状态 |
| --- | --- | --- | --- |
| Q46 全排列 | 确定排列位置i | k属于[i,n)，谁占据位置i | i + 1 |
| Q78 子集 | 决定元素i是否进入子集 | 不选择 / 选择nums[i] | i + 1 |
| Q22 括号生成 | 根据已使用的l、r填写下一位 | 合法时添加左括号 / 右括号 | l或r增加1 |
| Q131 分割回文串 | 下一段从start开始 | end属于[start,n) | end + 1 |
| Q51 N皇后 | 在第row行放皇后 | column属于[0,n) | row + 1 |
| Q39 组合总和 | 从候选区间继续选择数字 | 当前层允许选择的候选数字或使用次数 | 新起点和剩余目标 |
| Q17 电话号码组合 | 填写结果位置index | 当前数字映射出的所有字母 | index + 1 |

### Q46：枚举剩余元素

~~~java
for (int k = i; k < arr.length; k++) {
    swap(arr, i, k);
    process(arr, i + 1, ans);
    swap(arr, i, k);
}
~~~

当前层要确定arr[i]，候选元素全部位于[i,n)。

### Q78：枚举选择与不选择

~~~java
// 不选择nums[i]
process(nums, i + 1, path, ans);

// 选择nums[i]
path.add(nums[i]);
process(nums, i + 1, path, ans);
path.remove(path.size() - 1);
~~~

这里没有for循环，但仍然存在枚举行为：当前递归节点有“不选择”和“选择”两条边。

这种二叉决策树在所有元素都完成决策，也就是i等于n时收集答案。另一种start + for写法会在
每个递归节点先收集当前path，再枚举后续候选元素。两种递归树的节点语义不同，因此收集答案的
位置也不同，不能把一套代码的base case机械套到另一套代码中。

### Q22：枚举下一位放左括号还是右括号

~~~java
if (left < n) {
    path.add('(');
    process(left + 1, right, n, path, ans);
    path.remove(path.size() - 1);
}

if (left > right) {
    path.add(')');
    process(left, right + 1, n, path, ans);
    path.remove(path.size() - 1);
}
~~~

状态含义：

~~~text
left：当前路径已经使用的左括号数量
right：当前路径已经使用的右括号数量
~~~

递归始终维持：

~~~text
0 <= right <= left <= n
~~~

- left小于n，说明仍可添加左括号；
- left大于right，说明当前存在尚未配对的左括号，才可添加右括号；
- right等于n时，根据不变量必然有left等于n，完整答案形成。

两个判断必须是独立if，不能写成if...else if。当left小于n且left大于right时，两种选择
同时合法，它们是当前决策节点的两条不同出边，都必须递归搜索。

### Q131：枚举下一段的结束位置

~~~java
for (int end = start; end < s.length(); end++) {
    if (palindrome[start][end]) {
        path.add(s.substring(start, end + 1));
        process(s, end + 1, path, ans);
        path.remove(path.size() - 1);
    }
}
~~~

这里的选择不是一个现成元素，而是一个动态区间[start,end]。

### Q51：枚举当前行的所有列

~~~java
for (int column = 0; column < n; column++) {
    if (canPlace(board, row, column)) {
        board[row] = column;
        process(row + 1, board, ans);
    }
}
~~~

每一行都枚举全部列[0,n)；[0,row)表示已经放好皇后的历史行。

### Q39：枚举候选元素

Q39有两种正确的递归树设计。

#### 模型一：选择下一个元素，并保证下标不下降

~~~java
for (int i = start; i < candidates.length; i++) {
    path.add(candidates[i]);
    process(candidates, i, rest - candidates[i], path, ans);
    path.remove(path.size() - 1);
}
~~~

元素允许重复使用，所以选择i之后，下一层仍可以从i开始。

这里真正的去重条件是：

~~~text
下一层只能继续选择当前下标i及其右侧元素，不能回到i之前。
~~~

例如[2,3,6,7]：

~~~text
[2,2,3]允许出现
[2,3,2]不会出现，因为选择3后不能回到2
[3,2,2]不会出现，因为选择3后不能回到2
~~~

题目已经保证candidates中的元素互不相同。即使输入元素不重复，如果每层都重新扫描整个数组，
仍会生成上面三种顺序。因此对输入使用HashSet去重，不能解决组合路径的排列型重复。

#### 模型二：每层确定一种候选数的使用次数

~~~java
// 当前数字使用0次
process(candidates, index + 1, path, ans, target);

for (int times = 1; candidate * times <= target; times++) {
    path.add(candidate);
    process(
            candidates,
            index + 1,
            path,
            ans,
            target - candidate * times
    );
}
~~~

当前层固定candidate，只枚举它使用0到target/candidate次，然后进入下一种候选数。每种数字只由
固定的一层处理，因此也不会产生选择顺序不同的重复组合。

其中“使用0次”不能遗漏。它是决策树的一条状态转移，负责跳过当前候选数；target等于0的
base case只负责终止和收集答案，不能创造这条缺失的分支。

面试优先使用模型一，因为代码更短，也更容易在排序后通过break完成单调剪枝；模型二更接近
完全背包的“每种物品选择0到若干件”原始递归模型。

### Q17：枚举当前数字对应的字母

使用固定长度char[]承载路径：

~~~java
char[] options = letters[digits[index] - '0'];
for (char option : options) {
    path[index] = option;
    process(index + 1, path, ans);
}
~~~

枚举的是当前数字对应的局部选择列表，不是全部数字对应字母的总列表。

也可以使用List<Character>承载路径：

~~~java
String options = map.get(digits[i]);
for (int k = 0; k < options.length(); k++) {
    path.add(options.charAt(k));
    process(digits, i + 1, path, ans);
    path.remove(path.size() - 1);
}
~~~

两种写法对应同一棵决策树，差别只在路径状态的维护方式：

| 路径容器 | 做选择 | 是否恢复 |
| --- | --- | --- |
| 固定长度char[] | path[i] = option | 兄弟分支覆盖同一位置，不需要 |
| List<Character> | path.add(option) | 改变了List长度，必须remove |

这说明是否恢复现场不由题目决定，而由当前实现修改共享状态的方式决定。

## 第五部分：承接容器不一定是List

路径状态记录从递归树根节点到当前节点已经作出的选择，但它不一定是List。

| 承载方式 | 典型题目 | 是否通常需要恢复 |
| --- | --- | --- |
| List | Q39、Q78、Q131 | add后通常必须remove |
| char[]固定位置 | Q17、Q22 | 下一分支覆盖同一位置，通常不需要 |
| int[]固定位置 | Q51 | 当前行会被兄弟分支覆盖，通常不需要 |
| int[]交换 | Q46 | 必须反向交换，恢复候选状态 |
| 原始棋盘原地标记 | Q79 | 必须恢复，否则影响其他路径 |
| StringBuilder | 字符串路径题 | append后通常必须恢复长度 |
| 值类型参数 | 剩余目标、左右括号数量 | Java按值传递，通常不需要 |

所以不能简单记成：

~~~text
数组不恢复，List要恢复。
~~~

正确判断标准只有一个：

> 当前分支对共享可变状态的修改，在递归返回后是否会被兄弟分支读取？

如果会，就必须恢复。

### Q46为什么必须恢复数组

交换修改了两个位置，也改变了父节点看到的剩余候选状态。兄弟分支需要从相同父状态开始，因此必须交换回来。

### Q51为什么不需要恢复board[row]

下一个兄弟分支会重新写入board[row]，合法性检查只读取board[0,row)，不会读取尚未确定的后缀，因此旧值不会污染后续分支。

### Q131为什么必须恢复List

List.add改变了共享容器的长度。如果不删除，兄弟分支会携带上一分支留下的子串。

## 第六部分：收集答案与保存快照

到达叶子节点时，通常需要把当前路径加入答案：

~~~java
if (到达叶子节点) {
    ans.add(当前路径的快照);
    return;
}
~~~

如果路径是共享可变容器，必须保存快照：

~~~java
ans.add(new ArrayList<>(path));
~~~

不能直接保存path引用，否则ans中的多个位置会指向同一个对象，后续回溯会继续修改已经收集的答案。

固定长度字符数组可以在收集时转成String：

~~~java
ans.add(new String(path));
~~~

即使某些代码不写return也会因为后续循环范围为空而暂时得到正确结果，也应显式返回，保持终止语义完整。

## 第七部分：从定义推导代码

以后遇到回溯题，按下面顺序写。

### 1. 定义递归函数

~~~text
process(state)负责解决什么范围的子问题？
~~~

例如：

~~~text
Q46：固定[0,i)，排列[i,n)。
Q131：已经完成[0,start)，继续切分[start,n)。
Q51：已经放好[0,row)行，继续放置[row,n)行。
~~~

### 2. 确定当前层选择

当前层要确定哪个位置、区间、元素或者业务状态？所有候选选择从哪里来？

### 3. 确定合法性与剪枝

- Q51排除同列和对角线冲突；
- Q131排除非回文区间；
- Q39排除剩余目标小于0的选择；
- Q79排除越界、字符不匹配和重复使用的格子。

### 4. 确定base case

base case必须直接来自递归定义：待处理范围为空、所有位置填满或者目标状态满足。

### 5. 检查恢复现场

列出当前分支修改的每一项共享状态：List、交换数组、visited、棋盘标记、StringBuilder。兄弟分支还会读取的修改必须逐项撤销。

## 最终总结

回溯不是“递归 + List + remove”的固定代码，而是：

~~~text
1. 定义递归子问题；
2. 用参数描述当前子问题的状态；
3. 枚举当前递归节点的全部合法选择；
4. 做选择并进入下一层；
5. 到达叶子节点时保存答案快照并return；
6. 返回父节点前恢复会影响兄弟分支的共享状态。
~~~

最核心的一句话：

> 先定义process负责什么，再把每次调用看成决策树上的一个节点；当前层枚举节点的所有出边，递归返回时保证父节点状态没有被当前分支污染。
