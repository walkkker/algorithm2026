# 回溯解题技巧

> 我觉得做回溯就是把递归树给想象出来，每一层有一些选择。这样还能确定承载容器是否需要做恢复现场动作（固定长数组一般不需要，List需要等等）。

这句话就是回溯的核心。回溯不是需要单独死记的特殊算法，而是：

```text
深度优先遍历一棵由“选择”构成的递归树。
```

每进入一层递归，就确定答案中的一个位置或做出一次选择；递归返回时，再根据共享状态是否会影响兄弟分支，决定是否恢复现场。

## 一、先画出递归树

写代码前先回答四个问题：

| 问题 | 含义 |
| --- | --- |
| 当前层代表什么 | 正在填写第几个位置、正在考虑第几个元素，或者正在选择下一步 |
| 当前层有哪些选择 | 字母、数字、括号、数组元素、棋盘位置等 |
| 哪些选择不合法 | 越界、重复使用、违反题目约束、无法组成答案 |
| 什么时候收集答案 | 固定长度填满、所有元素考虑完成、目标值归零等 |

例如 Q17 电话号码的字母组合：

```text
第0层：选择第0个数字对应的字母
第1层：选择第1个数字对应的字母
第2层：选择第2个数字对应的字母
...
```

例如 Q22 括号生成：

```text
第index层：决定答案的第index个字符放'('还是')'
```

递归树一旦明确，方法参数通常也会自然确定：

```java
process(index, path, otherState, ans);
```

其中：

- `index`表示当前递归层；
- `path`表示从根节点走到当前位置已经做出的选择；
- `otherState`表示剩余目标、左右括号数量、已使用元素等约束；
- `ans`收集所有叶子节点对应的答案。

## 二、回溯的通用模板

```java
private void process(State state, Path path, List<Answer> ans) {
    if (到达叶子节点) {
        ans.add(复制当前答案);
        return;
    }

    for (Choice choice : 当前层的所有选择) {
        if (choice不合法) {
            continue;
        }

        做选择;
        process(下一层状态, path, ans);
        恢复现场;
    }
}
```

真正需要思考的不是模板，而是：

```text
当前层是什么？
当前层有哪些合法选择？
做选择时修改了哪些共享状态？
兄弟分支是否会读取这些修改？
```

## 三、终止型base case收集答案后必须return

典型的叶子节点终止条件：

```java
if (index == path.length) {
    ans.add(new String(path));
    return;
}
```

这里的`return`不能遗漏。

### 依据

`base case`表示当前递归分支已经到达叶子节点：

```text
当前答案已经完整；
当前层已经没有合法选择；
当前分支不应该继续向下展开。
```

收集答案后如果不立即返回，程序会继续执行base case下面的“选择和递归”代码，相当于强行给叶子节点继续添加孩子。

可能产生以下后果：

### 1. 固定长度数组发生越界

```java
if (index == path.length) {
    ans.add(new String(path));
    // 漏掉return
}

path[index] = choice;
```

此时`index == path.length`，继续访问`path[index]`会产生
`ArrayIndexOutOfBoundsException`。

Q17中如果遗漏`return`，后面还可能继续访问：

```java
chs[index]
```

同样会越界。

### 2. 已经完整的答案继续被扩展

例如目标和已经满足：

```java
if (remaining == 0) {
    ans.add(new ArrayList<>(path));
    return;
}
```

如果收集后继续尝试选择，当前分支可能产生不符合要求的更长路径、重复答案，甚至在元素可以重复选择时产生无效递归。

### 3. 终止条件失去意义

base case不仅负责“收集答案”，还负责“截断当前分支”。完整结构必须是：

```java
if (到达终止状态) {
    收集答案;
    return;
}
```

面试时可以直接记忆：

```text
终止型base case：收集完答案，千万别忘return！
```

### 重要例外：收集节点不一定是终止节点

Q78子集通常在每个递归节点都收集当前路径：

```java
ans.add(new ArrayList<>(path));

for (int i = start; i < nums.length; i++) {
    ...
}
```

这里当前路径本身是一个答案，但仍然需要继续选择后续元素，生成更长的子集。因此这段收集逻辑不是终止型base case，不能立即`return`。

判断标准：

```text
如果当前状态已经是递归树叶子节点：收集后return。
如果当前状态既是答案，又仍然可以产生其他答案：收集后继续展开。
```

## 四、如何判断是否需要恢复现场

判断标准只有一个：

> 当前分支修改的状态，在递归返回后，是否会被下一个兄弟分支继续读取？

如果会，就必须恢复；如果下一分支一定会覆盖该位置，或者状态通过值传递形成了独立副本，就不需要恢复。

### 1. 固定长度数组按当前下标覆盖：通常不需要恢复

典型题：

- Q17 电话号码的字母组合；
- Q22 括号生成。

```java
path[index] = option;
process(index + 1, path, ans);
```

下一条兄弟分支会再次执行：

```java
path[index] = nextOption;
```

当前下标会被直接覆盖，而更深层下标也会在后续递归中重新填写，因此不需要：

```java
path[index] = 0;
```

但是收集答案时必须创建结果对象：

```java
ans.add(new String(path));
```

不能把同一个可变数组引用直接保存到答案中。

### 2. List执行add：通常必须remove

典型题：

- Q78 子集；
- Q39 组合总和；
- Q131 分割回文串。

```java
path.add(choice);
process(...);
path.remove(path.size() - 1);
```

`path.add(choice)`改变了List长度。递归返回后，如果不删除，兄弟分支会看到上一分支残留的元素。

收集答案时也必须复制：

```java
ans.add(new ArrayList<>(path));
```

错误写法：

```java
ans.add(path);
```

它会让答案中的多个元素指向同一个List，后续回溯会继续修改已经收集的答案。

### 3. StringBuilder执行append：必须删除

```java
path.append(choice);
process(...);
path.deleteCharAt(path.length() - 1);
```

也可以记录修改前长度，更适合一次追加多个字符：

```java
int oldLength = path.length();
path.append(choice);
process(...);
path.setLength(oldLength);
```

### 4. visited数组：必须恢复

典型题：Q46 全排列。

```java
used[i] = true;
process(...);
used[i] = false;
```

如果不恢复，当前分支使用过的元素在兄弟分支中仍然会被认为不可选择。

### 5. 原地修改棋盘或网格：通常必须恢复

典型题：Q79 单词搜索。

```java
char original = board[row][col];
board[row][col] = '#';

boolean found = process(...);

board[row][col] = original;
```

当前路径不能重复使用同一单元格，但其他搜索起点或兄弟路径仍然可以使用它，因此递归返回时必须恢复。

### 6. Set记录当前路径状态：必须恢复

```java
used.add(choice);
process(...);
used.remove(choice);
```

除非每次递归都创建一个全新的Set副本，否则共享Set必须回溯。

### 7. 基本类型参数按值传递：通常不需要恢复

```java
process(index + 1, left + 1, right, path, ans);
```

Java基本类型参数按值传递。子调用修改的是自己的局部变量，不会修改父调用中的`left`和`right`，因此不需要在递归后执行`left--`。

为了减少恢复操作，优先把新状态直接写入递归参数：

```java
process(index + 1, count + 1);
```

而不是：

```java
count++;
process(index + 1, count);
count--;
```

两种写法都正确，但第一种更稳定。

## 五、固定长度数组并非一定不需要恢复

“固定长度数组一般不需要恢复”成立的前提是：

```text
每层只写自己的固定下标，并且兄弟分支一定会覆盖该下标。
```

如果修改了其他位置，或者兄弟分支依赖数组当前排列，就必须恢复。

### 数组交换必须恢复

全排列也可以使用交换模型：

```java
swap(nums, index, i);
process(index + 1, nums, ans);
swap(nums, index, i);
```

进入`process(nums, index)`时必须维持：

```text
nums[0, index)            已经确定的排列前缀
nums[index, nums.length)  当前层可以选择的剩余元素
```

第一次交换表示做出选择：

```java
swap(nums, index, i);
```

第二次交换表示撤销选择：

```java
swap(nums, index, i);
```

交换相同的两个位置是自身的逆操作，可以把数组恢复到进入当前分支之前的父状态。

虽然`nums`是固定长度数组，但交换修改了两个位置以及后续兄弟分支依赖的候选排列。递归返回后
必须交换回来，否则下一个兄弟分支无法从相同的父状态出发。

### 不恢复时的具体错误

输入：

```text
[1, 2, 3]
```

第一棵子树可以收集：

```text
[1, 2, 3]
[1, 3, 2]
```

如果不恢复，返回根节点时数组停留在：

```text
[1, 3, 2]
```

后续循环不再从原始父状态`[1,2,3]`开始。最终可能得到：

```text
[1,2,3]
[1,3,2]
[3,1,2]
[3,2,1]
[1,2,3]  重复
[1,3,2]  重复
```

并且遗漏：

```text
[2,1,3]
[2,3,1]
```

根本原因不是“数组内容看起来乱了”，而是：

```text
for循环中的每个i代表同一个父节点的不同子分支；
所有兄弟分支必须从同一份父状态出发。
```

因此不能只根据容器类型判断，而要根据修改方式判断：

```text
固定下标覆盖：通常不恢复。
交换、累计、标记或修改其他位置：必须恢复。

swap一次是做选择；
再swap一次是撤销选择。
```

## 六、收集答案时要保存快照

回溯通常复用同一个`path`对象。到达叶子节点时，需要把当前状态转换为独立答案。

### char[]

```java
ans.add(new String(path));
```

### List

```java
ans.add(new ArrayList<>(path));
```

### StringBuilder

```java
ans.add(path.toString());
```

### int[]

```java
ans.add(Arrays.copyOf(path, path.length));
```

核心原则：

> 答案保存的是当前路径的快照，不能保存后续还会被修改的共享容器引用。

## 七、选择、约束和剪枝

回溯的每一层不是无条件尝试所有选择，而是只展开可能产生合法答案的分支。

### Q22 括号生成

始终维持：

```text
left >= right
left <= n
```

按照状态分类：

```text
left == right
    只能放左括号

left > right && left == n
    只能放右括号

left > right && left < n
    左右括号都可以放
```

这就是在递归树展开之前删除非法分支。

### Q39 组合总和

如果候选数组均为正数，并且当前累计和已经超过目标：

```java
if (sum > target) {
    return;
}
```

这是利用题目单调性进行剪枝。如果元素允许负数，就不能使用这个条件。

## 八、start参数解决组合去重

排列和组合的递归树不同。

### 排列

每层可以从全部尚未使用的元素中选择：

```java
for (int i = 0; i < nums.length; i++) {
    if (!used[i]) {
        ...
    }
}
```

### 组合或子集

为了避免把`[1, 2]`和`[2, 1]`当成两个答案，下一层只能从当前位置之后继续选择：

```java
for (int i = start; i < nums.length; i++) {
    path.add(nums[i]);
    process(i + 1, path, ans);
    path.remove(path.size() - 1);
}
```

因此：

```text
排列关注“哪些元素已经使用”：常用used。
组合关注“后面还能从哪里选择”：常用start。
```

## 九、常见错误

| 错误 | 后果 |
| --- | --- |
| 没有明确当前递归层的含义 | 参数和终止条件混乱 |
| List只add不remove | 兄弟分支携带上一分支残留 |
| visited只标记不恢复 | 后续分支无法使用合法元素 |
| 收集答案时直接保存path引用 | 所有答案最终变成相同内容 |
| 固定数组无条件执行恢复 | 通常不影响正确性，但增加无意义操作和理解成本 |
| 固定数组执行swap后不恢复 | 兄弟分支起始状态被破坏 |
| 没有先判断空输入 | 可能错误收集空路径 |
| 终止型base case收集答案后漏写return | 数组越界、非法扩展或重复递归 |
| 去重时没有区分排列和组合 | 产生重复答案或遗漏答案 |
| 剪枝没有确认单调性 | 在存在负数等情况下漏解 |

## 十、写代码前的检查清单

```text
1. 当前递归的第index层表示什么？
2. 当前层有哪些选择？
3. 哪些选择不合法，可以提前剪枝？
4. 什么时候到达叶子节点并收集答案？
5. 终止型base case收集答案后是否立即return？
6. path使用什么容器？
7. 做选择时修改了哪些共享状态？
8. 兄弟分支会不会读取这些状态？
9. 是否需要恢复现场？
10. 收集答案时是否创建了快照？
11. 本题是排列模型、组合模型，还是网格路径模型？
```

## 十一、面试记忆

```text
先画递归树：每一层做一个选择。

再定四件事：当前层、可选项、剪枝条件、结束条件。

终止型base case：收集完答案，千万别忘return。

是否恢复现场，不看“是不是回溯”，而看共享状态会不会影响兄弟分支。

固定下标覆盖通常不用恢复；
List add、visited标记、网格修改、数组交换通常需要恢复。

收集答案必须保存快照。
```
