# 双指针解题手册

## 1. 本质

双指针不是一个固定代码模板，而是一类优化思想：

> 利用单调性或局部确定性，每次排除一部分不可能答案，或者直接结算一个位置，
> 将暴力枚举的 `O(N^2)` 优化为 `O(N)`。

代码中出现 `L、R` 或 `slow、fast` 不代表算法自动成为 `O(N)`。
复杂度取决于所有指针和内部循环的总移动次数。

例如移动零的错误解法虽然使用了 `L、R`，但每发现一个零都要移动后续元素，
最坏交换次数为：

```text
(N - 1) + (N - 2) + ... + 1 = O(N^2)
```

## 2. 解题五问

遇到双指针题，先回答下面五个问题，再写代码：

```text
1. 两个指针分别表示什么？
2. 已处理区间和待处理区间分别在哪里？
3. 循环过程中保持什么不变量？
4. 为什么当前条件下可以移动这个指针，并且不会遗漏答案？
5. 每个指针是否单调移动，从而保证总复杂度？
```

最重要的是第 4 问：

> 双指针题的难点不是“如何移动”，而是“为什么可以这样移动”。

## 3. 主要模型

| 模型 | 代表题目 | 指针含义 | 移动依据 |
|---|---|---|---|
| 同向读写指针 | 移动零、移除元素、数组去重 | `fast` 读取，`slow` 写入 | 当前元素是否需要保留 |
| 相向有序搜索 | 三数之和 | `L、R` 搜索目标组合 | 当前和过小移动 `L`，过大移动 `R` |
| 相向边界收缩 | 盛最多水的容器 | `L、R` 是容器边界 | 移动较矮边界才可能提高面积 |
| 相向局部结算 | 接雨水 | `L、R` 是未结算区间两端 | 哪侧历史最高挡板较矮，就结算哪侧 |
| 滑动窗口 | 最长无重复子串等 | `L、R` 表示当前窗口 | `R` 扩展，条件失效时收缩 `L` |
| 链表快慢指针 | 中点、判环、环入口 | 两指针速度不同 | 利用速度差建立位置或距离关系 |

当前 package 中主要包含前三种数组相向指针和接雨水；同向读写模型单独放在：

```text

```

## 4. 同向读写：原地稳定压缩

通用骨架：

```java
int slow = 0;

for (int fast = 0; fast < nums.length; fast++) {
    if (nums[fast] 满足保留条件) {
        nums[slow++] = nums[fast];
    }
}
```

循环不变量：

```text
[0, slow) 保存 nums[0...fast) 中所有需要保留的元素，
并且这些元素的相对顺序不变。
```

三个关键词：

```text
原地：直接修改原数组，额外空间 O(1)
稳定：保留元素的相对顺序不变
压缩：保留元素被连续写入数组前部 [0, slow)
```

各题只是保留条件不同：

| 题目 | 保留条件 |
|---|---|
| `Q283_MoveZeroes` | `nums[fast] != 0` |
| `Q27_RemoveElement` | `nums[fast] != val` |
| `Q26_RemoveDuplicatesFromSortedArray` | 当前值不等于最后一个已保留值 |

详细说明见
[同向读写双指针_原地稳定压缩/note.md](./同向读写双指针_原地稳定压缩/note.md)。

## 5. 三数之和：相向有序搜索

核心是先排序，再固定一个数，把三数之和降维成两数之和：

```text
nums[i] + nums[L] + nums[R] = 0
```

排序后具有单调性：

```text
sum < 0：当前和太小，只能 L++
sum > 0：当前和太大，只能 R--
sum = 0：收集答案，然后 L++、R--
```

去重原则：

> 相同值必须让第一个位置先参与计算，后面的相同值再跳过。

固定位置去重：

```java
if (i > 0 && nums[i] == nums[i - 1]) {
    continue;
}
```

不能与后一个元素比较后跳过当前元素：

```text
错误：[0, 0, 0]

如果第一个 0 因为和后一个 0 相同而被跳过，
最后一个 0 的右侧已经没有足够元素，会遗漏 [0, 0, 0]。
```

复杂度：

```text
排序 O(N log N)
外层枚举 O(N) × 内层双指针 O(N)
总时间复杂度 O(N^2)
```

## 6. 盛最多水的容器：相向边界收缩

面积：

```text
area = min(height[L], height[R]) * (R - L)
```

注意宽度是：

```text
R - L
```

下标表示的是两条线的位置，不是 `[L, R]` 中元素的数量，因此不是 `R - L + 1`。

为什么移动较矮侧？

假设：

```text
height[L] <= height[R]
```

如果保留 `L`、移动 `R`：

```text
宽度一定缩小
有效高度仍然不可能超过 height[L]
面积不可能增大
```

因此必须移动较矮的 `L`，尝试找到更高的新边界。

记忆：

> 宽度缩小不可避免，只能尝试提高较矮边界。

## 7. 接雨水：相向局部结算

每列接水公式：

```text
water[i] = min(leftMax[i], rightMax[i]) - height[i]
```

双指针维护：

```text
leftMax  = [0, L] 中的最大值
rightMax = [R, N - 1] 中的最大值
```

如果：

```text
leftMax <= rightMax
```

右侧已经确定存在一个不低于 `leftMax` 的挡板，因此 `L` 位置的水量已经确定：

```text
water[L] = leftMax - height[L]
```

此时可以结算 `L` 并执行 `L++`。反之结算 `R`：

```java
while (L <= R) {
    leftMax = Math.max(leftMax, height[L]);
    rightMax = Math.max(rightMax, height[R]);

    if (leftMax <= rightMax) {
        ans += leftMax - height[L];
        L++;
    } else {
        ans += rightMax - height[R];
        R--;
    }
}
```

记忆：

> 哪一侧的历史最高挡板更矮，哪一侧当前格子的水量就已经可以确定。

这里利用的是“局部答案已经确定”，而不是像三数之和那样排除搜索范围。

## 8. 滑动窗口

滑动窗口也是同向双指针，但它维护的是一个连续区间，而不是读写位置：

```java
int L = 0;

for (int R = 0; R < nums.length; R++) {
    将 nums[R] 加入窗口状态;

    while (窗口条件不满足) {
        将 nums[L] 移出窗口状态;
        L++;
    }

    使用当前合法窗口 [L, R] 更新答案;
}
```

适用前提通常是窗口状态具有可维护性，并且移动 `L` 后能够朝恢复合法性的方向变化。
数组包含负数时，窗口和通常不再具有单调性，不能机械套用滑动窗口。

## 9. `for + while` 为什么仍可能是 O(N)

不能只看循环嵌套层数，要看指针总移动次数。

三数之和中，每次固定 `i` 后：

```text
L 只向右移动
R 只向左移动
```

因此单轮双指针是 `O(N)`，外层再乘一个 `O(N)`，总计 `O(N^2)`。

滑动窗口中，整个算法执行期间：

```text
R 最多右移 N 次
L 最多右移 N 次
```

所以即使结构是 `for + while`，总复杂度仍为 `O(N)`。

## 10. 高频错误

### 10.1 找到答案后没有移动指针

```java
if (sum == target) {
    ans.add(...);
    // 必须移动 L、R，否则下一轮状态不变，形成死循环
}
```

### 10.2 去重方向错误

保留第一个重复值，让后续重复值跳过：

```java
if (i > 0 && nums[i] == nums[i - 1]) {
    continue;
}
```

### 10.3 混淆距离和元素数量

```text
端点距离：R - L
闭区间元素数量：R - L + 1
```

### 10.4 指针移动后继续访问数组

指针执行 `L++` 或 `R--` 后，新的下标还没有重新经过循环条件检查。
不要在本轮后续代码中直接访问 `nums[L]` 或 `nums[R]`。

### 10.5 整数溢出

三数之和等涉及多个 `int` 相加时，先转成 `long`：

```java
long sum = (long) nums[i] + nums[L] + nums[R];
```

## 11. 面试表达模板

不要直接报出代码，按下面顺序说明：

```text
1. 暴力解法为什么慢。
2. 题目中存在什么单调性或局部确定性。
3. 两个指针分别表示什么。
4. 循环不变量是什么。
5. 为什么移动当前指针不会遗漏答案。
6. 每个指针总共移动多少次，得到什么复杂度。
```

最终记忆：

> 双指针的代码通常很短，价值集中在移动依据和正确性证明。
