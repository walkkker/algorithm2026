你的理解没错：

> **具体实现技巧是 `slow / fast` 快慢指针。**  
> **“原地稳定压缩”描述的是这类快慢指针正在完成什么操作。**

这是两个不同层次的命名。

**为什么叫原地稳定压缩**

以：

```text
[0, 1, 0, 3, 12]
```

为例，我们真正做的是把所有非零元素：

```text
[1, 3, 12]
```

按照原来的顺序，连续放到数组前部：

```text
[1, 3, 12, 0, 0]
```

三个词分别表示：

- **原地**：直接修改原数组，额外空间 `O(1)`。
- **稳定**：非零元素原来是 `1、3、12`，处理后仍然是 `1、3、12`，相对顺序不变。
- **压缩**：原本分散在数组中的保留元素，被连续放入 `[0, slow)`。

对应的不变量是：

```text
[0, slow) 保存已经扫描过的全部保留元素，并且相对顺序正确。
```

所以：

```text
fast = 读取指针
slow = 写入指针
```

严格来说，它也可以叫：

> **同向读写双指针**

这个名字比“快慢指针”更加准确，因为这里不一定强调两个指针移动速度不同，而是强调一个负责读取，一个负责写入。

**题目演进关系**

这个专题以同向读写双指针为核心，并继续收录输出扩张、双输入流和多分区边界等直接扩展：

| 题目 | 模型变化 | 核心状态或不变量 |
|---|---|---|
| `Q27_RemoveElement` | 固定条件过滤 | `[0, slow)` 是全部保留元素 |
| `Q26_RemoveDuplicatesFromSortedArray` | 保留条件依赖压缩结果 | 与 `nums[slow - 1]` 比较 |
| `Q80_RemoveDuplicatesFromSortedArrayII` | 每个值最多保留 K 次 | 与 `nums[slow - k]` 比较 |
| `Q283_MoveZeroes` | 保留元素且整理尾部 | `[slow, fast)` 全是零 |
| `Q443_StringCompression` | 一个输入分组产生多个输出 | 始终满足 `write <= read` |
| `Q1047_RemoveAllAdjacentDuplicatesInString` | 写指针可以后退 | `slow` 同时是模拟栈顶 |
| `Q1209_RemoveAllAdjacentDuplicatesInStringII` | 栈中增加连续次数 | `count[i]` 记录以 i 结尾的组长度 |
| `Q1089_DuplicateZeros` | 输出数量可能大于输入 | 反向读写 + 虚拟输出下标 |
| `Q88_MergeSortedArray` | 两个输入流合并 | 两个反向读指针 + 一个写指针 |
| `Q75_SortColors` | 一个有效区扩展为多个分区 | 0区、1区、未处理区、2区 |
| `RetainElementsByCondition` | 通用过滤模板 | 谓词决定是否写入 |

它们的通用骨架都是：

```java
int slow = 0;

for (int fast = 0; fast < nums.length; fast++) {
    if (nums[fast] 满足保留条件) {
        nums[slow++] = nums[fast];
    }
}
```

只有 `Q283_MoveZeroes` 使用了交换，因为它不仅要把非零元素放到前面，还要求后面的元素明确变成 `0`。

**Q283：一阶段交换法为什么不需要补零**

`fast` 找到非零元素后，将它与 `slow` 指向的位置交换：

```java
public void moveZeroes(int[] nums) {
    int slow = 0;

    for (int fast = 0; fast < nums.length; fast++) {
        if (nums[fast] != 0) {
            if (slow != fast) {
                int temp = nums[slow];
                nums[slow] = nums[fast];
                nums[fast] = temp;
            }
            slow++;
        }
    }
}
```

循环开始处理 `fast` 位置时，维护以下区间不变量：

| 区间 | 含义 |
|---|---|
| `[0, slow)` | 已整理完成的非零元素，且相对顺序与原数组一致 |
| `[slow, fast)` | 全部是零 |
| `[fast, n)` | 尚未检查的输入 |

因此，当 `slow < fast` 且 `nums[fast] != 0` 时，一定有：

```java
nums[slow] == 0
```

交换完成后：

- 当前非零元素进入有效区末尾；
- `slow` 位置原来的零被交换到 `fast`；
- `slow++` 后，三个区间的不变量继续成立。

例如：

```text
[0, 1, 0, 3, 12]

fast 找到 1：  [1, 0, 0, 3, 12]，slow = 1
fast 找到 3：  [1, 3, 0, 0, 12]，slow = 2
fast 找到 12： [1, 3, 12, 0, 0]，slow = 3
```

零会在每次交换时自然被带到后面，所以不需要第二阶段补零。

**为什么仍然稳定**

`fast` 从左向右依次发现非零元素，`slow` 也从左向右依次接收它们。例如发现顺序是：

```text
1 -> 3 -> 12
```

写入顺序就是：

```text
nums[0] -> nums[1] -> nums[2]
```

所有非零元素的相对顺序没有改变，因此该算法是稳定的。

**已知 `slow` 指向零时，可以不用临时变量**

根据不变量，只要 `slow < fast`，就能确定 `nums[slow] == 0`，因此可以直接写成：

```java
public void moveZeroes(int[] nums) {
    int slow = 0;

    for (int fast = 0; fast < nums.length; fast++) {
        if (nums[fast] != 0) {
            if (slow != fast) {
                nums[slow] = nums[fast];
                nums[fast] = 0;
            }
            slow++;
        }
    }
}
```

这里的 `slow != fast` 不能省略。二者指向同一个非零元素时，如果仍执行：

```java
nums[slow] = nums[fast];
nums[fast] = 0;
```

这个非零元素会被错误清零。真正的 `swap` 即使发生自交换也不会出错，但属于无效操作。

**与两阶段覆盖法比较**

两阶段覆盖法先稳定压缩非零元素，再将剩余位置补零：

```java
int slow = 0;
for (int fast = 0; fast < nums.length; fast++) {
    if (nums[fast] != 0) {
        nums[slow++] = nums[fast];
    }
}
while (slow < nums.length) {
    nums[slow++] = 0;
}
```

| 写法 | 特点 |
|---|---|
| 两阶段覆盖法 | 通用原地过滤模板更直观，最后统一填充默认值 |
| 一阶段交换法 | 一趟扫描后结果已经完整，不需要第二阶段补零 |

两者时间复杂度均为 `O(N)`，额外空间复杂度均为 `O(1)`。一趟扫描不一定意味着数组写操作更少：交换一次通常产生两次数组写入；但通过 `slow != fast` 跳过自交换后，全为非零元素时可以完全不写数组。

**Q80：每个值最多保留 K 次**

Q26只保留一次，判断条件是当前值是否等于最后一个有效值。Q80最多保留两次，判断条件推广为：

```java
slow < 2 || nums[fast] != nums[slow - 2]
```

为什么比较`slow - 2`？如果当前值等于结果中倒数第二个值，由于数组有序，结果末尾两个值必然都等于当前值，再写入就会出现第三次。

最多保留`k`次的统一模板是：

```java
int slow = 0;
for (int fast = 0; fast < nums.length; fast++) {
    if (slow < k || nums[fast] != nums[slow - k]) {
        nums[slow++] = nums[fast];
    }
}
```

关键不是死记`slow - 2`，而是明确：判断依据来自已经满足约束的压缩结果`[0, slow)`。

**Q443：一个输入分组产生多个输出**

`read`一次消费完整的一组相同字符，`write`先写字符，再按十进制逐位写入组长度：

```text
aaaaaaaaaaaa -> ['a', '1', '2']
```

区间含义为：

```text
[0, write)  已生成的压缩结果
[0, read)   已消费的原始输入
[read, n)   尚未读取的输入
```

原地向前写不会覆盖未读数据，核心依据是始终满足`write <= read`。每个非空分组至少消费一个字符，输出的字符及计数位数不会超过该组原长度。

这道题将模型从：

```text
一个输入 -> 0/1个输出
```

扩展为：

```text
一组输入 -> 1/多个输出
```

**Q1047 与 Q1209：写指针同时作为栈顶**

Q1047 删除两个相邻重复字符时，`slow` 不再只能前进：

```text
当前字符 != 栈顶：写入 chars[slow]，slow++，相当于入栈
当前字符 == 栈顶：slow--，相当于出栈
```

此时 `[0, slow)` 的精确定义是：

> 原字符串已经扫描部分完成所有相邻重复删除后的最终结果。

Q1209 是 Q1047 的进阶题，需要删除连续 `k` 个相同字符。仅保存字符不够，还要为结果栈中的每个位置保存连续次数：

```java
chars[slow] = chars[fast];
count[slow] = slow > 0 && chars[slow] == chars[slow - 1]
        ? count[slow - 1] + 1
        : 1;
slow++;

if (count[slow - 1] == k) {
    slow -= k;
}
```

删除整组字符后，`slow` 直接退回删除前的位置。后续输入会与新暴露的栈顶继续比较，所以能够自然完成连锁删除。

**Q1089：输出扩张时反向写**

Q1089中普通元素产生一个输出，0产生两个输出。此时从左向右写可能出现`write > read`，覆盖尚未读取的数据。

先统计0的数量，将结果想象成一个虚拟扩容数组：

```java
int read = n - 1;
int write = n + zeroCount - 1;
```

从后向前处理，每次都移动虚拟`write`，但只在`write < n`时真正写入原数组。这能统一处理最后一个0只能复写一部分的边界。

核心规律是：

> 压缩通常从前向后写，因为`write <= read`；扩张通常从后向前写，因为这样不会覆盖未读输入。

**Q88：两个输入流合并为一个输出流**

`nums1`尾部已有预留空间，因此从两个数组的有效末尾开始比较：

```java
int i = m - 1;
int j = n - 1;
int write = m + n - 1;
```

每次把两个未处理区间中的较大值写入`nums1[write]`。从前向后合并会覆盖`nums1`尚未读取的有效元素，从后向前则正好利用预留空间。

循环只需要保证`nums2`全部写完：

- `nums1`先耗尽：继续复制`nums2`；
- `nums2`先耗尽：`nums1`剩余元素本来就在正确位置。

**Q75：从一个有效区扩展为多个分区**

Q75不是纯粹的读写压缩，而是荷兰国旗的多边界扩展：

```text
[0, left)          全是0
[left, current)    全是1
[current, right]   未处理
(right, n)         全是2
```

遇到0，与左边界交换后`current++`；遇到1直接前进；遇到2，与右边界交换后只能`right--`，不能立即移动`current`。原因是右侧换回来的元素来自未处理区，可能是0、1或2，必须继续检查。

**双指针是更大的分类**

“快慢指针”本身范围很广，例如：

- 数组原地压缩
- 链表中点
- 链表判环
- 寻找环入口
- 删除链表倒数第 `K` 个节点

这些题虽然都可能出现 `slow/fast`，但算法模型并不相同。
