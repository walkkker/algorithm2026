# 二叉树通用技巧与题型分类

## 1. 先判断信息流动方向

拿到树题先问：当前节点需要的信息来自哪里？

### 子树向父节点汇总

如果当前答案可由：

```text
左子树Info + 右子树Info + 当前节点
```

得到，使用后序位置的底向上递归。典型题：Q104、Q543、Q124、Q236。

### 祖先向子节点传递

如果当前节点依赖：

- 根到当前节点的前缀和；
- 当前路径已访问节点；
- 剩余目标值；
- 当前深度或路径字符串；

使用自顶向下DFS参数。典型题：Q437。

信息方向选错，会导致一个函数同时承担两种语义，产生重复计算或错误组合。

## 2. DFS遍历：递归代码的位置就是访问时机

```java
void dfs(TreeNode cur) {
    if (cur == null) {
        return;
    }
    // 前序位置：进入节点
    dfs(cur.left);
    // 中序位置：左子树完成
    dfs(cur.right);
    // 后序位置：左右子树都完成
}
```

- 前序适合向下传递状态、复制或创建结构。
- 中序利用BST有序性。
- 后序适合汇总左右子树Info。

非递归中序的循环条件：

```java
while (cur != null || !stack.isEmpty()) {
    while (cur != null) {
        stack.push(cur);
        cur = cur.left;
    }
    cur = stack.pop();
    visit(cur);
    cur = cur.right;
}
```

栈中保存“左子树已经进入，但自身尚未访问”的节点。

## 3. BFS分层：层边界是额外状态

### BFS启动模板：先创建容器，再注册起点

```java
Queue<TreeNode> queue = new ArrayDeque<>();
queue.offer(root);
```

BFS初始化不是只有“创建队列”，而是两个独立动作：

1. 创建保存待处理状态的队列；
2. 把第一个待处理状态（本题为`root`）加入队列。

若遗漏第二步，队列会一直为空，主循环一次也不执行，并直接返回初始答案。这类错误不会像
空指针那样立即报错，而是产生“静默的空结果”。这个模型也适用于图BFS：创建`queue`以后，
必须把所有初始源点加入队列，算法才真正启动。

推荐使用当前队列大小冻结本层节点数：

```java
while (!queue.isEmpty()) {
    int size = queue.size();
    List<Integer> level = new ArrayList<>();
    for (int i = 0; i < size; i++) {
        TreeNode cur = queue.poll();
        level.add(cur.val);
        if (cur.left != null) queue.offer(cur.left);
        if (cur.right != null) queue.offer(cur.right);
    }
    ans.add(level);
}
```

Q199只需收集每层最后一个节点。也可以维护`curEnd/nextEnd`，但变量语义更多，初始化和更新更易错。

### curEnd/nextEnd模型

```text
curEnd：当前层最后一个节点
nextEnd：目前发现的下一层最后一个节点
```

每次把非空孩子加入队列时更新`nextEnd`。当`cur == curEnd`时，说明当前层已经消费完毕：收集
当前层结果，并执行`curEnd = nextEnd`。

Q199中孩子按“先左后右”入队，因此`nextEnd`最终指向下一层最后发现的节点；下一层处理到
这个节点时，它就是该层从左到右遍历的最后一个节点，也就是右视图需要收集的节点。

空树必须在根节点入队前返回。`LinkedList`作为Queue时技术上允许保存null，但本算法取出节点后
会访问`cur.val`，因此不能把空节点作为普通节点入队；`ArrayDeque`则明确禁止加入null。

分层结果还涉及Java引用语义：

```java
ans.add(level);
level = new ArrayList<>();
```

`ans.add(level)`保存的是对象引用。若随后执行`level.clear()`并继续复用同一个对象，ans中已经
保存的这一层也会被清空。可以选择“切换到新对象”，也可以保存快照：

```java
ans.add(new ArrayList<>(level));
level.clear();
```

## 4. 直接递归改写：保存原指针再赋值

Q226错误模式：

```java
cur.left = process(cur.right);
cur.right = process(cur.left); // cur.left已经不是原左子树
```

这不是一次“交换”，因为两条语句按顺序修改同一个对象。设原左子树为L、原右子树为R：

```text
执行前：cur.left = L，cur.right = R
第一行后：cur.left = invert(R)，cur.right = R
第二行读取cur.left时，读到的是invert(R)，不是L
结果：L失去入口，R还可能被重复处理并被两个字段同时引用
```

正确：

```java
TreeNode oldLeft = cur.left;
TreeNode oldRight = cur.right;
cur.left = process(oldRight);
cur.right = process(oldLeft);
```

也可以先递归取得两个返回值，再统一交换：

```java
TreeNode newLeft = process(cur.left);
TreeNode newRight = process(cur.right);
cur.left = newRight;
cur.right = newLeft;
```

通用原则：

```text
等号左边的指针将被覆盖；
如果后续仍要访问其原值，必须先保存到独立引用。
```

更准确地说，某条赋值语句的右侧会先基于当时状态求值，然后结果写入左侧字段；下一条语句看到
的是写入后的新状态。不要把多条赋值语句想象成数学公式中的同时成立关系。

适用题目：Q226、Q114、Morris遍历以及所有树结构原地改写。

## 5. 双节点递归：比较关系决定递归配对

Q101不是分别判断左右子树自身对称，而是判断两棵子树互为镜像：

```java
boolean mirror(TreeNode a, TreeNode b) {
    if (a == null || b == null) return a == b;
    return a.val == b.val
            && mirror(a.left, b.right)
            && mirror(a.right, b.left);
}
```

镜像关系：

```text
外侧：a.left  <-> b.right
内侧：a.right <-> b.left
```

这类题的关键是递归参数不再只有一个节点，而是“一对必须满足某种关系的节点”。

## 6. Info递归：字段必须是接口契约

以Q124为例：

```text
maxDown：必须从cur开始，只能向下一侧延伸，可交给父节点。
maxPath：当前子树中的完整答案，可以连接左右两侧，不能再交给父节点延伸。
```

```java
int maxDown = cur.val + Math.max(0, Math.max(left.maxDown, right.maxDown));
int throughCur = cur.val + Math.max(0, left.maxDown) + Math.max(0, right.maxDown);
int maxPath = Math.max(throughCur, Math.max(left.maxPath, right.maxPath));
```

### 必问五件事

1. 状态是否必须包含当前节点？
2. 是否允许同时连接左右孩子？
3. 能否继续交给父节点？
4. 空树返回值是什么？
5. 单位是什么？

完整答案通常不能继续向父节点延伸，因为父节点继续连接后可能形成三叉分支。

## 7. 高度、直径和路径：区分“贡献”与“答案”

Q543：

```text
向父节点贡献：当前子树高度，只能选择更高的一侧。
当前节点形成答案：leftHeight + rightHeight。
子树最终答案：max(左答案, 右答案, 当前形成答案)。
```

若空树高度为0、叶子高度为1，则：

```java
int heightByNodes = Math.max(left.heightByNodes, right.heightByNodes) + 1;
int throughCurEdges = left.heightByNodes + right.heightByNodes;
```

这样完整答案直接使用边数，不必最后凭感觉减1。

## 8. 最近公共祖先：孩子答案优先传播

Info定义：

```text
containsP：当前子树是否包含p
containsQ：当前子树是否包含q
ancestor：当前子树是否已经找到最近公共祖先
```

判断优先级：

```text
左子树已有ancestor -> 直接传播
右子树已有ancestor -> 直接传播
当前子树第一次同时包含p和q -> 当前节点成为ancestor
否则没有答案
```

这比枚举`p/q`位于左右或当前节点的所有组合更稳定。

## 9. 路径前缀和：进入登记，离开撤销

Q437维护当前根路径上的前缀和频次：

```java
map.put(0L, 1);

long sum = preSum + cur.val;
int ans = map.getOrDefault(sum - target, 0);
map.put(sum, map.getOrDefault(sum, 0) + 1);
ans += dfs(cur.left, sum) + dfs(cur.right, sum);
map.put(sum, map.get(sum) - 1);
if (map.get(sum) == 0) {
    map.remove(sum);
}
```

不变量：Map只包含**当前递归路径**上的前缀和，不包含已经完成的兄弟子树。离开节点时不回溯会让不同分支错误拼接。

前缀和必须使用`long`，因为路径累加可能超出`int`。

## 10. BST：有序性可以转化为遍历或边界

### 中序严格递增

Q98：中序序列必须满足：

```text
previous < current
```

不能使用`<=`允许重复值。

### 上下界递归

```java
boolean validate(TreeNode cur, long lower, long upper) {
    if (cur == null) return true;
    if (cur.val <= lower || cur.val >= upper) return false;
    return validate(cur.left, lower, cur.val)
            && validate(cur.right, cur.val, upper);
}
```

使用`long`边界避免节点值恰好为`Integer.MIN_VALUE/MAX_VALUE`时无法表达开放区间。

### 第K小

静态BST：中序访问到第K个节点即可，时间`O(H + K)`，栈空间`O(H)`。

频繁插入删除和查询：每个节点维护子树`size`，根据左子树大小决定向左、命中或向右。这与SBT的
`getIndex`完全同构。

## 11. 数组区间建树

Q108：

```text
mid作为根；[l,mid-1]构建左子树；[mid+1,r]构建右子树。
```

Q105：前序首元素是根；根在中序中的位置决定左子树长度：

```text
leftSize = rootIndexInInorder - inorderLeft
```

然后用长度同步切分前序和中序区间。每层线性查找根位置最坏`O(N^2)`；先建立
`value -> inorderIndex`的HashMap可降为`O(N)`。

数组递归没有节点自带的`null`边界，因此参数必须明确携带`l/r`范围。

## 12. Q114原地展开：改变后续处理顺序

当前节点有左子树时：

1. 找到左子树最右节点`predecessor`。
2. `predecessor.right = cur.right`，保存原右子树的后续访问顺序。
3. `cur.right = cur.left`，让前序中的左子树成为下一段。
4. `cur.left = null`。
5. `cur = cur.right`继续处理。

它不是要求左子树已经整体展开，而是先把前序遍历的后继顺序改造成right链，再逐节点继续处理。

### 为什么额外空间是O(1)

原地版本不使用递归、系统栈、显式Stack、Queue、数组或集合，只保留固定数量的节点引用：

```java
TreeNode cur;
TreeNode leftRightMost;
```

局部引用数量不会随`N`或树高`H`增长，所以辅助空间为`O(1)`。O(1)不是“不允许任何额外变量”，
而是额外变量数量是常数。输入树及原地修改后得到的right链不计入辅助空间。

### 微观重连与宏观结果

微观上，对每个存在左子树的节点`cur`执行：

```text
左子树右边界.right = 原cur.right
cur.right = 原cur.left
cur.left = null
cur = cur.right
```

这等价于把左子树插入`cur`与原右子树之间：

```text
cur -> 左子树 -> 原右子树
```

宏观上，每个节点都执行同一规则，最终所有`left`都被清空，所有节点只通过`right`连接；由于每轮
都安排“当前节点后先处理左子树，再处理原右子树”，最终right链就是整棵树的前序遍历。

注意，`leftRightMost`更准确的含义是**当前结构中的左子树右边界节点**。它不一定已经是完整
左子树最终前序链的尾节点；后续沿right走到相关节点时，算法还会继续搬移其中尚未处理的左子树，
从而把原右子树继续向后推，最终仍保证完整左子树在原右子树之前。

## 13. Q297序列化与反序列化：协议必须对称

推荐使用前序遍历并显式记录空节点：

```text
根 -> 左 -> 右
空节点写作#
```

序列化负责按照协议写token；反序列化必须按照完全相同的顺序消费token：

```java
String token = tokens[index++];
if ("#".equals(token)) {
    return null;
}
TreeNode cur = new TreeNode(Integer.parseInt(token));
cur.left = build(tokens);
cur.right = build(tokens);
return cur;
```

空节点标记不能省略，因为只有节点值不能唯一确定树结构。`#`同时承担两项职责：记录缺失孩子，
以及告诉反序列化递归“当前子树在这里结束”。

本题与建树题的统一递归契约是：

```text
根据当前输入创建一棵完整子树，并返回新子树根节点。
```

边界来源不同：

```text
Q108：单数组[l,r]区间
Q105：前序和中序的双数组区间
Q297：遍历协议中的#空节点标记
```

## 14. 通用复查清单

```text
[ ] 函数返回的是节点、单链贡献、子树答案还是多个Info字段？
[ ] 返回状态是否必须包含cur？
[ ] 状态能否继续交给父节点连接？
[ ] 左右孩子可以同时选择吗？
[ ] 空树返回值符合定义吗？
[ ] 节点数、边数、层数统一吗？
[ ] 本题信息是向上汇总还是向下传递？
[ ] 修改left/right前保存原指针了吗？
[ ] 依赖当前路径的Map/Set在离开节点时回溯了吗？
[ ] BST比较是严格不等还是允许重复？
```
