# 二叉树递归套路：易犯错误注意事项

## 错误汇总

| 题目 | 状态定义或错误点 | 错误后果 | 正确处理 |
| --- | --- | --- | --- |
| Q543 二叉树的直径 | `height`、`maxDistance`统计的是节点数，但题目要求边数 | 最终结果相差1；如果定义混用，中间公式也会出错 | 从头统一“节点数”或“边数”口径，不要在递归中混用 |
| Q124 二叉树中的最大路径和 | 把“已经连接左右子树的完整路径”继续交给父节点使用 | 在某个节点形成三个方向的分叉，结果不是合法路径 | 分开维护“可向父节点延伸的单链”和“子树内完整答案” |
| Q236 二叉树的最近公共祖先 | `ancestor`判断枚举了四组位置关系 | 原逻辑正确，但条件冗长，面试时容易遗漏分支 | 子树答案优先；否则使用`containsP && containsQ`判断当前节点 |
| Q437 路径总和 III | `process(cur, target)`同时表示“子树内任意路径”和“必须从cur开始的路径” | 统计不连续路径、重复计数；基于正数的剪枝也会漏解 | 拆分函数语义，或使用前缀和与HashMap进行从根到当前节点的状态维护 |

## 核心结论

二叉树递归套路本身通常不难，主要错误来自 **`Info`字段或者递归函数的语义在使用过程中发生了变化**。

定义`Info`时认为某字段表示A，父节点合并时却把它当成B使用。代码的类型仍然正确，编译器无法发现这种错误，因此必须人为维护严格的“状态契约”。

每个`Info`字段至少需要明确以下内容：

| 必须明确的问题 | 典型选项 |
| --- | --- |
| 信息属于谁 | 当前节点、当前子树、从整棵树根到当前节点 |
| 是否必须包含当前节点 | 必须包含、可以不包含 |
| 路径从哪里开始 | 必须从当前节点开始、当前子树内任意位置 |
| 能否继续交给父节点连接 | 可以继续延伸、已经是完整答案 |
| 允许选择几个孩子 | 只能选择一侧、可以同时连接左右两侧 |
| 统计单位是什么 | 节点数、边数、节点值之和 |
| 空树代表什么 | `0`、`false`、`Integer.MIN_VALUE`、`Integer.MAX_VALUE` |
| 信息流动方向 | 子树向父节点汇总、父节点向子节点传递 |

只要其中一项没有确定，递归公式就可能产生歧义。

## Q543：节点数与边数不能混用

相关代码：[Q543_DiameterOfBinaryTree.java](./Q543_DiameterOfBinaryTree.java)

当前实现中：

```java
height = Math.max(left.height, right.height) + 1;
p1 = left.height + right.height + 1;
```

这里的`height`和`p1`都使用 **节点数量**：

- 空树高度为`0`。
- 叶子节点高度为`1`。
- 经过当前节点的最长路径节点数为`left.height + right.height + 1`。

但是题目要求返回 **边的数量**，所以非空树最终需要：

```java
return maxDistance - 1;
```

这个写法可以通过，但要牢记当前`Info`内部全部使用节点数。另一种写法是在递归内部直接维护边数：

```java
height = Math.max(left.height, right.height) + 1; // height仍表示节点高度
throughCurEdges = left.height + right.height;
```

此时最终答案不再需要减1。

### 易错本质

`maxDistance`这个名字没有说明单位。父节点可能把“节点数”当成“边数”继续计算。

建议使用更明确的命名：

```java
heightByNodes
diameterByEdges
```

至少要在`Info`字段旁写明单位。

## Q124：完整路径不能继续向父节点延伸

相关代码：[Q124_BinaryTreeMaximumPathSum.java](./Q124_BinaryTreeMaximumPathSum.java)

错误版本中的`yes`表示：

> 当前子树中，必须经过当前节点，并且可以同时连接左右子树的完整路径。

原错误计算：

```java
yes = Math.max(left.yes, 0)
        + Math.max(right.yes, 0)
        + cur.val;
```

问题不在于“同时连接左右子树”，而在于使用了`left.yes`和`right.yes`。孩子的`yes`自身可能已经连接了两个方向，父节点再连接它，就可能产生分叉。

例如：

```text
    1
   /
  2
 / \
3   4
```

节点2处的完整路径是`3-2-4`。它不能再连接父节点1，否则节点2同时连接1、3、4三个方向，不再是一条路径。

### 正确状态

```java
line
```

必须表示：

> 从当前节点出发，只能向左或者向右选择一侧的最大路径和，可以继续交给父节点。

```java
line = cur.val + Math.max(
        0,
        Math.max(left.line, right.line)
);
```

子树内的完整答案可以同时连接左右单链：

```java
throughCur = cur.val
        + Math.max(0, left.line)
        + Math.max(0, right.line);

maxPathSum = Math.max(
        throughCur,
        Math.max(left.maxPathSum, right.maxPathSum)
);
```

### 易错本质

混淆了两种不同权限的信息：

| 状态 | 可以连接左右两侧 | 可以继续交给父节点 |
| --- | --- | --- |
| `line` | 否，只能选一侧 | 是 |
| `maxPathSum` | 可以 | 否，它是当前子树的完整答案 |

判断路径类`Info`是否正确，必须问一句：

> 这个返回值交给父节点后，父节点继续连接是否合法？

## Q236：先传播已有答案，再判断当前节点

相关代码：[Q236_LowestCommonAncestorOfABinaryTree.java](./Q236_LowestCommonAncestorOfABinaryTree.java)

本题的三个状态定义是清晰的：

```java
ancestor  // 当前子树已经找到的最近公共祖先
containsA // 当前子树是否包含p
containsB // 当前子树是否包含q
```

最初的代码枚举了四种情况：

- `p`在左、`q`在右。
- `q`在左、`p`在右。
- 当前节点是`p`，`q`在某棵子树。
- 当前节点是`q`，`p`在某棵子树。

这些判断逻辑正确，但存在重复。更稳定的判断顺序是：

```java
if (left.ancestor != null) {
    ancestor = left.ancestor;
} else if (right.ancestor != null) {
    ancestor = right.ancestor;
} else if (containsA && containsB) {
    ancestor = cur;
} else {
    ancestor = null;
}
```

前两个分支非常关键，它们建立了下面的不变量：

> 如果`p、q`完整位于同一棵子树，该子树已经返回最近公共祖先。

因此，左右子树都没有现成答案，但当前子树同时包含`p、q`时，当前节点就是二者第一次汇合的位置。

### 易错本质

没有先确定“子树已有答案是否应直接传播”，就开始枚举节点位置关系，导致条件迅速膨胀。

对于“子树内已经形成最终答案”的状态，通常使用以下优先级：

```text
孩子已有最终答案
    > 当前节点新形成答案
    > 当前子树暂时没有答案
```

同时，字段命名建议直接对应题目：

```java
containsP
containsQ
```

比`containsA/containsB`更不容易在合并时写反。

## Q437：不是所有问题都适合纯底向上的Info

相关代码：[Q437_PathSumIII.java](./Q437_PathSumIII.java)

错误版本试图让：

```java
process(cur, targetSum)
```

同时完成两件事：

1. 统计当前子树任意位置开始的合法路径。
2. 统计必须从当前节点开始的合法路径。

这两个递归函数的定义不同，不能混用。

例如，为了统计“必须经过当前节点”的路径而调用：

```java
process(cur.left, targetSum - cur.val)
```

如果`process`会统计左子树任意位置开始的路径，那么它返回的路径可能根本不经过`cur.left`，也就无法与`cur`连接。

此外还有两个错误：

- `cur.val > targetSum`不能剪枝，因为节点值允许为负数，后续路径和可能重新降低。
- `cur.val == targetSum`时不能立即停止向下统计，后面可能存在和为`0`的连续路径。

### 正确选择

可以拆成两个语义严格不同的函数：

```java
pathSum(cur, target)       // 当前子树任意位置开始的答案
countFrom(cur, remaining)  // 必须从cur开始的答案
```

这种方法最坏为`O(N^2)`。

更优方法是前缀和加HashMap：

```text
父节点向子节点传递“根到当前路径”的前缀和状态
```

这是一个 **自顶向下、依赖祖先路径上下文** 的问题，不是典型的“左右子树各返回固定Info，父节点合并”问题。

### 易错本质

把“从当前节点开始”和“当前子树任意位置开始”当成了同一个函数定义。

## 最常见的语义歧义

### 1. 子树全局答案与可向父节点延伸的信息

典型题：Q124。

```text
maxPathSum：当前子树任意合法路径的最大值
maxDown：必须从当前节点开始、可以向父节点延伸的最大值
```

全局答案通常不能直接交给父节点继续组合。

### 2. 必须经过当前节点与可以不经过当前节点

典型公式：

```java
throughCur = 使用当前节点形成的答案;
best = Math.max(
        throughCur,
        Math.max(left.best, right.best)
);
```

如果字段名称只是`max`，很容易忘记它是否必须经过当前节点。

### 3. 从当前节点开始与当前子树任意位置开始

典型题：Q437。

这两个函数的递归入口相同，但语义完全不同。建议直接拆成不同的方法名，禁止复用。

### 4. 节点数与边数

典型题：Q543。

必须在字段名或注释中写清单位。不要依赖最后“凭感觉减1”。

### 5. 空树的返回值

空树返回值不是固定的`0`，而是由字段语义决定：

| 状态 | 常见空树返回值 |
| --- | --- |
| 节点数量、高度 | `0` |
| 是否包含目标节点 | `false` |
| 最大路径和且路径不能为空 | `Integer.MIN_VALUE` |
| 可选贡献，允许不选择该子树 | 通常在父节点使用`Math.max(value, 0)` |
| BST最小值 | `Integer.MAX_VALUE`或额外布尔状态 |
| BST最大值 | `Integer.MIN_VALUE`或额外布尔状态 |

特别注意：不能因为最大值题目习惯返回`0`，就让全负数二叉树错误地选择“空路径”。

### 6. 子树汇总状态与祖先上下文

如果父节点答案能够完全由：

```text
左子树Info + 右子树Info + 当前节点
```

推导出来，适合二叉树递归套路。

如果当前节点计算依赖：

- 根到当前节点的路径和；
- 祖先节点集合；
- 当前剩余目标值；
- 路径上字符或频次；

通常需要父节点向子节点传递参数，属于自顶向下递归，不能强行塞进固定的底向上`Info`。

## 写代码前的状态契约

建议在定义`Info`之前，先写出类似下面的注释：

```java
/*
Info属于：以cur为根的整棵子树。

maxDownPathSum：
1. 必须包含cur；
2. 从cur开始向下；
3. 左右孩子最多选择一侧；
4. 可以继续交给父节点连接；
5. 空树返回Integer.MIN_VALUE。

maxPathSum：
1. 当前子树内任意位置开始；
2. 不一定包含cur；
3. 是完整答案，不能继续交给父节点连接；
4. 路径不能为空；
5. 空树返回Integer.MIN_VALUE。
*/
```

这段注释不是为了形式，而是递归公式的接口契约。

## 固定检查流程

写完`Info`递归后，按以下顺序检查：

1. **逐字段复述定义**：字段属于当前节点还是当前子树？
2. **检查包含关系**：是否必须包含当前节点？
3. **检查连接权限**：这个值能否继续交给父节点？
4. **检查路径形状**：只能选择一个孩子，还是可以同时连接左右孩子？
5. **检查空树返回值**：是否会错误选择空路径？是否会溢出？
6. **检查统计单位**：节点数、边数、层数是否统一？
7. **检查信息方向**：本题是底向上汇总，还是需要祖先状态向下传递？
8. **检查答案传播优先级**：孩子已有答案时，是否应该直接向上传播？
9. **检查命名**：`line`、`yes`、`no`是否过于抽象，能否换成准确业务含义？
10. **检查复杂度**：是否在每个节点内部又完整递归或遍历了一遍子树？

## 最小反例

至少使用以下结构验证状态定义：

```text
1. 单节点，且节点值为负数
2. 只有左孩子或只有右孩子的单链
3. 当前节点同时拥有左右孩子
4. 最终答案完全位于某一棵子树
5. 当前节点本身就是目标节点
6. 节点值包含正数、0和负数
```

其中“当前节点同时拥有左右孩子，再连接一个父节点”是检查路径状态能否向父节点延伸的最有效反例。

## 面试记忆结论

```text
先定义Info，再写递归。
字段定义必须包含：范围、是否含头、能否上交、单位、空树值。
完整答案不能随便继续向上连接。
孩子已有答案，通常优先向上传播。
依赖祖先路径的题，不要强行使用纯底向上的Info。
```
