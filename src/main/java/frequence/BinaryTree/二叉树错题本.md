## 错误汇总

| 题目 | 错误或遗漏 | 后果 | 稳定修正 |
| --- | --- | --- | --- |
| Q94 中序遍历 | 非递归循环只判断`cur != null` | cur为空时提前结束，遗漏栈内节点 | 条件为`cur != null || !stack.isEmpty()` |
| Q101 对称二叉树 | 左对左、右对右 | 判断的是结构相同，不是轴对称 | 外侧配对、内侧配对：`left-right`、`right-left` |
| Q102 层序遍历 | 空树直接入队；`nextEnd`未初始化 | NPE或编译错误 | 空树先返回；优先使用`levelSize`模型 |
| Q102 层序遍历 | `ans.add(layer)`后对同一个layer执行clear | ans保存的是同一个对象引用，已收集层也被清空 | 切换为新ArrayList，或add时保存副本 |
| Q105 前中序建树 | 每层线性扫描中序找根 | 斜树退化为`O(N^2)` | 预处理HashMap，根位置查询`O(1)` |
| Q105 前中序建树 | 四个区间边界靠猜 | 子树长度错位 | 先计算`leftSize`，再统一推导两个遍历区间 |
| Q114 展开链表 | 无条件重连左子树 | `cur.left == null`时断开原右子树 | 只有存在左子树时执行重连 |
| Q114 展开链表 | 递归无条件返回`rightTail` | 右子树为空时返回null，父节点无法连接 | 返回最右侧非空尾：右尾、左尾、当前节点 |
| Q114 展开链表 | 原地重连后遗漏`cur.left = null` | 节点仍保留left引用，结果不是题目要求的单链表 | `cur.right`接住左子树后立即清空`cur.left` |
| Q124 最大路径和 | 把连接左右两侧的完整路径继续交给父节点 | 形成三个方向分叉，不再是合法路径 | 分离`maxDown`和`maxPath` |
| Q199 右视图 | 层尾更新与结果收集混杂 | 漏层或层边界错位 | 每层冻结`queue.size()`，收集`i == size-1` |
| Q199 右视图 | 创建Queue后忘记加入`root` | 队列始终为空，循环零次并静默返回空结果 | 空树检查后立即执行`queue.offer(root)` |
| Q226 翻转二叉树 | 先覆盖`cur.left`，再把它当原左子树使用 | 原左子树丢失 | 保存`oldLeft/oldRight`后再递归赋值 |
| Q236 最近公共祖先 | 枚举四组p/q位置关系 | 逻辑虽可正确，但分支长且容易漏 | 子树答案优先；否则`containsP && containsQ` |
| Q437 路径总和III | 未把当前前缀和频次`+1` | 后代无法匹配当前前缀，统计偏小 | 递归子树前执行`map[sum]++` |
| Q437 路径总和III | 离开节点不回溯Map | 不同分支错误拼接为一条路径 | 子树完成后`map[sum]--`，为0时删除 |
| Q437 路径总和III | 使用`int`前缀和 | 长路径累加溢出 | `long sum`和`HashMap<Long,Integer>` |
| Q437 路径总和III | 同一Solution对象复用Map未清空 | 上一次调用状态污染下一次 | 入口处`map.clear()`并重新放入`0L -> 1` |
| Q543 直径 | Info中使用节点数，题目返回边数 | 结果差1 | 从状态定义开始统一单位，或明确最终减1 |
| Q98 验证BST | 只验证父子局部大小关系 | 深层节点可能违反祖先边界 | 中序严格递增或递归传递上下界 |

## 1. 递归最常见错误：定义在使用中漂移

例如Q124把`yes`最初理解为“经过当前节点的完整路径”，父节点又把它理解成“可以继续向上连接的单链”。
类型都是`int`，编译器无法发现语义变化。

预防方式：字段定义必须写全：

```text
属于谁；
是否包含cur；
能否向父节点延伸；
能选几个孩子；
单位；
空树值。
```

## 2. Q101：轴对称不是左右子树分别相同

错误：

```text
left.left  对 right.left
left.right 对 right.right
```

正确：

```text
left.left  对 right.right
left.right 对 right.left
```

最小反例：根的左孩子只有左节点，根的右孩子只有右节点。这是对称树，但同方向比较会判错。

## 3. Q102/Q199：识别层边界后再收集业务结果

### 2026-09-03：创建队列不等于启动BFS

Q199复写时遗漏了`queue.add(root)`。BFS启动必须完整执行：

```text
创建frontier容器 -> 注册初始状态 -> 循环消费并扩展后继状态
```

只创建空队列时，`while (!queue.isEmpty())`从第一次判断就为false，算法不会访问任何节点，
并直接返回空List。该错误不会抛异常，必须通过检查“初始状态是否已经进入frontier”主动预防。

使用`curEnd/nextEnd`可以工作，但需要维护更多状态。更稳定的模板是：

```java
int size = queue.size();
for (int i = 0; i < size; i++) {
    TreeNode cur = queue.poll();
    if (i == size - 1) {
        // 当前层最后一个节点
    }
}
```

### 2026-09-02：层结果必须固化

下面的组合是错误的：

```java
ans.add(layer);
layer.clear();
```

`List<List<Integer>>`保存的是内层List对象的引用，`clear()`修改的仍是ans中已经保存的同一个
对象。正确做法有两种：

```java
ans.add(layer);
layer = new ArrayList<>();
```

或者：

```java
ans.add(new ArrayList<>(layer));
layer.clear();
```

空树也必须在入队前返回。不要笼统记成“所有Queue都不能存null”：LinkedList允许null，
ArrayDeque不允许null；但二叉树BFS通常不应把null当普通节点入队，否则访问节点字段时会NPE。

先建立“本层节点数量”这个不变量，再按题目要求收集整层或最后一个节点。

## 4. Q105：区间参数代表长度范围，不是凭直觉切分

根为`preorder[preL]`，在中序中的位置为`inRoot`：

```text
leftSize = inRoot - inL
```

四个新区间：

```text
左前序：[preL+1, preL+leftSize]
右前序：[preL+leftSize+1, preR]
左中序：[inL, inRoot-1]
右中序：[inRoot+1, inR]
```

先写长度，再写边界，可以显著减少off-by-one。

## 5. Q114：改指针前必须区分原结构与目标结构

### 2026-09-03：清空left属于结构变换，不是可选收尾

原地版本完成下面两步后：

```java
des.right = cur.right;
cur.right = cur.left;
```

原左子树已经可以通过`cur.right`访问，但`cur.left`仍然保留着旧引用。此时不能认为转换已经完成，
必须继续执行：

```java
cur.left = null;
```

循环不变量应写成：`cur`之前的节点已经构成只含right指针的前序链，所有这些节点的left均为
null。遗漏清空left虽然通常不会丢节点，却违反了题目要求，也破坏了“已处理部分已经定型”的定义。

另一个文字层面的易错点是：左子树最右节点要接的是`cur.right`（原右子树），不是
`cur.left`。前者保存尚未处理的右子树，后者会错误地重新指回左子树。

### 递归版

尾节点返回规则：

```text
rightTail非空 -> rightTail
否则leftTail非空 -> leftTail
否则 -> cur
```

不能无条件返回`rightTail`。

### 原地版

只有`cur.left != null`时才需要重连。顺序必须是：

```text
找到左子树最右节点
最右节点接原右子树
右指针接原左子树
左指针清空
```

### 2026-09-02：不能只背三次赋值

稳定理解分为两个尺度：

```text
微观：把cur的左子树插入cur与原右子树之间，然后cur沿新的right继续。
宏观：每个节点都执行相同操作，最终所有left为空，right链就是前序遍历。
```

`leftRightMost`是当前结构中的左子树右边界节点，不保证此刻已经是完整左子树前序序列的最后
节点。如果其内部仍有左子树，后续处理会继续把原右子树向后调整。

指针顺序不能改变：必须先让右边界接住原右子树，再覆盖`cur.right`。否则原右子树入口丢失。

空间复杂度`O(1)`表示只使用固定数量的节点引用；不使用系统递归栈、Stack、Queue或随N增长的
容器。它不表示连`cur/leftRightMost`这样的局部变量都不能使用。

## 6. Q124：完整答案没有“继续延伸权限”

节点可以连接父、左、右三条边。如果孩子状态已经同时连接其左右两侧，父节点再连接它，就形成三叉分支。

因此：

```text
maxDown：只选一个孩子，可以上交；
maxPath：可以同时连接两个孩子，是完整答案，不能上交。
```

最有效反例：让某个孩子同时拥有左右子树，再给它增加一个父节点。

## 7. Q226：赋值左侧会立刻覆盖对象字段

错误：

```java
cur.left = process(cur.right);
cur.right = process(cur.left);
```

第二行读取的`cur.left`已经是第一行的新值。正确做法是通过额外引用冻结原入口。这里多写两个变量不是冗余，
而是在隔离“原结构”和“新结构”。

### 2026-09-02：两行赋值不是同时交换

假设执行前：

```text
cur.left = L
cur.right = R
```

逐行执行错误代码：

```text
1. cur.left = process(cur.right)
   此时cur.left已经变成invert(R)，L失去字段入口。

2. cur.right = process(cur.left)
   此时读取的是新cur.left，也就是invert(R)，不是原左子树L。
```

致命点是**覆盖以后仍把对象字段当作旧值使用**。正确修正：

```java
TreeNode oldLeft = cur.left;
TreeNode oldRight = cur.right;
cur.left = process(oldRight);
cur.right = process(oldLeft);
```

复查所有指针改写代码时都问一句：

```text
这个字段被赋值以后，后面的代码还需要它原来指向的结构吗？
```

如果答案是“需要”，必须在第一条赋值之前冻结原引用。这个原则同样适用于链表反转、局部重连、
树旋转和数组原地覆盖。

## 8. Q437：Map是当前路径状态，不是整棵树状态

完整时序：

```text
计算当前sum
查询sum-target出现次数
登记当前sum
递归左右子树
撤销当前sum
```

登记时漏掉`+1`：

```java
map.put(sum, map.getOrDefault(sum, 0));
```

会让新key永远记录为0。正确：

```java
map.put(sum, map.getOrDefault(sum, 0) + 1);
```

回溯的目的不是恢复数值变量`sum`，而是让共享Map重新只表示父节点路径。

## 9. Q543：单位必须从base case开始统一

若：

```text
空树高度 = 0
叶子高度 = 1
```

则高度单位是节点数，经过当前节点的直径边数为：

```text
leftHeight + rightHeight
```

不要让字段名只叫`distance`而不写单位。推荐`heightByNodes`、`diameterByEdges`。

## 10. Q98/Q230：BST有序性必须是全局约束

BST不是只要求：

```text
cur.left < cur < cur.right
```

左子树所有节点都必须小于cur，右子树所有节点都必须大于cur。中序遍历将这个全局结构约束转化为
一维严格递增序列，是最容易验证的做法。

## 最小反例集合

```text
空树
单节点负数树
只有左孩子或只有右孩子的单链
当前节点同时有左右孩子
最终答案完全位于某一棵子树
孩子已经形成完整路径，再给它增加父节点
Integer.MIN_VALUE / Integer.MAX_VALUE作为BST节点
不同分支具有相同前缀和
```

## 错误预防口诀

```text
先写递归契约，再写左右递归。
完整答案不能随便继续向上连接。
改left/right前先保存原指针。
路径共享状态进入时登记，离开时撤销。
BST看全局边界，不只看父子。
节点数、边数、层数从base case开始统一。
```
