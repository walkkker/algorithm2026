## Q94 BinaryTreeInorderTraversal 【Hot 100】

### 核心思想与题目要求

中序遍历的访问顺序固定为左子树、当前节点、右子树。递归写法直接按照这个语义组织代码。

非递归写法使用栈模拟递归调用：只要`cur != null`就持续压入左链；走到空节点后弹栈并访问，随后转向该节点的右子树。循环条件必须是`cur != null || !stack.isEmpty()`，否则可能遗漏栈中节点。

栈内保存的是左子树已经进入、但自身尚未访问的节点。每个节点入栈和出栈各一次，时间复杂度为`O(N)`，递归或显式栈空间复杂度为`O(H)`。二叉搜索树的中序遍历结果有序。如要求严格`O(1)`额外空间，可进一步使用Morris遍历。

### 算法流程与正确性依据

1. 根据题意确定输入中可利用的单调性、值域、结构关系或可复用子问题。
2. 使用本专题模型组织状态：base case必须符合返回值定义；递归前保存仍需访问的指针；全局答案与向上返回值不能混淆。
3. 每次更新后维持上述定义；只有在不变量仍成立时才移动指针、覆盖数据或进入下一状态。
4. 最终从定义直接读取答案，而不是根据样例猜测返回位置。

正确性的关键是：每一步只排除已经证明不可能成为答案的选择，或者完整枚举状态定义允许的所有前驱，因此不会漏解。

```java
package frequence.BinaryTree;

import java.util.*;

/**
 * 94. 二叉树的中序遍历
 *
 * <p>给定一个二叉树的根节点 {@code root}，返回它的中序遍历结果。
 *
 *
 * 实现递归和非递归版本
 */
public class Q94_BinaryTreeInorderTraversal {

    public List<Integer> inorderTraversal(TreeNode root) {
        List<Integer> ans = new ArrayList<>();
        process(root, ans);
        return ans;
    }

    private void process(TreeNode head, List<Integer> ans) {
        if (head == null) {
            return;
        }
        process(head.left, ans);
        ans.add(head.val);
        process(head.right, ans);
    }

    public List<Integer> inorderTraversalUnRecursive(TreeNode root) {
        Stack<TreeNode> stack = new Stack<>();
        TreeNode cur = root;
        List<Integer> ans = new ArrayList<>();
        while (cur != null || !stack.isEmpty()) {
            if (cur != null) {
                stack.push(cur);
                cur = cur.left;
            } else {
                cur = stack.pop();
                ans.add(cur.val);
                cur = cur.right;
            }
        }
        return ans;
    }


    }
```

```java
 * 104. 二叉树的最大深度

public class Q104_MaximumDepthOfBinaryTree {

    public int process(TreeNode cur) {

            return 0;
```

## Q230 KthSmallestElementInABST 【Hot 100】

### 核心思想与题目要求

230. 二叉搜索树中第 K 小的元素
给定一棵二叉搜索树的根节点 `root` 和一个整数 `k`，
返回该二叉搜索树中第 `k` 小的节点值。
**普通问题答案：**
BST的中序遍历严格升序，迭代中序遍历弹出的第k个节点就是第k小。
找到后立即返回，时间复杂度为 `O(H + k)`，最坏为 `O(N)`；
显式栈空间为 `O(H)`。
**进阶问题：**
如果二叉搜索树经常被修改（插入/删除），并且需要频繁查询第k小，应该如何优化？
**进阶答案：**
将BST改造成维护子树节点数量size的顺序统计树（Order Statistic Tree）。
每个节点额外维护：
size = size(left) + size(right) + 1
插入、删除以及旋转完成后必须调用 `pull(cur)` 更新size；所有修改都必须经过
这棵树提供的API，否则size会失效。
查询第k小时，令 `leftSize = size(cur.left)`：
k &lt;= leftSize      ：第k小在左子树
k == leftSize + 1 ：当前节点就是第k小
k &gt; leftSize + 1  ：进入右子树，并令k = k - leftSize - 1
每次可以跳过一整棵子树，查询复杂度由遍历节点数降为 `O(H)`。
为了防止普通BST退化成链表，需要使用带size增强属性的平衡搜索二叉树，例如
SBT、AVL、红黑树或Treap。平衡后插入、删除和查询第k小均为 `O(log N)`。

Q230的BST不允许重复值，只需要 `SBTSet<Integer>`；如果SBT的
`getIndex(index)` 使用0-based下标，则：

`(value, id)` 复合键区分重复元素。

```java
                    stack.push(cur);
                    cur = cur.left;

                    cur = stack.pop();
                    if (--k == 0) {

                    cur = cur.right;
```

```java
    public int pathSum(TreeNode root, int targetSum) {
        map.put(0, 1);

    public int process(TreeNode cur, int preSum, int targetSum) {

            map.remove(preSum);
        }
        return ans;
    }
```
