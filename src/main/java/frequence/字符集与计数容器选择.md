# 字符集与计数容器选择

## 1. 快速结论

字符串算法经常需要记录字符的词频、存在性或最后出现位置。容器选择首先取决于题目的字符范围：

| 题目字符范围 | 推荐容器 | 下标方式 |
|---|---|---|
| 仅小写字母 `a-z` | `int[26]` | `c - 'a'` |
| 仅大写字母 `A-Z` | `int[26]` | `c - 'A'` |
| 大小写字母、数字、空格、英文符号 | `int[128]` | `count[c]` |
| 任意 Java `char` | `int[65536]` 或 `HashMap<Character, Integer>` | `count[c]` 或 Map |
| 完整 Unicode code point | `HashMap<Integer, Integer>` | 配合 `s.codePoints()` |

选择原则：

> 字符范围小且固定时优先使用数组直接寻址；字符范围大、不确定或稀疏时使用 HashMap。

## 2. 标准 ASCII

标准 ASCII 一共有 128 个编码：

```text
0 ~ 127
```

常用范围：

| 字符 | ASCII 编码 |
|---|---:|
| 空格 | `32` |
| 数字 `0-9` | `48-57` |
| 大写字母 `A-Z` | `65-90` |
| 小写字母 `a-z` | `97-122` |
| 常见英文符号 | 主要分布在 `33-47、58-64、91-96、123-126` |

因此题目保证字符串只包含下面内容时，可以使用 `int[128]`：

```text
英文字母
数字
空格
常见英文标点和符号
```

Java 的 `char` 可以自动提升为 `int`，所以能够直接作为数组下标：

```java
int[] count = new int[128];
char c = 'A';
count[c]++;
```

这等价于：

```java
count[65]++;
```

## 3. 常见数组模板

### 3.1 统计词频

```java
int[] count = new int[128];

count[c]++;
count[c]--;
```

### 3.2 记录是否出现

```java
boolean[] seen = new boolean[128];

seen[c] = true;
if (seen[c]) {
    // c已经出现
}
```

### 3.3 记录最后出现位置

```java
int[] lastIndex = new int[128];
Arrays.fill(lastIndex, -1);

lastIndex[c] = index;
```

### 3.4 仅小写字母

题目明确只有 `a-z` 时，可以进一步缩小为：

```java
int[] count = new int[26];
count[c - 'a']++;
```

不能在字符范围包含大写字母、数字或空格时继续使用 `c - 'a'`。

例如：

```java
'A' - 'a' = -32
```

会产生负下标并抛出 `ArrayIndexOutOfBoundsException`。

## 4. 数组和 HashMap 的取舍

### 固定小字符集：数组更合适

```java
int[] count = new int[128];
count[c]++;
```

优点：

- 直接寻址，访问时间稳定为 `O(1)`。
- 没有哈希计算。
- 没有 `Character`、`Integer` 装箱和拆箱。
- 没有 HashMap 节点对象，常数和内存开销较小。
- 面试代码短，边界明确。

### 字符集未知或稀疏：HashMap 更合适

```java
HashMap<Character, Integer> count = new HashMap<>();

if (!count.containsKey(c)) {
    count.put(c, 1);
} else {
    count.put(c, count.get(c) + 1);
}
```

优点：

- 不需要提前为整个字符范围分配数组。
- 字符范围不确定时更安全。
- 只保存实际出现的字符。

HashMap 操作平均为 `O(1)`，因此很多字符串算法仍然可以达到平均 `O(N)`。

## 5. 空间大小

Java 的一个 `int` 占 4 字节，忽略数组对象头时：

```text
int[26]    约 104 B
int[128]   约 512 B
int[65536] 约 256 KB
```

`int[128]` 的空间很小，通常比存放若干装箱键值和节点对象的 HashMap 更紧凑。

空间复杂度中，固定长度数组通常记为：

```text
O(1)
```

因为数组长度不随输入规模 `N` 增长。

## 6. Java char 不等于完整 Unicode 字符

Java 的 `char` 是一个 16 位 UTF-16 code unit，取值范围：

```text
0 ~ 65535
```

因此下面写法能够覆盖任意单个 Java `char`：

```java
int[] count = new int[65536];
count[c]++;
```

但部分 Unicode 字符，例如很多 Emoji，需要两个 `char`（一对代理项）表示：

```java
String emoji = "😀";
System.out.println(emoji.length()); // 2
```

如果题目要求按照完整 Unicode code point 处理，应使用：

```java
int[] codePoints = s.codePoints().toArray();
HashMap<Integer, Integer> count = new HashMap<>();
```

此时 Map 的 key 是 `Integer` code point，而不是 `Character`。

## 7. 不要误解 int[256]

有时会看到：

```java
int[] count = new int[256];
```

它能够覆盖单字节无符号值 `0-255`，但“扩展 ASCII”没有一个统一标准，并且 `256` 个位置远远不能覆盖 Unicode。

所以：

```text
题目明确标准ASCII -> int[128]
题目明确字节值0-255 -> int[256]
题目可能包含中文 -> 不能使用int[128]或int[256]
```

## 8. 在最长无重复子串中的选择

题目给出的字符范围是英文字母、数字、符号和空格，可以使用标准 ASCII 数组：

```java
int[] count = new int[128];

for (int R = 0; R < s.length(); R++) {
    char current = s.charAt(R);
    count[current]++;

    while (count[current] > 1) {
        count[s.charAt(L)]--;
        L++;
    }

    ans = Math.max(ans, R - L + 1);
}
```

窗口不变量：

```text
每次更新答案之前，[L, R] 中所有字符的词频都不超过1。
```

数组和 HashMap 版本的渐进时间复杂度都是 `O(N)`；数组版本的常数开销通常更小。

## 9. 面试选型

```text
看到“仅小写字母”：
    优先想到 int[26]

看到“英文字母、数字、空格、英文符号”：
    优先想到 int[128]

看到“字符范围未知”：
    使用 HashMap<Character, ...>

看到“完整Unicode字符”：
    使用 codePoints() + HashMap<Integer, ...>
```

最终原则：

> 先确认字符范围，再选择最小且安全的直接寻址数组；无法确认范围时使用 Map。
