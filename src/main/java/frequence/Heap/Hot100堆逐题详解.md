给定整数数组`nums`和整数`k`，返回数组中第`k`个最大的元素。
需要查找的是数组排序后的第`k`个最大元素，而不是第`k`个不同的元素。

本题核心算法是 QuickSelect: 实现上就是 类似二分 + partition。  神似快排，但是因为扫描的数据量不一样，所以平均时间复杂度为O(N)，最差退化到O(N^2)

### 2026-09-19复盘：为什么第K大可以使用荷兰国旗

荷兰国旗分区会把当前区间划分为：

~~~text
[小于pivot][等于pivot][大于pivot]
~~~

虽然三个区域内部没有完全排序，但`等于pivot`区域在完整升序数组中的最终下标范围已经确定。
因此，只要先把第k大转换为升序目标下标：

~~~java
int targetIndex = nums.length - k;
~~~

就可以根据目标下标与等于区间的位置关系淘汰区域：

~~~text
targetIndex < equalLeft   -> 只保留左侧
targetIndex > equalRight  -> 只保留右侧
否则                     -> pivot就是答案
~~~

这就是“荷兰国旗 + 类二分区间淘汰”的Quickselect。它不像普通二分那样依赖原数组有序，
而是先通过一次partition制造出能够安全排除区间的信息。

### 两个基础错误

闭区间初始化：

~~~java
int left = 0;
int right = nums.length - 1;
~~~

`right`是可访问的数组下标，不能写成`nums.length`。

第k大不是下标k：

~~~text
升序数组长度为N
最大值下标       N-1，对应第1大
次大值下标       N-2，对应第2大
第k大目标下标    N-k
~~~

partition返回的是升序排列语义下的最终区间，所以后续必须比较`targetIndex`，不能直接比较题目
给出的1-based变量`k`。

### Quickselect为什么期望O(N)

需要修正一个不严谨说法：随机pivot不保证每轮都能去掉一半。只有pivot恰好接近中间时，剩余
规模才接近`N/2`。随机化保证的是长期来看不容易持续选中极端pivot，剩余规模在期望意义上
按固定比例缩小。

Quickselect每轮只继续处理目标所在的一侧，因此扫描量近似为：

~~~text
N + aN + a^2N + a^3N + ... = O(N)，其中0 < a < 1
~~~

如果为了理解暂时假设每次正好减半，则是：

~~~text
N + N/2 + N/4 + ... < 2N
~~~

这能解释几何级数，但“每次减半”不是算法保证，只是便于理解的理想情况。

### 与快速排序的区别

| 算法 | partition后继续处理 | 期望复杂度 |
| --- | --- | --- |
| QuickSort | 左右两侧都处理 | `O(N log N)` |
| Quickselect | 只处理目标所在一侧 | `O(N)` |

快速排序在同一递归层需要处理所有分区，总工作量约为`O(N)`，期望高度为`O(log N)`。
Quickselect只沿一条路径继续，后续扫描区间越来越小，所以期望总扫描量为`O(N)`。

但随机Quickselect最坏仍可能连续选到端点pivot：

~~~text
N + (N-1) + (N-2) + ... = O(N^2)
~~~

因此准确复杂度是：期望`O(N)`，最坏`O(N^2)`，额外空间在迭代实现中为`O(1)`。

### 两套荷兰国旗边界定义

第一套把`less`和`more`定义为开区间端点：

~~~text
[left, less)  < pivot
[less, index) == pivot
[index, more] 待处理
(more, right] > pivot
~~~

循环条件是`index <= more`，结束后等于区间直接是`[less,more]`。

第二套把pivot预留在`right`位置：

~~~text
[left, less]  < pivot
(less, index) == pivot
[index, more) 待处理
[more, right) > pivot
right          pivot
~~~

循环条件是`index < more`，结束后必须执行：

~~~java
swap(nums, more, right);
~~~

再返回等于区间`[less + 1,more]`。两套定义都正确，但循环条件、边界含义、最终交换和返回值
必须成套使用，不能混搭。

## Q295 FindMedianFromDataStream 【Hot 100】

### 核心思想与题目要求

295. 数据流的中位数
中位数是有序整数列表中间位置的值。如果列表长度为偶数，中位数是中间两个值的平均值。
设计一个支持以下操作的数据结构：
    - `addNum(num)`：将整数加入数据流；
    - `findMedian()`：返回当前所有元素的中位数。
**核心思路：**`more`是保存左半区的大根堆，`less`是保存右半区的小根堆。
始终维持`more.size() == less.size()`或`more.size() == less.size() + 1`，并保证
`more.peek() <= less.peek()`。因此奇数个元素时中位数是`more.peek()`，偶数个元素时
是两个堆顶的平均值。
`addNum`不能只按堆大小直接加入某个堆，因为这只能维持容量，不能保证左右区间有序。
当前实现先加入一侧，再把该侧堆顶转移到另一侧，一次操作同时维护两个不变量。

### 2026-09-14复盘：双堆与固定三步

把数据流概念上切成两半：

~~~text
较小的一半                         较大的一半
[...... lower.peek()] | [upper.peek() ......]
          左侧最大值       右侧最小值
~~~

- `lower`保存较小的一半，必须使用大根堆；
- `upper`保存较大的一半，使用Java `PriorityQueue`默认的小根堆。

需要同时维护两个不变量：

~~~text
顺序不变量：lower中的所有元素 <= upper中的所有元素

数量不变量：lower.size() == upper.size()
          或lower.size() == upper.size() + 1
~~~

只按照两个堆的大小直接放入新元素，只能维护数量关系，不能保证新元素落在正确的数值区间。
最稳定的写法是不判断新元素属于哪边，每次固定执行三步：

~~~java
// 1. 新元素先进入左侧大根堆。
lower.offer(num);

// 2. 左堆最大值转入右侧小根堆，维护顺序不变量。
upper.offer(lower.poll());

// 3. 如果右侧数量更多，把右侧最小值移回左侧，维护数量不变量。
if (upper.size() > lower.size()) {
    lower.offer(upper.poll());
}
~~~

第2步执行后，`lower`中留下的都是更小的元素；被转移的是`lower`当前最大值，因此能够进入
保存较大一半的`upper`。第3步只负责让奇数个元素时`lower`多一个。

中位数由数量不变量直接得到：

~~~java
if (lower.size() > upper.size()) {
    return lower.peek();
}
return ((double) lower.peek() + upper.peek()) / 2.0;
~~~

### PriorityQueue默认方向

~~~java
PriorityQueue<Integer> upper = new PriorityQueue<>();
// 默认自然顺序，小根堆，peek()返回最小值。

PriorityQueue<Integer> lower =
        new PriorityQueue<>(Comparator.reverseOrder());
// 反向顺序，大根堆，peek()返回最大值。
~~~

不推荐使用`(a,b) -> b-a`，因为整数极值相减可能溢出。双堆插入时间复杂度为`O(log N)`，
查询中位数为`O(1)`，总空间复杂度为`O(N)`。

```java
package frequence.Heap;

import java.util.PriorityQueue;

/**
 * 295. 数据流的中位数
 *
 * <p>中位数是有序整数列表中间位置的值。如果列表长度为偶数，中位数是中间两个值的平均值。
 *
 * <p>设计一个支持以下操作的数据结构：
 * <ul>
 *     <li>{@code addNum(num)}：将整数加入数据流；</li>
 *     <li>{@code findMedian()}：返回当前所有元素的中位数。</li>
 * </ul>
 *
 * <p><b>核心思路：</b>{@code more}是保存左半区的大根堆，{@code less}是保存右半区的小根堆。
 * 始终维持{@code more.size() == less.size()}或{@code more.size() == less.size() + 1}，并保证
 * {@code more.peek() <= less.peek()}。因此奇数个元素时中位数是{@code more.peek()}，偶数个元素时
 * 是两个堆顶的平均值。
 *
 * <p>{@code addNum}不能只按堆大小直接加入某个堆，因为这只能维持容量，不能保证左右区间有序。
 * 当前实现先加入一侧，再把该侧堆顶转移到另一侧，一次操作同时维护两个不变量。
 */
public class Q295_FindMedianFromDataStream {

    public static class MedianFinder {

        private final PriorityQueue<Integer> more;
        private final PriorityQueue<Integer> less;
        private int size;

        public MedianFinder() {
            more = new PriorityQueue<>((a, b) -> b - a);
            less = new PriorityQueue<>();
            size = 0;
        }

        public void addNum(int num) {
            if (more.size() == less.size() + 1) {
                more.offer(num);
                less.offer(more.poll());
            } else {
                less.offer(num);
                more.offer(less.poll());
            }
            size++;
        }

        public double findMedian() {
            if (size % 2 == 1) {
                return (double) more.peek();
            } else {
                return ((double) more.peek() + less.peek()) / 2;
            }
        }
    }
}
```

     PS： 但是你看到了，在门槛堆中，我们比较的是频次，但是最终要拿出来的结果 是 该频次对应的值。 这就使得 同一个对象需要具备两个属性： 【1】频次用来比较 【2】对应的值用来获取结果  ==》 所以要封装成Node实例就可以了

```java
        public int[] topKFrequent(int[] nums, int k) {
            HashMap<Integer, Node> map = new HashMap<>();
            // Step1 统计词频
            for (int i = 0; i < nums.length; i++) {
                if (!map.containsKey(nums[i])) {
                    map.put(nums[i], new Node(nums[i], 0));
                }
                // 【错误点】这里不是 重新赋值。 而是直接访问对应Node，修改Node里面的值
                // map.put(nums[i], map.get(nums[i]).freq + 1);
                map.get(nums[i]).freq++;
            }


            PriorityQueue<Node> minHeap = new PriorityQueue<>((a,b) -> (a.freq - b.freq)); // 注意，因为对象不可比较，所以要传入比较器
            // 词频统计完成之后，都封装到了Node里面，此时遍历Node， 使用 map.values()
            for (Node node : map.values()) {
                if (minHeap.size() < k) {                    // 门槛堆未满时，直接加入
                    minHeap.add(node);
                } else {
                    if (node.freq > minHeap.peek().freq) {  // 门槛堆满了，只有当堆顶元素<新元素时，才弹堆顶+加入新元素
                        minHeap.poll();
                        minHeap.add(node);
                    }
                }
            }

            // 最后，将门槛堆中的 node 依次弹出，塞入ans数组结果
            int[] ans = new int[k];
            int index = 0;
            while (!minHeap.isEmpty()) {
                ans[index++] = minHeap.poll().val;
            }
            return ans;
        }

            int val;
            int freq;

            public Node(int v, int f) {
                val = v;
                freq = f;
            }
        }

        public class MyComparator implements Comparator<Node> {
            public int compare(Node o1, Node o2) {
                return o1.freq - o2.freq;
            }
        }
```
