## 一、核心结论

> 二分查找不是机械地把下标除以2，而是利用有序性或单调性，证明一部分区间不可能包含答案，然后安全地舍弃该区间。

每轮二分必须回答两个问题：

```text
1. 根据mid位置的信息，可以得到什么确定结论？
2. 根据这个结论，哪一部分一定不包含答案？
```

只有能够证明某一部分不可能包含答案，才能更新边界。

二分的标准推理过程：

```text
确定答案仍然存在的搜索区间；
选择mid；
计算或观察mid对应的信息；
利用有序性、单调性或题目结构；
证明某一部分一定不含答案；
舍弃该部分；
继续维持搜索区间不变量。
```

## 二、为什么普通升序数组可以二分

升序数组：

```text
[1,3,5,7,9,11,13]
```

如果：

```java
nums[mid] < target
```

因为数组升序，所以：

```text
nums[left..mid]中的所有值都 <= nums[mid] < target
```

因此`[left, mid]`一定不包含答案，可以整体舍弃：

```java
left = mid + 1;
```

如果：

```java
nums[mid] > target
```

同理可知`[mid, right]`一定不包含答案：

```java
right = mid - 1;
```

这里真正产生作用的是“升序”提供的范围证明，而不是`mid`本身。

## 三、搜索区间不变量

写二分前必须先确定：

```text
答案可能存在于哪个区间？
边界以外的部分为什么可以确定舍弃？
```

常见区间模型有两种。

### 闭区间 `[left, right]`

```java
while (left <= right) {
    int mid = left + (right - left) / 2;
}
```

`mid`已经检查并确定不是答案时，更新：

```java
left = mid + 1;
right = mid - 1;
```

典型场景：查找某个具体值。

### 左闭右开区间 `[left, right)`

```java
while (left < right) {
    int mid = left + (right - left) / 2;
}
```

更新方式根据`mid`是否仍可能是答案决定：

```java
right = mid;      // mid仍可能是答案
left = mid + 1;   // mid确定不是答案
```

典型场景：寻找第一个满足条件的位置。

不能只背`left <= right`或`left < right`。循环条件、区间定义和边界更新必须属于同一套不变量。

## 四、mid能不能被排除

边界更新不是固定语法，而是候选区间证明的直接结果：

> `left`、`right`每次收缩，都是在排除已经确定不可能包含答案的区间；剩下的闭区间必须仍然覆盖所有可能答案。

因此，先问“这次能够排除哪一段”，再决定使用`mid + 1`、`mid - 1`还是保留`mid`。

边界更新最容易出错的地方是：

```text
right = mid
还是
right = mid - 1
```

判断依据：

```text
如果mid确定不可能是答案：排除mid。
如果mid仍然可能是答案：保留mid。
```

例如Q153寻找旋转数组最小值：

```java
if (nums[mid] > nums[right]) {
    // mid位于高值段，不可能是最小值
    left = mid + 1;
} else {
    // mid可能就是最小值
    right = mid;
}
```

不要凭模板感觉决定`+1`或`-1`，要先回答`mid`是否可能是答案。

## 五、边界二分：寻找第一个满足条件的位置

Q35搜索插入位置的本质是：

```text
寻找第一个nums[index] >= target的位置。
```

### Q35致命边界错误：插入到mid前面时返回mid，不是mid-1

如果最后比较得到：

~~~text
nums[mid] > target
~~~

说明target应该插入到nums[mid]前面。数组下标表示元素将要占据的位置，因此插入位置正是mid：

~~~text
错误：mid - 1
正确：mid
~~~

mid-1是nums[mid]前一个已有元素的下标，不是“插到nums[mid]前面”的新元素下标。

不过，更稳定的闭区间写法不需要在循环结束后继续比较最后一次mid：

~~~java
int left = 0;
int right = nums.length - 1;

while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) {
        return mid;
    } else if (nums[mid] < target) {
        left = mid + 1;
    } else {
        right = mid - 1;
    }
}
return left;
~~~

循环结束时：

~~~text
[0,left)            已经确定全部小于target
[left,nums.length)  已经确定全部大于target
~~~

所以left正好是两段的分界点，也是target的插入位置。它可以自然表示：

~~~text
0             插到所有元素之前
数组内部下标    插到两个元素之间
nums.length   插到所有元素之后
~~~

可以定义单调条件：

```text
false false false true true true
                  ↑
              第一个true
```

二分的目标不是寻找某个相等值，而是寻找条件从`false`变成`true`的边界。

Q34可以拆成两个边界：

```text
first = 第一个 >= target 的位置
afterLast = 第一个 > target 的位置
last = afterLast - 1
```

也可以直接做两次闭区间边界搜索：

~~~text
mostRight = 最右的nums[index] <= target
mostLeft  = 最左的nums[index] >= target
~~~

这两个位置最初只是边界候选，并不保证对应元素等于target。例如：

~~~text
nums = [1,3,5], target = 4
mostRight指向3
mostLeft指向5
~~~

因此搜索结束后必须验证target是否存在：

~~~java
if (mostRight == -1 || nums[mostRight] != target) {
    return new int[]{-1, -1};
}
return new int[]{mostLeft, mostRight};
~~~

哨兵初值：

~~~text
mostRight = -1
表示不存在任何<=target的元素。

mostLeft = nums.length
表示不存在任何>=target的元素，也是数组末尾之后的虚拟插入位置。
~~~

其中逻辑或具有短路求值特性。mostRight等于-1时，后半段不会执行，因此不会访问nums[-1]；
这个写法可以自然处理空数组，不需要额外的空数组分支。

排除原则：

```text
条件为false的整段可以舍弃；
条件为true时，mid可能就是第一个true，必须保留mid继续向左收缩。
```

## 六、旋转数组：先寻找局部有序性

旋转数组整体不再有序，但只有一个旋转断点，因此使用`mid`切分后至少有一侧有序。

```text
先判断哪一侧有序；
再判断target是否属于有序侧的值域；

属于：
    保留有序侧，舍弃另一侧。

不属于：
    有序侧可以确定舍弃，进入另一侧。
```

这仍然是普通二分的排除原则，只是利用的范围信息从“整体有序”变成了“局部有序”。

详细内容参见：

[旋转排序数组二分查找.md](./旋转排序数组二分查找.md)

## 七、重复值为什么会导致退化

Q81允许重复元素，可能出现：

```text
nums[left] == nums[mid] == nums[right]
```

此时无法确定旋转断点在哪一侧，也无法证明哪一半一定不包含答案。

不能强行排除一半，只能收缩无效边界：

```java
left++;
right--;
```

当数组包含大量相同元素时，每轮可能只能排除一个或两个位置，最坏时间复杂度退化为：

```text
O(N)
```

退化的根本原因不是代码没有使用二分形式，而是：

```text
重复值让算法失去了“一次安全排除一半”的信息依据。
```

## 八、二维矩阵：先建立一维有序映射

Q74满足：

```text
每行内部有序；
下一行第一个元素大于上一行最后一个元素。
```

### 方法一：两次二分，先确定行再搜索列

第一轮在所有行的首元素中寻找：

~~~text
matrix[row][0] <= target的最右位置
~~~

设该位置为candidateRow。根据“下一行首元素大于上一行尾元素”的题目条件，可以证明：

~~~text
candidateRow上方所有行的全部元素都小于target；
candidateRow下方所有行的首元素都大于target，因此整行都大于target。
~~~

所以target如果存在，只可能位于candidateRow。第二轮只需要在该行进行普通二分。

复杂度必须区分：

~~~text
错误方案：线性扫描所有行 + 行内二分
O(M + log N)，不满足要求。

正确方案：二分行 + 二分列
O(log M + log N)
= O(log(M * N))
~~~

TODO: 【变量命名】二维矩阵通常使用m、n表示行列数量，二分中点统一命名为mid，不要再次
使用m表示中点，否则同名冲突或语义混乱。

### 方法二：虚拟展开为一维有序数组

因此整个矩阵可以视为长度为`rows * cols`的一维升序数组。

一维下标映射：

```java
int row = mid / cols;
int col = mid % cols;
```

建立映射后，仍然使用普通升序数组的排除证明：

```text
matrix[row][col] < target
    舍弃一维区间[left, mid]

matrix[row][col] > target
    舍弃一维区间[mid, right]
```

所以二维二分的关键不是矩阵本身，而是证明它能够映射成一个整体有序序列。

## 九、答案二分：二分的不是数组元素

有些题目没有现成有序数组，但答案范围具有单调性。

例如判断：

```text
是否能够在限制值x下完成任务？
```

可能形成：

```text
x太小：false false false
x足够：true true true
```

那么可以二分寻找：

```text
第一个使check(x) == true的x
```

标准结构：

```java
while (left < right) {
    int mid = left + (right - left) / 2;

    if (check(mid)) {
        // mid可能是最小可行答案，保留mid
        right = mid;
    } else {
        // mid不可行，mid及其左侧都可以舍弃
        left = mid + 1;
    }
}
```

这里的有序性不是数组值有序，而是谓词`check(x)`具有单调性。

## 十、两个正序数组中位数：二分分割位置

Q4不是查找某个具体数组元素，而是在较短数组中二分分割位置。

目标是找到一种分割，使：

```text
左半部分元素总数符合要求；
左半部分所有元素 <= 右半部分所有元素。
```

如果第一个数组左侧最大值太大，说明分割位置偏右，可以舍弃更右的分割位置；如果第二个数组
左侧最大值太大，说明分割位置偏左，可以舍弃更左的分割位置。

本质仍然是：

```text
根据当前分割状态判断方向，
证明一部分分割位置不可能满足条件，
然后舍弃。
```

## 十一、无法证明时不能强行二分

二分最危险的错误是：

```text
没有建立单调性或有序性，
却仍然根据mid随意舍弃一半。
```

如果无法回答：

```text
为什么被舍弃的区间一定不包含答案？
```

那么当前二分更新就没有正确性依据。

此时应该：

- 重新寻找单调条件；
- 改变搜索对象，例如二分答案；
- 增加辅助信息；
- 或者承认该问题不能直接二分。

## 十二、常见错误

| 错误 | 本质原因 |
| --- | --- |
| 只背模板，不定义搜索区间 | 循环条件和边界更新不匹配 |
| 无法说明为什么舍弃某一侧 | 没有建立有序性或单调性 |
| `right = mid`写成`mid - 1` | 错误排除了仍可能是答案的mid |
| `left = mid`导致死循环 | 区间没有严格缩小 |
| 查找边界时找到相等就返回 | 找到的可能不是第一个或最后一个位置 |
| 旋转数组没有先判断有序侧 | 无法确定target所在范围 |
| 忽略重复元素 | 有序侧判断出现歧义 |
| `mid = (left + right) / 2` | 通用场景可能发生整数溢出 |

安全的`mid`计算：

```java
int mid = left + (right - left) / 2;
```

## 十三、写二分前的检查清单

```text
1. 搜索对象是什么：下标、边界、答案值还是分割位置？
2. 搜索区间是什么：[left,right]还是[left,right)？
3. 当前区间维持什么不变量？
4. 有序性或单调性体现在哪里？
5. mid的信息能够证明哪部分一定不含答案？
6. mid本身是否仍可能是答案？
7. 更新后区间是否严格缩小？
8. 存在重复值时，判断依据是否仍然成立？
9. 最终left/right代表什么？
10. 空数组、单元素和答案位于边界时是否正确？
```

## 十四、面试记忆

```text
二分不是折半，而是排除。

先找有序性或单调性，
再证明哪一段不可能有答案，
最后安全舍弃。

mid可能是答案，就保留mid；
mid确定不是答案，才排除mid。

无法证明哪一半可以舍弃，就不能强行二分。
```
