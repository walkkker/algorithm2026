| 题目 | 是否允许重复值 | 主要难点 | 典型复杂度 | 最坏复杂度 |
|---|---|---|---|---|
| Q33 | 否 | 判断哪一侧有序，再检查`target`值域 | `O(log N)` | `O(log N)` |

## 一、核心结论

旋转排序数组的二分查找可以记成：

```text
先判断哪一侧有序，
再判断target是否位于有序侧的值域中，
最后决定进入左侧还是右侧。

特别大的思想核心，就是 旋转数组只有一个断崖，寻找断崖在哪里。 => 另一侧就是有序的，此时便可以判断 有序区间的值域
```

普通升序数组中，`mid`左右两侧都保持有序；旋转数组虽然整体不再有序，但对于当前二分区间：

```text
[left, mid]和[mid, right]中，至少有一侧一定有序。
```

这就是旋转数组仍然能够二分的依据。

### 二分查找的本质：有依据地舍弃一部分区间

最简单的升序数组二分之所以能够每次排除一半，是因为数组整体有序：

```text
nums[mid] < target
    [left, mid]中的所有值都小于target，可以整体舍弃。

nums[mid] > target
    [mid, right]中的所有值都大于target，可以整体舍弃。
```

因此二分的本质不是机械地执行“下标除以2”，而是：

```text
利用有序性或单调性得到一个确定的范围结论，
证明其中一部分不可能包含答案，
然后安全地舍弃该区间。
```

旋转数组也不例外。它虽然不再整体有序，但每次被`mid`切分后至少有一侧有序：

```text
先找到有序段；
再判断有序段是不是target所在的目标段；

如果target落在该有序段的值域内：
    保留有序段，舍弃另一段。

如果target不在该有序段的值域内：
    该有序段就是可以确定舍弃的区间，进入另一段。
```

Q153没有具体`target`，但原则相同：通过`nums[mid]`与右端点的关系判断`mid`位于高值段还是
低值段，从而证明某一部分不可能包含最小值并将其舍弃。

Q81允许重复元素。当重复值导致无法判断哪一侧有序时，就失去了“一次安全舍弃一半”的依据，
只能逐步收缩边界，因此最坏时间复杂度退化为`O(N)`。

### 旋转数组的走势图

旋转数组最重要的视觉模型是：

```text
两段分别递增的曲线，中间发生一次从高值到低值的断崖式下降。
```

例如：

```text
nums = [4,5,6,7,0,1,2]

值
7 |          ●
6 |       ●
5 |    ●
4 | ●
3 |
2 |                   ●
1 |                ●
0 |             ●
  +----------------------> 下标
    0  1  2  3  4  5  6
               ↑
          旋转断点/断崖
```

可以简化记忆为：

```text
高值递增段：4 -> 5 -> 6 -> 7
                         |
                         | 断崖式下降
                         v
低值递增段：             0 -> 1 -> 2
```

这张走势图可以同时解释多道旋转数组题：

```text
Q33搜索目标：
判断mid位于高值段还是低值段，确定哪一侧有序，
再通过target的值域决定搜索方向。

Q153寻找最小值：
寻找断崖下降后的第一个点，也就是低值递增段的起点。

Q81/Q154存在重复值：
走势图可能出现水平平台，部分位置无法判断属于哪一段，
因此需要收缩边界，最坏退化为O(N)。
```

## 二、为什么至少有一侧有序

升序数组旋转后，只会产生一个断点：

```text
原数组：
[0,1,2,4,5,6,7]

旋转后：
[4,5,6,7,0,1,2]
         ↑
       旋转断点
```

使用`mid`切分当前区间时：

- 如果断点位于右半部分，左半部分保持有序；
- 如果断点位于左半部分，右半部分保持有序；
- 如果断点不在当前区间，两侧都可能有序。

因此只需要识别出其中一个有序部分，就可以利用目标值的范围排除一半区间。

## 三、推荐模板：比较当前区间左端点

```java
public int search(int[] nums, int target) {
    int left = 0;
    int right = nums.length - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;

        if (nums[mid] == target) {
            return mid;
        }

        if (nums[left] <= nums[mid]) {
            // [left, mid]有序
            if (nums[left] <= target && target < nums[mid]) {
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        } else {
            // [mid, right]有序
            if (nums[mid] < target && target <= nums[right]) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
    }

    return -1;
}
```

完整判断流程：

```text
nums[left] <= nums[mid]
    左侧有序

    target属于[nums[left], nums[mid])
        去左侧
    否则
        去右侧

nums[left] > nums[mid]
    右侧有序

    target属于(nums[mid], nums[right]]
        去右侧
    否则
        去左侧
```

`nums[mid] == target`已经在前面单独判断，因此后面的值域不需要再次包含`nums[mid]`。

## 四、你的写法：与全局最后一个元素比较

你的判断方式：

```java
if (nums[mid] < nums[nums.length - 1]) {
    // mid位于旋转点右侧的低值有序段
} else {
    // mid位于旋转点左侧的高值有序段
}
```

在Q33元素互不相同的约束下，这种判断也成立。

旋转数组可以看成两个有序段：

```text
[较大的左段][较小的右段]
```

全局最后一个元素位于较小的右段：

- `nums[mid] < nums[n - 1]`：`mid`位于右侧低值段；
- `nums[mid] > nums[n - 1]`：`mid`位于左侧高值段；
- `nums[mid] == nums[n - 1]`：元素互不相同时，只可能`mid == n - 1`。

对应代码：

```java
if (nums[mid] < nums[nums.length - 1]) {
    // 当前mid右侧有序
    if (nums[mid] < target && target <= nums[right]) {
        left = mid + 1;
    } else {
        right = mid - 1;
    }
} else {
    // 当前mid左侧有序
    if (nums[left] <= target && target < nums[mid]) {
        right = mid - 1;
    } else {
        left = mid + 1;
    }
}
```

这种写法正确，但“比较当前区间端点”的模板通常更容易迁移到其他旋转数组问题：

```java
nums[left] <= nums[mid]
```

它直接描述当前搜索区间的有序性，不依赖原数组的全局最后一个位置。

## 五、区间边界为什么一边闭一边开

已经提前排除：

```java
nums[mid] == target
```

因此左侧有序区间只需要检查：

```java
nums[left] <= target && target < nums[mid]
```

对应：

```text
[nums[left], nums[mid])
```

右侧有序区间只需要检查：

```java
nums[mid] < target && target <= nums[right]
```

对应：

```text
(nums[mid], nums[right]]
```

这种边界写法与下标更新严格对应：

```java
right = mid - 1;
left = mid + 1;
```

## 六、执行示例

```text
nums = [4,5,6,7,0,1,2]
target = 0
```

第一次：

```text
left=0, right=6, mid=3, nums[mid]=7

[left, mid] = [4,5,6,7]有序
target=0不属于[4,7)

进入右侧：
left=mid+1=4
```

第二次：

```text
left=4, right=6, mid=5, nums[mid]=1

[left, mid] = [0,1]有序
target=0属于[0,1)

进入左侧：
right=mid-1=4
```

第三次：

```text
left=4, right=4, mid=4
nums[mid]=0

找到target
```

## 七、Q81：存在重复元素时的两种模板

Q33保证数组元素互不相同，因此：

```java
nums[left] <= nums[mid]
```

可以直接判断左侧有序。

如果允许重复元素，例如：

```text
[1,0,1,1,1]
```

可能出现：

```text
nums[left] == nums[mid] == nums[right]
```

此时无法判断旋转断点位于哪一侧。

### 方法一：三点相等时双端收缩，面试首选

这是Q81的标准写法，也是面试遇到原题时推荐使用的模板：

```java
public boolean search(int[] nums, int target) {
    int left = 0;
    int right = nums.length - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;

        if (nums[mid] == target) {
            return true;
        }

        // 三个位置相等时，无法判断断崖在哪一侧。
        if (nums[left] == nums[mid] && nums[mid] == nums[right]) {
            left++;
            right--;
            continue;
        }

        if (nums[left] <= nums[mid]) {
            // [left, mid]有序
            if (nums[left] <= target && target < nums[mid]) {
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        } else {
            // [mid, right]有序
            if (nums[mid] < target && target <= nums[right]) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
    }

    return false;
}
```

#### 为什么处理三点相等后，`left <= mid`就能判断左侧有序

分两种情况理解：

```text
nums[left] < nums[mid]
```

左端点严格小于中点，`[left, mid]`不可能跨越从高值段跌落到低值段的断崖，因此左侧有序。

```text
nums[left] == nums[mid]
```

如果`[left, mid]`跨越了断崖，并且断崖后的值又增长到与`nums[left]`相等，那么右端点也只能与它们
相等，即会出现：

```text
nums[left] == nums[mid] == nums[right]
```

这个歧义分支已经被前面的双端收缩处理。因此进入有序性判断时，`nums[left] <= nums[mid]`
可以归入“左侧有序”。

这里的顺序不能颠倒：必须先处理三点相等，再使用`left <= mid`判断有序侧。

### 方法二：`left == mid`时单边收缩，低记忆负担版本

还可以先单独排除左端点与中点相等的情况：

```java
public boolean search(int[] nums, int target) {
    int left = 0;
    int right = nums.length - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;

        if (nums[mid] == target) {
            return true;
        }

        if (nums[left] == nums[mid]) {
            // nums[mid]已经确认不是target，所以相等的nums[left]也不是target。
            left++;
            continue;
        }

        if (nums[left] < nums[mid]) {
            // [left, mid]严格有序
            if (nums[left] <= target && target < nums[mid]) {
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        } else {
            // [mid, right]有序
            if (nums[mid] < target && target <= nums[right]) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
    }

    return false;
}
```

这个版本成立的关键是执行顺序：

```text
先确认nums[mid] != target；
再根据nums[left] == nums[mid]推出nums[left] != target；
因此可以安全执行left++。
```

这不是所有二分题都能使用的通用规则，而是“搜索某个确定target”时才能使用的等值排除。

### 两种方法如何选择

| 方法 | 歧义处理 | 判断有序侧 | 特点 |
|---|---|---|---|
| 方法一，面试首选 | 三点相等时`left++`、`right--` | `nums[left] <= nums[mid]` | 标准模板；一次可去掉两个无信息边界 |
| 方法二，备选 | 左端点等于中点时`left++` | `nums[left] < nums[mid]` | 证明直接、记忆负担较低 |

两者在无大量重复值时通常为`O(log N)`，最坏情况下都可能退化为`O(N)`，额外空间都是`O(1)`。
这里所说的“面试首选/最优模板”主要指标准性和常数表现；在渐进复杂度上，两者相同。

重复值导致退化不是代码写得不够好，而是比较信息不足。极端数组例如：

```text
[1,1,1,1,1,0,1,1,1]
```

边界和中点长时间相等，算法无法证明任何一半一定不含`target`，只能逐步缩小搜索区间。

## 八、Q153与Q33的区别

Q33寻找具体目标值：

```text
先判断有序侧，
再判断target是否属于有序侧。
```

Q153寻找旋转点，也就是最小值。常用判断是比较`nums[mid]`与`nums[right]`：

```java
if (nums[mid] > nums[right]) {
    // 最小值一定在mid右侧，mid不可能是答案
    left = mid + 1;
} else {
    // mid可能就是最小值，不能排除
    right = mid;
}
```

区别：

```text
Q33：排除不可能包含target的一半，使用left <= right。

Q153：不断收缩最小值所在区间，使用left < right，
      最终left == right就是最小值位置。
```

## 九、复杂度

元素互不相同时，每次都能排除至少一半区间：

- 时间复杂度：`O(log N)`；
- 额外空间复杂度：`O(1)`。

## 十、面试记忆

```text

mid切开后，左右至少一边有序。

先判断哪边有序，
再看target是否落在有序区间，
在就进去，不在就去另一边。

Q81存在重复值，面试首选：
    先判断mid是否命中；

```
