# 链表错题本

## 使用方式

本文只记录“已经真实出现或从当前代码审计中确认的高风险错误”。复习时先看汇总表，再用最小反例在纸上走指针。

## 错误汇总

| 题目 | 错误或遗漏 | 直接后果 | 稳定修正 |
| --- | --- | --- | --- |
| Q2 两数相加 | 循环完成计算后忘记推进输入指针 | 死循环、重复创建同一位 | 每轮结束检查输入指针和`tail`是否都推进 |
| Q19 删除倒数第N个 | 将“目标位置”与“需要执行的跳跃次数”混淆 | 删除错位或NPE | 使用dummy和固定间距；让指针直接停在目标前驱 |
| Q21 两路归并 | 只推进输入链表或只推进`tail` | 死循环或覆盖已连接节点 | 接入节点后同时推进被消费输入和结果尾指针 |
| Q141/Q142 环 | `slow=fast=head`后立即用`while(slow != fast)` | 循环零次，错误判断已经相遇 | 先移动再判断，或让初始位置不同；统一做空指针检查 |
| Q160 相交链表 | 统计长度后继续使用已经走到`null`的指针 | 后续逻辑从空指针开始 | 重新从`headA/headB`初始化，或使用指针换道法 |
| Q24 两两交换 | 忽略反转后会产生新头 | 第一组或后续分组断链 | 站在前驱节点操作，并让`prev.next`接住新头 |
| Q25 K组反转 | 把下一组前驱更新为旧`end` | 重复处理已反转节点，分组边界崩溃 | 反转前保存`start`；反转后`start`是新尾，令`prev=start` |
| Q25 K组反转 | 未冻结`endNext`或未连接新尾 | 丢失剩余链表 | 反转前保存`end.next`，结束后保证`newTail.next=endNext` |
| Q148 排序链表 | base case漏掉单节点 | 无限递归 | `head == null || head.next == null`直接返回`head` |
| Q148 排序链表 | 单节点返回`null` | 排序时丢节点 | 单节点必须返回自己 |
| Q148 排序链表 | 找到中点但不断链 | 左递归仍包含完整链表，无法缩小问题 | 保存右头后执行`slow.next=null` |
| Q234 回文链表 | 比较时把后半区入口推进到`null`，随后用它恢复 | `reverse(null)`无效果，原链表没有恢复 | 保存`reversedHead`，比较使用另一个游标 |
| Q23 K路归并 | 比较器写成`a.val - b.val` | 通用值域下可能整数溢出 | 使用`Integer.compare(a.val, b.val)` |
| Q138 随机链表复制 | 只复制`next`，没有建立random映射 | 新链表结构不等价 | HashMap映射或穿插节点编码原新关系 |
| 双向链表/LRU/LFU | 删除节点只维护一个方向 | 正反向链不一致，后续删除NPE | 同时连接`prev.next`和`next.prev` |
| 链表重组 | 尾节点`next`未清空 | 分区间串联、成环、无限遍历 | 每条独立链及最终尾节点都检查`tail.next == null` |

## 1. Q2：循环体逻辑一多，遗漏“推进”

### 错误本质

链表循环同时承担计算、创建节点、更新进位和移动指针，注意力集中在业务计算后容易漏掉遍历动作。

2026-08-31版本再次出现了同一类遗漏：公共部分只移动了结果尾指针`end`，忘记移动`l1/l2`；
剩余部分也一度遗漏`rest = rest.next`。这说明问题不在具体语法，而在于没有区分两组独立角色：

```text
输入消费指针：l1、l2、rest
输出构造指针：end
```

移动`end`只会改变结果链表的追加位置，不会消费任何输入节点。每轮循环都必须分别检查这两组指针。

### 固定检查

```text
本轮消费了谁？
消费后谁必须移动？
结果链表tail是否也移动？
```

最小反例：`[2] + [3]`。如果任一输入指针不动，循环永远处理同一节点。

## 2. Q19：位置、前驱和跳跃次数混淆

要删除第`p`个节点，真正需要定位的是第`p-1`个前驱。若从第一个节点开始，走到第`p-1`个节点只需要
移动`p-2`次。这个推导很容易产生off-by-one。

2026-08-31版本把两步推导拆开记录：

```text
第一步：倒数第n个 -> 正序第k个，k = len - n + 1。
第二步：删除第k个 -> 停在第k-1个前驱；从head出发移动k-2次。
```

最容易混淆的是三个不同概念：

| 概念 | 数值 |
| --- | --- |
| 待删除节点的正序位置 | `k` |
| 应停留的前驱位置 | `k - 1` |
| 从第1个节点出发的移动次数 | `k - 2` |

不要使用一句“跳到第k个节点要走k-1次”同时描述三者；必须先明确目标是待删除节点还是它的前驱。

更稳定的面试写法是：

```text
dummy作为第0个节点；
fast先走n步；
fast继续走到尾部时，slow停在待删除节点前驱。
```

通过结构不变量替代手算跳跃次数。

## 3. Q141/Q142：初始化必须和循环条件配套

错误组合：

```java
slow = head;
fast = head;
while (slow != fast) { ... }
```

初始时二者必然相等，循环不会执行。推荐：

```java
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow == fast) {
        // 相遇
    }
}
```

这同时把“能否继续走”和“是否相遇”放在正确时序上。

## 4. Q160：遍历完成意味着游标状态已经改变

统计长度以后：

```java
while (cur != null) {
    cur = cur.next;
}
```

退出时`cur == null`。后续不能因为变量名还叫`cur1/cur2`，就把它们当作链表头。必须重新赋值。

这是一个通用错误：**变量的业务身份不会由名字保证，必须以当前实际引用为准。**

## 5. Q24/Q25：反转后头尾身份交换

```text
反转前：prev -> start ... end -> endNext
反转后：prev -> end ... start -> endNext
```

因此：

```text
prev.next = end
下一轮prev = start
```

Q25中错误写成`prev = end`非常致命，因为下一轮前驱落在本组新头，导致已经处理过的节点再次进入分组。

建议在代码中保留角色名：

```java
ListNode oldHead = start;
ListNode newHead = reverse(start, end);
prev.next = newHead;
prev = oldHead; // oldHead现在是newTail
```

## 6. Q148：递归问题必须严格缩小

正确递归契约：

```text
sort(head)接收一条以null结束的独立链表，返回排序后的新头。
```

三个必要条件：

1. 空链和单节点直接返回。
2. 左右半区必须断开。
3. 父调用必须接住左右递归返回的新头。

漏掉任何一项都可能无限递归或丢节点。

## 7. Q234：恢复现场必须保存入口

当前代码中的高风险模式：

```java
ListNode end = reverse(slow);
while (...) {
    end = end.next;
}
reverse(end);
```

循环结束后`end`通常已经为`null`，最后一行无法恢复任何节点。正确角色拆分：

```java
ListNode reversedHead = reverse(secondStart);
ListNode right = reversedHead;
// 使用right比较
reverse(reversedHead);
```

错误原因不是反转算法，而是同一个变量同时承担“结构入口”和“遍历游标”两个不兼容职责。

## 8. Q138：复制值不等于复制结构

普通链表只需保持相邻关系；随机链表还要复制任意跨节点引用。必须建立可查询的原新节点映射：

```text
HashMap：显式映射，O(N)空间；
穿插节点：original.next即copy，利用链表结构隐式编码映射，O(1)额外空间。
```

拆链阶段同时承担两项职责：恢复原链表、构造新链表。必须分别维护，不能只顾其中一个。

## 9. 双向链表：一次删除不是一行代码

错误：

```java
node.prev.next = node.next;
```

正确：

```java
node.prev.next = node.next;
node.next.prev = node.prev;
```

缓存题中还要同步维护Map：

```text
链表删除节点 + map.remove(node.key)
```

否则节点虽然不在淘汰顺序中，仍能通过Map被访问。

## 最小反例集合

每道链表题至少验证：

```text
空链表
单节点
两个节点
操作目标是头节点
操作目标是尾节点
全部节点都被操作
最后剩余不足一组
节点值重复但节点引用不同
存在环或重组后可能意外成环
```

## 错误预防口诀

```text
一个变量只承担一个角色。
覆盖next之前先保存next。
反转以后原头就是新尾。
局部操作从前驱开始，结束后前驱跳到新尾。
递归链表必须真的断开，保证问题规模缩小。
恢复现场必须保留结构入口，不能使用已经走空的游标。
```
