## 一句话总纲

```text
链表没有下标，算法边界由节点引用、断链、前驱和后继表达；
修改结构前先保存仍需访问的指针，修改完成后明确返回新头、新尾和后继。
```

数组中的`arr[l...r]`到了链表中，通常映射为：

```text
一条从head开始、以null结束的独立子链表
```

这就是链表题最重要的结构意识。数组下标天然保存区间，链表必须通过断链或显式的
`start/end/endNext`建立边界。

## 推荐复习顺序

```text
Q206
  -> Q21
  -> Q19
  -> Q141 / Q142
  -> Q160
  -> Q234
  -> Q24
  -> Q25
  -> Q148
  -> Q23
  -> Q138
  -> Q146 / Q460
```

这个顺序不是按题号，而是按能力依赖：

1. 先掌握单段指针修改。
2. 再掌握双指针定位。
3. 然后处理局部区间的新头、新尾和重连。
4. 最后组合堆、HashMap和多条双向链表。

## 写链表代码前必须回答的问题

1. 当前指针分别表示什么：当前节点、前驱、尾节点还是下一组前驱？
2. 哪个节点的`next`即将被覆盖？覆盖前是否还需要通过它继续遍历？
3. 操作后头节点会不会变化？如果会，谁接住新头？
4. 操作后尾节点是谁？它应该连接哪个`endNext`？
5. 当前子链表边界由什么保证：`null`、`end`还是节点数量？
6. 比较的是节点值还是节点身份？相交、成环必须比较引用。
7. 结果是否要求恢复输入结构？Q234如果选择原地反转，应恢复后半链表。
8. 双向链表操作是否同时维护了`next`和`prev/last`？

## 统一复杂度认识

- 单次线性遍历通常为`O(N)`。
- 两个指针各自只向前移动，即使写成嵌套逻辑，总移动次数仍可能是`O(N)`。
- 归并两个链表是`O(M + N)`，不需要数组的`help[]`。
- K路归并总节点数为`T`、路数为`K`，时间为`O(T log K)`，堆空间为`O(K)`。
- 自顶向下链表归并排序时间为`O(N log N)`，递归栈为`O(log N)`；自底向上版本可做到
  `O(1)`额外空间。
- LRU、LFU要求平均`O(1)`，关键是已知节点引用后双向链表删除必须为`O(1)`。

## 最终记忆

```text
先保存next，再修改next。
头可能变化，用dummy。
删除或局部反转，要站在前驱上操作。
反转后原头变新尾，原尾变新头。
数组区间映射到链表，就是断开成独立子链表。
返回值必须说清楚：返回新头，还是同时返回新头和新尾。
```
