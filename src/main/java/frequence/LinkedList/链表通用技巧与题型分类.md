# 链表通用技巧与题型分类

## 1. 链表题真正难在哪里

链表题通常不是计算复杂，而是**引用语义和结构边界**容易混乱：

- `cur`移动以后，原节点可能再也找不到。
- `cur.next`被覆盖以后，原后继链可能整体丢失。
- 反转后，原来的头尾身份交换。
- 子链表没有数组下标，必须主动断链或保存边界。
- 节点值相同不代表节点相同；相交与成环比较的是引用。

因此，链表代码要优先维护“指针含义”和“区间不变量”，而不是追求少写变量。

## 2. 基础骨架：先保存后继，再修改指针

标准反转：

```java
ListNode pre = null;
ListNode cur = head;
while (cur != null) {
    ListNode next = cur.next;
    cur.next = pre;
    pre = cur;
    cur = next;
}
return pre;
```

这里的顺序不能打乱：

```text
保存原后继 -> 改当前节点next -> 推进pre -> 推进cur
```

如果先执行`cur.next = pre`，再读取`cur.next`，读到的已经不是原链表后继。

适用题目：Q206、Q234、Q24、Q25，以及所有链表重组和排序题。

## 3. Dummy节点：统一“头节点可能变化”

只要操作可能删除、插入或替换原头节点，就优先考虑dummy：

```java
ListNode dummy = new ListNode(0);
dummy.next = head;
ListNode prev = dummy;
```

它把“修改头节点”统一成普通的：

```java
prev.next = newHead;
```

适用题目：

- Q19：删除节点，目标可能是原头。
- Q21、Q2：构造结果链表。
- Q24、Q25：第一组反转会产生新头。
- Q146、Q460：双向链表使用头尾哨兵统一空桶和边界节点。

Dummy只解决入口统一问题，不会自动解决局部反转后的新尾和后继连接。

## 4. 前驱节点模型：删除、插入和局部重连

单链表无法从当前节点直接找到前驱。因此需要修改一个区间时，循环变量通常应该站在该区间前面：

```text
prev -> start ... end -> endNext
```

局部操作完成后必须明确：

```text
prev.next = newHead
newTail.next = endNext
prev = newTail
```

### K组反转的身份变化

反转前：

```text
prev -> start -> ... -> end -> endNext
```

反转后：

```text
prev -> end -> ... -> start -> endNext
```

结论：

```text
newHead = end
newTail = start
下一组prev = start
```

Q25最致命的错误就是把下一组前驱更新为`end`。`end`已经是本组新头，不是本组新尾；下一轮会从
已经反转过的组内部继续寻找边界。

### 完整分组只能由计数函数判定

末尾出现`end.next == null`具有两种可能：

```text
情况1：本组恰好完整包含k个节点，并且第k个节点正好是链表尾节点；
情况2：末尾剩余节点不足k个。
```

所以`end.next == null`不能区分分组是否完整。应让查找函数建立明确契约：

```text
找到完整k个节点 -> 返回第k个节点end；
不足k个节点     -> 返回null。
```

主流程只判断`end == null`。一旦不足k个直接退出，由于本轮尚未修改任何指针，末尾节点会自然保持
原有顺序。

## 5. 区间反转：必须冻结endNext

```java
ListNode reverse(ListNode start, ListNode end) {
    ListNode endNext = end.next;
    ListNode pre = endNext;
    ListNode cur = start;
    while (cur != endNext) {
        ListNode next = cur.next;
        cur.next = pre;
        pre = cur;
        cur = next;
    }
    return pre;
}
```

令`pre = endNext`可以在反转过程中直接完成新尾到后继的连接。若令`pre = null`，则反转结束后还要
显式执行`start.next = endNext`。

关键不是选择哪种写法，而是必须冻结`endNext`。不能在指针已经变化以后再通过`end.next`推断原后继。

错误循环：

```java
while (cur.next != end.next) {
    ...
}
```

这里同时存在两个错误：

1. `end.next`不是稳定边界。反转到`end`时，它的`next`会从原后继改为前驱节点。
2. 标准反转循环判断的是“当前节点是否到达终止位置”，即`cur != endNext`，不是判断
   `cur.next`；后者容易漏处理边界节点。

这是一条通用原则：

```text
如果循环边界来自即将被修改的数据结构，进入修改过程前必须把边界值冻结到独立变量。
```

### reverse返回值的接口一致性

完整反转`[start,end]`以后，返回的新头必然是原`end`。因此调用方有两种一致写法：

```text
1. reverse返回newHead，调用方使用返回值连接pre.next；
2. 调用方已经保存end并直接使用它，reverse改为void。
```

不要声明返回值却长期忽略它。虽然不影响正确性，但会让读者误以为返回结果还有其他语义。

## 6. 快慢指针：速度差制造结构信息

### 找中点

典型循环：

```java
while (fast.next != null && fast.next.next != null) {
    slow = slow.next;
    fast = fast.next.next;
}
```

最终落点由`slow/fast`初始位置决定。不要脱离初始化死背循环。

| 目标 | 常见初始位置 |
| --- | --- |
| 中点或上中点 | `slow=head, fast=head`，结合具体循环验证 |
| 中点前驱，用于断链 | 让`slow`最终停在左半区尾节点 |
| 下中点 | 调整`fast`起始位置或循环边界 |

最稳定的方法是使用长度2、3、4、5的链表手工验证落点。

### 判断环

推荐写法避免“slow和fast都从head开始，`while (slow != fast)`一次不执行”的初始化陷阱：

```java
ListNode slow = head;
ListNode fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow == fast) {
        return true;
    }
}
return false;
```

先移动，再判断相遇，语义更稳定。

### 找入环节点

第一次相遇后：

```text
一个指针回到head；
两个指针都改为每次走一步；
再次相遇的位置就是入环节点。
```

适用题目：Q141、Q142。

### 固定距离窗口

Q19可让`fast`先走`n`步，然后`slow/fast`同步移动。配合dummy，`slow`最终停在待删除节点的前驱。

## 7. 两条链表消除长度差

Q160有两种稳定模型。

### 长度对齐

1. 分别计算长度。
2. 长链表先走长度差。
3. 两指针同步移动，第一次引用相同的位置就是交点。

计算长度以后，原遍历指针都已经为`null`，必须重新从`headA/headB`赋值。

### 指针换道

```java
while (a != b) {
    a = a == null ? headB : a.next;
    b = b == null ? headA : b.next;
}
return a;
```

两者都走过`A长度 + B长度`，长度差被自动抵消。无交点时最终同时为`null`。

## 8. 归并模型：消费当前最小节点

### 两路归并

循环不变量：

```text
dummy.next到tail已经有序；
list1、list2分别指向各自未消费部分的最小节点。
```

每轮需要推进两个角色：

1. 被消费的输入链表指针。
2. 结果链表的`tail`。

漏掉任意一个都会导致死循环或覆盖结果。

### K路归并

堆中只保存每条链表当前未消费的第一个节点：

```java
PriorityQueue<ListNode> heap = new PriorityQueue<>(
        (a, b) -> Integer.compare(a.val, b.val)
);
```

初始化堆时必须过滤空链表头：

```java
for (ListNode head : lists) {
    if (head != null) {
        heap.offer(head);
    }
}
```

`lists[i] == null`表示第`i`条链表为空，这是合法输入；但Java的`PriorityQueue`不允许保存
`null`，直接`offer(null)`会触发`NullPointerException`。后续弹出节点以后，也只加入非空的
`cur.next`。由此维持堆不变量：

```text
堆中只存在有效节点，并且每条尚未耗尽的链表至多贡献一个当前候选节点。
```

弹出一个节点后，只把它的`next`加入堆。总节点数为`T`、链表数量为`K`：

```text
时间 O(T log K)
堆空间 O(K)
```

Q23与二维有序数组K路归并完全同构，区别只是下一候选分别是`node.next`和`column + 1`。

### 链表归并排序

```text
快慢指针找中点 -> slow.next = null断链 -> 递归排序两半 -> 两路归并
```

数组使用`l、r`限制递归区间；链表通过断链让每个递归参数成为以`null`结尾的独立链表。

Q148必须同时记住两个接口契约：

```text
process(head)：对传入的整条独立链表排序，返回排序后的新头。
merge(head1, head2)：合并两条有序链表，返回归并结果的新头。
```

`process`和`merge`都会改变节点次序，因此都可能产生新头。尤其是对子链表递归排序时，不能只执行：

```java
process(head1);
process(head2);
```

必须写成：

```java
head1 = process(head1);
head2 = process(head2);
return merge(head1, head2);
```

这与数组归并排序的关键区别是：数组的区间起点下标不会因为排序改变；链表排序后，原头节点可能
移动到链表中间或尾部，所以父调用必须通过返回值取得新的结构入口。

空间复杂度方面，链表归并直接重连节点，不需要数组版本的`help[]`，递归写法的额外空间主要是
高度为`O(log N)`的递归栈。

## 9. 深拷贝：结构关系也必须复制

Q138有两种模型。

### HashMap映射

```text
原节点 -> 新节点
```

先创建全部新节点，再根据映射连接`next/random`。时间`O(N)`，空间`O(N)`，最容易解释。

### 穿插节点

```text
原1 -> 新1 -> 原2 -> 新2 -> ...
```

此时原节点`x`的复制节点是`x.next`，所以：

```java
copy.random = original.random == null
        ? null
        : original.random.next;
```

这里的空判断是算法正确性的一部分，不是防御式冗余。题目明确允许`random == null`，直接读取
`original.random.next`会触发`NullPointerException`。通用原则是：

```text
如果下一步需要通过一个可空引用继续访问字段，必须先处理null分支。
```

最后必须同时恢复原链表并拆出新链表。这是用临时结构编码映射关系，从而把额外空间降为`O(1)`。

拆链时可以维护两组`dummy + tail`分别重建原链和复制链。结束后显式保证：

```text
originalTail.next == null
copyTail.next == null
```

即使复制尾节点原本已经指向`null`，显式写出两条终止条件也能让拆链契约更清楚。

## 10. 回文链表：组合模型与恢复现场

Q234由四步组成：

```text
找中点 -> 反转后半区 -> 两端比较 -> 再次反转恢复
```

如果遍历比较时把`secondHead`一路推进到`null`，最后执行`reverse(secondHead)`只会反转空链表。
必须额外保存后半区反转后的头：

```java
ListNode reversedHead = reverse(secondStart);
ListNode right = reversedHead;
// 比较时移动right
reverse(reversedHead); // 使用保存的入口恢复
```

## 11. 双向链表：一个连接动作包含两个赋值

删除节点：

```java
node.prev.next = node.next;
node.next.prev = node.prev;
```

插入头部：

```java
Node first = head.next;
head.next = node;
node.prev = head;
node.next = first;
first.prev = node;
```

LRU、LFU最常见错误不是策略，而是只更新一个方向，导致正向和反向链不一致。

## 12. 统一复查清单

```text
[ ] 覆盖next前保存原后继了吗？
[ ] 当前操作会换头吗？谁接住新头？
[ ] 原头在反转后是不是新尾？
[ ] 新尾连接endNext了吗？
[ ] 下一轮prev更新成新尾了吗？
[ ] 子链表需要断开为null结尾吗？
[ ] while中的所有遍历指针都推进了吗？
[ ] 比较的是引用还是值？
[ ] 双向链表是否同时修改next和prev？
[ ] 原地修改后是否需要恢复现场？
```
