## Q1 TwoSum 【Hot 100】

### 核心思想与题目要求

这道题虽然很简单。 但是跟 【子数组累加和三连-第二连】是一样的框架。
但是它：
 1. HashMap
 2. 在for循环中，每一个 后面元素 【检查】 map是否存有'前面满足target-arr[i]的元素'

### 算法流程与正确性依据

1. 根据题意确定输入中可利用的单调性、值域、结构关系或可复用子问题。
2. 使用本专题模型组织状态：先确定查询关系，再决定先查询后登记还是先登记后查询；涉及连续性时只从序列起点扩展。
3. 每次更新后维持上述定义；只有在不变量仍成立时才移动指针、覆盖数据或进入下一状态。
4. 最终从定义直接读取答案，而不是根据样例猜测返回位置。

正确性的关键是：每一步只排除已经证明不可能成为答案的选择，或者完整枚举状态定义允许的所有前驱，因此不会漏解。

### 标准 Java 代码

```java
package frequence;

import java.util.*;

/**
 * 这道题虽然很简单。 但是跟 【子数组累加和三连-第二连】是一样的框架。
 * 但是它：
 *  1. HashMap
 *  2. 在for循环中，每一个 后面元素 【检查】 map是否存有'前面满足target-arr[i]的元素'
 */
public class Q1_TwoSum {
    // 题目保证唯一解
    public static int[] twoSum(int[] arr, int target) {
        HashMap<Integer, Integer> map = new HashMap<>();
        for (int i = 0; i < arr.length; i++) {
            if (map.containsKey(target - arr[i])) {
                return new int[]{map.get(target - arr[i]), i};
            } else {
                map.put(arr[i], i);
            }
        }
        return new int[]{-1, -1};
    }
}
```

### 易错点

- 不要在没有写清状态、区间或返回值定义前直接套模板。
- 边界条件必须与主循环使用同一套下标语义。

### 复杂度与面试记忆

复杂度需要按照代码中每个指针、节点、状态或边的实际访问次数推导；不能仅根据算法名称下结论。

> 记忆模板：先确定查询关系，再决定先查询后登记还是先登记后查询；涉及连续性时只从序列起点扩展。

## Q49 GroupAnagrams 【Hot 100】

### 核心思想与题目要求

字母异位词分组：将具有相同字符频次的字符串放入同一组。
例如输入：
{@code
["eat", "tea", "tan", "ate", "nat", "bat"]
}
当前实现先统计每个字符串中 26 个小写字母的出现次数，再按照字母顺序
重新生成字符串作为 HashMap 的 key：
{@code
"eat"、"tea"、"ate" -> a:1, e:1, t:1 -> key = "aet"
"tan"、"nat"        -> a:1, n:1, t:1 -> key = "ant"
"bat"               -> a:1, b:1, t:1 -> key = "abt"
}
因此，字母组成相同但排列顺序不同的字符串会得到相同 key，并进入同一个 List。
最终得到的分组等价于：
{@code
[["eat", "tea", "ate"], ["tan", "nat"], ["bat"]]
}
HashMap 不保证遍历顺序，因此各分组在结果中的先后顺序不固定。
另一种写法是不重新生成 "aet"，而是直接把 26 个频次编码成 key。
编码时必须添加分隔符，例如 `#1#0#0...`。如果直接拼接数字，
`[1, 11]` 和 `[11, 1]` 都会得到 `"111"`，产生错误分组。
频次编码可以减少长字符串的 key 长度，但不会改变算法复杂度。
复杂度：设所有字符串的字符总数为 L，单个字符串的最大长度为 M。
当前计数方案的时间复杂度为 O(L)，每个字符只需统计和生成一次；
如果对每个字符串使用 Arrays.sort，则时间复杂度为 O(L log M)。
因为任何正确算法都必须读取每个字符，所以 O(L) 已经达到渐进意义上的最优复杂度。
当前实现使用长度为 26 的计数数组，因此仅适用于小写英文字母 `'a' 到 'z'`。

### 算法流程与正确性依据

1. 根据题意确定输入中可利用的单调性、值域、结构关系或可复用子问题。
2. 使用本专题模型组织状态：先确定查询关系，再决定先查询后登记还是先登记后查询；涉及连续性时只从序列起点扩展。
3. 每次更新后维持上述定义；只有在不变量仍成立时才移动指针、覆盖数据或进入下一状态。
4. 最终从定义直接读取答案，而不是根据样例猜测返回位置。

正确性的关键是：每一步只排除已经证明不可能成为答案的选择，或者完整枚举状态定义允许的所有前驱，因此不会漏解。

 */
public class Q49_GroupAnagrams {

    public List<List<String>> groupAnagrams(String[] strs) {
        HashMap<String, List<String>> map = new HashMap<>();
        for (String s : strs) {
            String sorted = getSortedString(s);
            if (!map.containsKey(sorted)) {
                map.put(sorted, new ArrayList<>());
            }
            map.get(sorted).add(s);
        }
        // TODO：【优化】可以合并成下面依据， map.values() 返回的是 Collection<V>
        //   List<List<String>> ans = new ArrayList<>(map.values());
        List<List<String>> ans = new ArrayList<>();
        for (List<String> list : map.values()) {
            ans.add(list);
        }
        return ans;
    }

    public static String getSortedString(String s) {
        char[] chs = s.toCharArray();
        int[] count = new int[26];
        for (int i = 0; i < chs.length; i++) {
            count[chs[i] - 'a']++;
        }
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < count.length; i++) {
            char c = (char) ('a' + i);
            while (count[i]-- > 0) {
                sb.append(c);
            }
        }
        return sb.toString();
    }

}

### HashMap key 的判定原理与数组反例

#### 1. 反例：排序后的 char[] 不能直接作为内容型 key

下面的思路前半部分正确：异位词经过字符排序后，会得到相同的字符排列。但最后把 `char[]` 直接作为
HashMap key 是错误的：

```java
class Solution {
    public List<List<String>> groupAnagrams(String[] strs) {
        HashMap<char[], List<String>> map = new HashMap<>();

        for (String str : strs) {
            char[] chars = str.toCharArray();
            Arrays.sort(chars);

            // TODO: 【错误】char[]没有按字符内容重写equals和hashCode。
            // 每次toCharArray()都会创建新的数组对象，即使排序后内容相同，也会成为不同key。
            if (!map.containsKey(chars)) {
                map.put(chars, new ArrayList<>());
            }
            map.get(chars).add(str);
        }

        return new ArrayList<>(map.values());
    }
}
```

例如：

```text
"eat" -> 一个新的['a','e','t']数组
"tea" -> 另一个新的['a','e','t']数组
```

`Arrays.sort(chars)`只改变数组内容，不会把两个数组变成同一个对象。两个数组内容相等，但默认
`equals()`仍然返回 `false`，所以它们无法进入同一个分组。

#### 2. HashMap 如何判断两个 key 相同

HashMap 不固定“按地址比较”，也不固定“按内容比较”。它依赖 key 类型自身实现的：

```java
hashCode()
equals()
```

判断过程可以近似理解为：

```text
1. 调用key.hashCode()并经过扰动，定位哈希桶；
2. 哈希值不相同，直接认为不是同一个key；
3. 哈希值相同，再调用equals()确认逻辑内容是否相等；
4. equals()为true，才把它们视为同一个key。
```

只有 hashCode 相同并不足以认定 key 相同，因为不同对象可能发生哈希冲突；必须继续使用 `equals()`
确认。反过来，key 类型必须遵守 Java 契约：

```text
如果a.equals(b)为true，那么a.hashCode()必须等于b.hashCode()。
```

否则两个逻辑上相等的 key 可能被放入不同哈希桶，HashMap 将无法正常查找。

#### 3. 数组可以作为 key，但默认只具有对象身份语义

“数组不支持作为 HashMap key”并不严谨。Java 在语法上允许数组作为 key：

```java
HashMap<int[], String> map = new HashMap<>();
int[] key = {1, 2, 3};
map.put(key, "value");

map.get(key);               // 可以找到，因为使用的是同一个数组对象
map.get(new int[]{1, 2, 3}); // 找不到，因为这是另一个数组对象
```

真正的问题是：Java 数组没有重写 `Object.equals()` 和 `Object.hashCode()`，所以默认按照**对象身份**
而不是数组元素内容判等。专业表述应当是：

```text
数组可以作为HashMap key，
但不能直接作为“按数组内容合并”的key。
```

不要把对象身份简单等同于物理内存地址。Java 规范描述的是引用是否指向同一对象，并不承诺向应用程序
暴露真实内存地址。

如果业务上必须使用数组内容作为 key，可以：

1. 包装成自定义不可变类，并用 `Arrays.equals()`、`Arrays.hashCode()`重写判等逻辑。
2. 对 `char[]` 使用 `new String(chars)`转换成不可变 String。
3. 转换成真正的元素 List，但需要考虑装箱和可变性成本。

#### 4. String 为什么特别适合作为 key

String 重写了 `equals()` 和 `hashCode()`：

```text
equals()：逐字符判断内容是否相同；
hashCode()：根据字符序列计算哈希值。
```

因此：

```java
String first = new String(new char[]{'a', 'e', 't'});
String second = new String(new char[]{'a', 'e', 't'});

first == second;                       // false，不是同一个对象
first.equals(second);                  // true，字符内容相同
first.hashCode() == second.hashCode(); // true
```

String 还具有不可变性。创建以后字符内容不会变化，因此已经放入 HashMap 的 key 不会因为后续修改而
改变 hashCode。Q49 的正确写法是：

```java
HashMap<String, List<String>> map = new HashMap<>();

for (String str : strs) {
    char[] chars = str.toCharArray();
    Arrays.sort(chars);
    String key = new String(chars);

    if (!map.containsKey(key)) {
        map.put(key, new ArrayList<>());
    }
    map.get(key).add(str);
}
```

这里排序后的 String 是异位词的标准形态：

```text
"eat"、"tea"、"ate" -> "aet"
```

#### 5. List 为什么可以按元素内容作为 key

`ArrayList`等标准 List 实现按照“元素内容 + 元素顺序”实现 `equals()` 和 `hashCode()`：

```java
List<Integer> first = Arrays.asList(1, 2, 3);
List<Integer> second = Arrays.asList(1, 2, 3);
List<Integer> third = Arrays.asList(3, 2, 1);

first.equals(second); // true：相同顺序、相同位置的元素相等
first.equals(third);  // false：元素顺序不同
```

所以内容不变的 `List<Integer>` 可以作为内容型 key：

```java
HashMap<List<Integer>, String> map = new HashMap<>();
map.put(first, "value");
map.get(second); // "value"
```

但 List 的比较最终还会调用每个元素自己的 `equals()` 和 `hashCode()`。下面的写法不能把基本类型数组
变成内容型 List key：

```java
Arrays.asList(new int[]{1, 2, 3})
```

它的真实类型是一个只包含单个 `int[]` 元素的 `List<int[]>`。比较 List 元素时，最终仍然调用
`int[].equals()`，所以两个内容相同但对象不同的数组仍然不相等：

```java
Arrays.asList(new int[]{1, 2, 3})
        .equals(Arrays.asList(new int[]{1, 2, 3})); // false
```

而下面使用的是 `Integer` 元素，能够按数值比较：

```java
Arrays.asList(1, 2, 3)
        .equals(Arrays.asList(1, 2, 3)); // true
```

#### 6. 可变对象作为 key 的致命风险

虽然 `ArrayList`支持内容判等，但它是可变对象。影响 `equals/hashCode` 的内容在进入 HashMap 后不能
继续修改：

```java
List<Integer> key = new ArrayList<>(Arrays.asList(1, 2, 3));
HashMap<List<Integer>, String> map = new HashMap<>();
map.put(key, "value");

key.add(4);       // key的内容和hashCode已经变化
map.get(key);     // 可能找不到原来的Entry
```

Entry 仍然存放在插入时旧 hashCode 对应的哈希桶中，但查询会按照修改后的新 hashCode 定位另一个桶，
导致 key 逻辑上“丢失”。因此 HashMap key 的推荐标准是：

```text
1. equals/hashCode语义符合业务唯一性；
2. key放入Map以后保持不可变；
3. equals为true时必须拥有相同hashCode。
```

#### 7. 常见类型作为 key 的对照

| 类型 | 默认判等语义 | 内容型 key 是否合适 | 注意事项 |
|---|---|---|---|
| `char[]`、`int[]` | 对象身份 | 不适合直接使用 | 同内容的新数组仍是不同 key |
| `String` | 字符内容 | 非常适合 | 不可变，并正确重写 equals/hashCode |
| `Integer`等包装类型 | 包装值 | 适合 | 不可变 |
| `ArrayList` | 元素内容和顺序 | 可以谨慎使用 | 放入 Map 后不能修改内容 |
| 未重写的自定义类 | 对象身份 | 不适合内容型业务 key | 必须正确重写 equals/hashCode |
| 正确实现的不可变类 | 指定业务字段 | 适合 | 构造时应防御性复制可变字段 |

最终记忆：

```text
HashMap只负责调用key的hashCode和equals；
按身份还是按内容比较，由key类型决定。

数组默认按对象身份；
String按字符内容且不可变；
List按元素内容和顺序，但必须防止作为key后继续修改。
```

### HashMap 的 values、keySet 与 entrySet 集合视图

Q49 最终只需要所有分组，不需要作为分组标识的 key，因此可以直接读取：

```java
map.values()
```

`HashMap.values()`返回 Map 中所有 value 构成的**集合视图**，其声明类型是：

```java
Collection<V>
```

方法签名可以理解为：

```java
public Collection<V> values()
```

例如：

```java
HashMap<String, List<String>> map = new HashMap<>();
```

那么：

```java
map.values()
```

的编译类型就是：

```java
Collection<List<String>>
```

Q49 中的 Map 内容可能是：

```text
"aet" -> ["eat", "tea", "ate"]
"ant" -> ["tan", "nat"]
"abt" -> ["bat"]
```

`map.values()`得到的内容类似：

```text
[
    ["eat", "tea", "ate"],
    ["tan", "nat"],
    ["bat"]
]
```

但题目要求返回的是：

```java
List<List<String>>
```

`Collection<List<String>>`不能直接作为`List<List<String>>`返回，因此使用 `ArrayList` 接受
`Collection` 的构造方法：

```java
return new ArrayList<>(map.values());
```

对应的构造方法是：

```java
public ArrayList(Collection<? extends E> collection)
```

这里会把视图中的全部 value 复制到一个新的 `ArrayList` 中。新列表的增删不再改变原 Map，但这是
**浅复制**：外层 `ArrayList` 是新对象，里面每个 `List<String>` 仍然是 Map 中原来的 value 对象。

#### values() 返回的是动态视图，不是独立副本

```java
Collection<List<String>> values = map.values();
```

`values`由原 Map 支撑。后续修改 Map：

```java
map.put("abc", new ArrayList<>());
```

`values`会同步反映新增的 value。

通过视图删除 value 也会删除对应的 Map Entry：

```java
values.remove(someList);
```

如果多个 key 映射到相等的 value，单次 `remove` 只保证删除其中一个匹配的映射。

但是不能通过 `values()` 添加 value：

```java
values.add(new ArrayList<>()); // UnsupportedOperationException
```

原因是只有 value，没有与它对应的 key，Map 无法建立新的 key-value 映射。

#### Map 的三种集合视图

| 方法 | 返回类型 | 内容 |
|---|---|---|
| `map.keySet()` | `Set<K>` | 所有 key |
| `map.values()` | `Collection<V>` | 所有 value；value 可以重复，所以不是 Set |
| `map.entrySet()` | `Set<Map.Entry<K,V>>` | 所有 key-value Entry |

只遍历 value：

```java
for (List<String> group : map.values()) {
    System.out.println(group);
}
```

同时遍历 key 和 value：

```java
for (Map.Entry<String, List<String>> entry : map.entrySet()) {
    String key = entry.getKey();
    List<String> value = entry.getValue();
}
```

最终记忆：

```text
keySet()   -> Set<K>
values()   -> Collection<V>
entrySet() -> Set<Map.Entry<K,V>>
```
