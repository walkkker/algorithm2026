## 特点
1. 如何发现使用MergeSort解题？
    - 判断根源：原题的暴力解法都是，以每个元素为开头，与后面所有元素【比较】（大于右侧两倍/逆序/区间和是否落在[lower,upper]区间）。此时O(N^2)
    - 优化解法：如果暴力解法如上述：【1. 每两个元素依次比较 最终聚合得到答案。】 那么就可以使用 归并改写
2. 附带的四道题发现可以用一套模板解决：
    1. 左侧为滑动区间，对应循环体内部；
        - 单指针滑动其实也是区间，只不过是另一侧是固定位置
        - 例如rangeSum,那就是 左右两侧滑动
    2. 右侧for(int R = m + 1; R <= r; R++)，即依次遍历R元素
    3. 针对1的详细解释，那么具体怎么滑动呢？
        - 我们说过，本质是【每个元素与右侧所有元素】【比较】；既然是比较，那么就是大于 或者 小于
        - 1. 如果目标是【左侧>右侧】, 目标是 【寻找第一个合法[p1,m] 】
          - 那么 while(p1 <= m && arr[p1] <= arr[R]) {p1++}
          - 此时退出while时，p1对应第一个【大于右侧】，当前R对应的 有效左侧区间为[p1, m]
        - 2. 如果目标是【左侧<右侧】， 目标是 【寻找第一个违规[l, p1) 】
          - 那么 while(p1 <= m && arr[p1] < arr[R]) {p1++}
          - 此时退出，p1对应第一个【>=arr[R]】的元素(即非法元素)。那么此时有效区间为[l, p1) 即【左闭右开】
          - 【特别注意】因为此时有效区间为[l, p1)。 求区间长度或者标记终点时，不要p1-- =》因为可能p1==l，你再--就越界了。
          - 所以，上述情况，就构建 左闭右开区间就好。  这样区间计算就是用 p1 - l 就可以 （if p1==l, then len=0 => 说明正确）
    4. 综3所述，你会发现，不管比较是比大还是比小。 都可以一个模板，滑动窗口在左区间上滑动。 通过while 得到 有效区间。 【寻找第一个合法[p1,m] || 寻找第一个违规[l,p1)】

## 重点
1. 涉及到数组中每个元素，左/右边比他小/大 的xxx题，考虑归并改写。
2. 递归： 左孩子信息 + 右孩子信息 + 我自己merge信息 = 我当前负责范围的 答案
3. 归并排序本身是通过 左区间 右区间排好序后 进行头指针比较，避免了所有数字的两两比较，实现的计算量缩减。(暴力N^2 -> N*logN)
   - 但是，所有的基于比较的排序方法都可以理解为对每个元素进行了比较。但是通过算法设计，规避了一部分不必要的比较，减少了计算量
   - 【超重点】对于归并排序而言，它在减少计算量的同时，允许你计算每一个元素 大于或小于它的 左右侧元素数量。
     - 其实快排-荷兰国旗也能做个数统计，但是归并适用面积更大，同时覆盖 大于右侧两倍（额外双指针） 和 区间和这种（额外双指针） 超出简单积累个数的问题。
     - 后者主要是依赖 mergeSort带来的 有序性
     - 本质就是 指针滑动，只不过前两题可以跟 排序的逻辑合并到一起。本质都是在merge()函数里面做一个 O(N)的额外操作
